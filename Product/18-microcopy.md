# 18 · 微文案：界面上的每个字都是设计

## 1. 什么是微文案（Microcopy）

> 按钮文字、提示语、错误提示、空状态文案、确认弹窗……**用户实际读的那些字**。

微文案是成本最低、ROI 最高的体验优化手段——改几个字不需要开发排期（大部分改文案只改配置）。

## 2. 三条原则

```
① 清晰 > 聪明：用户来办事，不是来猜谜
② 简短 > 完整：能 5 个字说清不用 15 个字
③ 具体 > 抽象：说清会发生什么，而不是「确定吗」
```

## 3. 按钮文案

| ❌ | ✅ | 原因 |
|---|---|---|
| 确定 / 取消 | 删除文件 / 保留 | 说清动作后果 |
| 提交 | 发布文章 | 具体 |
| 点击这里 | 查看订单详情 | 具体且可读（对读屏软件友好） |
| OK | 知道了 / 重试 | 明确 |
| 是 / 否 | 退出编辑 / 继续编辑 | 避免误读 |

**规则**：按钮用「动词 + 名词」，不用「确定/取消」这种通用词（除非动作本身很明确）。

## 4. 错误提示三段式

```
发生了什么 + 为什么 + 怎么办

❌ 「操作失败」
❌ 「错误：500」
✅ 「图片上传失败：文件超过 10MB。
     已为你压缩到 8MB，点击重试即可。」
```

补充要点：
- **不要责怪用户**（「你输入错了」→「这个格式看起来不太对，试试 13800138000」）
- **不要暴露技术细节**（「NullPointerException」→ 内部记录，用户看人话）
- **错误码保留给排查用**（可折叠显示，用户能复制给客服）
- **提供出路**：重试、返回、联系客服

## 5. 空状态文案

```
结构：为什么是空的 + 能做什么 + 一个按钮

❌ 「暂无数据」
✅ 「还没有创建过商品
     导入现有商品，或点下面按钮新建第一个
     [新建商品]  [批量导入]」
```

| 场景 | 文案要点 |
|---|---|
| 首次使用 | 引导 + 教学（给示例） |
| 筛选无结果 | 说明筛选条件 + 「清空筛选」 |
| 已完成 | 正向确认（「全部处理完了 👍」） |
| 无权限 | 说明原因 + 申请入口 |
| 出错 | 重试 + 兜底 |

## 6. 语气与人格（Tone of Voice）

先定义产品的「人格」，再写文案。常见的四维定位：

```
幽默 ——○——○——○——● 严肃
正式 ——○——○——●——○ 随意
谦逊 ——○——●——○——○ 权威
热情 ——○——●——○——○ 冷静
```

| 产品类型 | 语气 |
|---|---|
| 工具类 B 端 | 简洁、专业、少废话 |
| C 端娱乐 | 活泼、有人情味 |
| 金融/医疗 | 严谨、克制、不承诺 |
| 开发者工具 | 精确、技术化、可直给错误码 |

**一致性的做法**：写一份「文案指南」，包含人称（用「你」还是「您」）、标点（用不用感叹号）、术语表（「项目」还是「空间」）、禁用词。

## 7. 加载与等待文案

| 场景 | 文案 |
|---|---|
| 短等待 | 「处理中…」 |
| 长等待 | 「正在分析 32 份文档，大约需要 20 秒」 |
| 可取消 | 「处理中… [停止]」 |
| 后台任务 | 「我们会在完成后通知你，可以先去做别的」 |
| 进度可见 | 「已完成 3/10」 |

★ AI 场景：展示**中间过程**比单纯「加载中」体验好得多（「正在检索知识库…」→「正在生成…」）。

## 8. ★ AI 产品的文案特殊要求

| 要求 | 说明 |
|---|---|
| **诚实交代是 AI** | 明确「由 AI 生成」，不要伪装成人 |
| **不夸大能力** | 不用「100% 准确」「专业律师建议」 |
| **不确定性表达** | 「AI 对此不太确定，建议人工核对」 |
| **失败不甩锅** | 「没生成成功，可能是内容触发了安全策略」（要说明，别只说失败） |
| **可控性提示** | 「你可以直接修改下面的内容」 |
| **拒绝回答要说清** | 「这个问题我无法回答」+ 替代建议，不要沉默 |
| **免责提示的位置** | 在结果附近，不是在页脚小字 |
| **反馈征集** | 「这条结果有用吗？👍👎」——这是数据飞轮入口 |

### AI 文案对照

| ❌ | ✅ |
|---|---|
| 「AI 智能生成，精准无误」 | 「AI 生成，请核对关键信息」 |
| 「回答：……」（像人） | 「AI 的回答（可能有误）：……」 |
| 「无法回答」 | 「这个问题超出了我的能力范围，你可以试试换个说法，或联系人工客服」 |
| 「生成完成」 | 「已生成 3 条，可点击任一条继续编辑」 |

## 9. 文案测试方法

| 方法 | 做法 |
|---|---|
| A/B 测试 | 改按钮文案测点击率 |
| 五秒测试 | 给用户看 5 秒，问他这个页面能干什么 |
| 朗读测试 | 念出来，拗口的要改 |
| 术语一致性检查 | 全站搜索同义词，统一 |
| 翻译回译 | 中英互译看是否变形（i18n 场景） |

## 10. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 全站「确定/取消」 | 用户不敢点 | 改成具体动作 |
| 错误提示甩技术术语 | 用户懵 | 三段式 + 人话 |
| 感叹号泛滥 | 显得廉价焦虑 | 一篇文案最多 1 个 |
| 术语不统一 | 「订单/单据/交易」混用 | 建立术语表 |
| 空状态只有「暂无数据」 | 浪费引导机会 | 加操作引导 |
| 文案与语气不一致 | 有的地方「您」有的地方「你」 | 写文案指南 |
| AI 过度承诺 | 用户失望与投诉 | 诚实表达不确定性 |
| 长文案不分段 | 没人读 | 换行、列表、加粗关键信息 |

## 11. Checklist

- [ ] 按钮文案是「动词+名词」，不是「确定」
- [ ] 错误提示含「发生了什么 + 怎么办」
- [ ] 空状态有引导与操作按钮
- [ ] 全站术语与语气一致（有术语表）
- [ ] AI 输出有「AI 生成」标识与不确定性提示
- [ ] 每条 AI 结果有反馈入口
