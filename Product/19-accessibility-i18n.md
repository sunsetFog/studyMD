# 19 · 无障碍与国际化

## 1. 无障碍（a11y）：为什么值得做

```
① 法律合规：多国（含中国《无障碍环境建设法》）对公共服务有要求
② 人群规模：全球约 15% 人口有某种形式的障碍
③ 附带收益：无障碍好的产品，SEO、键盘操作、语音控制都会更好
④ 所有人都受益：字幕在嘈杂环境有用，高对比度在强光下有用
```

## 2. WCAG 四大原则（POUR）

| 原则 | 含义 | 要点 |
|---|---|---|
| **P**erceivable 可感知 | 信息能被感知 | 文本替代、字幕、对比度 |
| **O**perable 可操作 | 界面能被操作 | 键盘可达、足够时间、不引发不适 |
| **U**nderstandable 可理解 | 信息与操作可理解 | 可读、可预测、输入辅助 |
| **R**obust 健壮性 | 能被辅助技术解析 | 语义化标签、兼容性 |

## 3. 实操清单（前端直接可做）

### 语义化与 ARIA

```html
<!-- ❌ 用 div 做按钮 -->
<div onclick="submit()">提交</div>

<!-- ✅ -->
<button type="button" onclick="submit()">提交</button>

<!-- 图标按钮必须有可访问名称 -->
<button aria-label="关闭弹窗"><svg .../></button>

<!-- 表单必须有关联 label -->
<label for="email">邮箱</label>
<input id="email" type="email" aria-describedby="email-tip">
<span id="email-tip">我们不会公开你的邮箱</span>

<!-- 动态内容用 live region 播报 -->
<div aria-live="polite">保存成功</div>

<!-- 弹窗焦点管理 -->
<div role="dialog" aria-modal="true" aria-labelledby="dlg-title">
```

### 键盘可达

| 要求 | 说明 |
|---|---|
| Tab 可遍历所有交互元素 | 顺序符合视觉顺序 |
| 焦点可见 | 不要 `outline: none` 除非有替代样式 |
| 弹窗焦点陷阱 | 打开时焦点进入弹窗，Esc 关闭，关闭后焦点回原位 |
| 跳过导航 | 提供「跳到主内容」链接 |
| 自定义控件 | 需实现方向键/Enter/Space 行为 |

### 视觉

| 要求 | 标准 |
|---|---|
| 文本对比度 | 正文 ≥ 4.5:1，大字(≥18.66px粗体或24px) ≥ 3:1 |
| 不只用颜色传达信息 | 红色错误要配图标或文字 |
| 支持 200% 缩放 | 不丢失内容与功能 |
| 尊重 prefers-reduced-motion | 减少动效 |
| 触控目标 | ≥ 24×24 (WCAG 2.2)，推荐 44×44 |

### 内容

- 图片有 `alt`（装饰图用 `alt=""`）
- 视频有字幕；音频有文字稿
- 链接文本有意义（不用「点击这里」）
- 错误提示指出具体字段

## 4. 测试方法

```
自动化：axe DevTools、Lighthouse Accessibility（能检出约 30-40%）
手动：
  ① 只用键盘走完主流程
  ② 用读屏软件（VoiceOver/NVDA）听一遍
  ③ 缩放到 200% 检查布局
  ④ 灰度模式检查是否只靠颜色区分
  ⑤ 检查对比度
```

## 5. 国际化（i18n）与本地化（l10n）

| 概念 | 说明 |
|---|---|
| i18n | 产品架构上支持多语言/多地区（工程能力） |
| l10n | 针对具体地区的翻译与文化适配（内容工作） |

### i18n 工程要点

```
① 文案外置：所有 UI 文案走 key，不硬编码
② 不要拼接句子：「你好，{name}」在不同语言语序不同 → 用完整句式模板
③ 复数处理：中文无复数，英/俄有；用 ICU MessageFormat
④ 日期/数字/货币：用 Intl API 按 locale 格式化
⑤ 时区：存储用 UTC，展示按用户时区
⑥ 字体与排版：阿拉伯语 RTL，德语单词长（布局要弹性）
⑦ 编码统一 UTF-8
⑧ 排序规则：不同语言排序不同（中文拼音/笔画）
```

```js
// 复数示例（ICU）
{count, plural, =0 {无消息} one {# 条消息} other {# 条消息}}

// 日期与货币
new Intl.DateTimeFormat('zh-CN', {dateStyle:'long'}).format(d)
new Intl.NumberFormat('ja-JP', {style:'currency', currency:'JPY'}).format(n)
```

### l10n 内容要点

- 翻译要有**上下文**（同一个词在不同位置译法不同）
- 截图/图标中的文字也要本地化
- 文化差异：颜色含义、手势、示例内容（如人名、货币、节日）
- 法律差异：隐私条款、数据存储地要求
- 长度膨胀：英译德通常长 30%，布局要留弹性

## 6. ★ AI 产品的特殊点

| 点 | 说明 |
|---|---|
| **多语言能力** | 大模型天然支持多语言，但要验证小语种质量（往往明显更差） |
| **输出语言控制** | 在 prompt 中明确指定输出语言，防止模型跟随输入语言漂移 |
| **读屏 + 流式输出** | 流式输出会让读屏软件反复播报，需控制播报策略（如完成后播报一次） |
| **AI 结果的 alt** | AI 生成的图片要有描述性 alt |
| **术语一致性** | 多语言下 AI 术语翻译要统一（建立术语表并注入 prompt） |
| **文化安全** | 不同地区的合规与敏感内容标准不同（★ 出海必查） |
| **隐私保护差异** | 欧盟 GDPR、中国 PIPL 对数据跨境要求不同 |

## 7. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| div 当按钮 | 键盘与读屏不可用 | 用原生语义标签 |
| `outline: none` | 键盘用户看不到焦点 | 提供替代焦点样式 |
| 图标无 label | 读屏播「按钮」 | 加 aria-label |
| 只靠颜色区分 | 色盲用户无法分辨 | 加图标/文字 |
| 弹窗不锁焦点 | Tab 跑到背景 | focus trap |
| 文案硬编码 | 无法翻译 | 全部外置为 key |
| 句子拼接 | 翻译后语序错乱 | 用完整模板 + 占位符 |
| 复数/日期写死 | 小语种出错 | 用 Intl / ICU |
| 流式输出刷屏读屏 | 体验灾难 | 控制 aria-live 策略 |
| 未验证小语种质量 | 模型输出质量差 | 建立多语言 evals |

## 8. Checklist

- [ ] 交互元素用语义标签，图标有 aria-label
- [ ] 键盘可完成主流程，焦点可见
- [ ] 正文对比度 ≥ 4.5:1
- [ ] 弹窗有焦点管理与 Esc 关闭
- [ ] Lighthouse a11y 分数 ≥ 90 且做过手动键盘测试
- [ ] UI 文案全部外置为 key，无硬编码
- [ ] 日期/货币/复数走 Intl / ICU
- [ ] AI 多语言有独立的质量测试集
