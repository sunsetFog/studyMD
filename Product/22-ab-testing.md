# 22 · A/B 测试：用实验验证因果

## 1. 为什么需要 A/B

相关不等于因果。A/B 实验是**唯一能可靠证明「改动导致变化」**的方法。

适用场景：改文案、改交互、改算法/策略、改推荐、改 prompt、换模型。

## 2. 实验流程

```
① 提出假设：「把主按钮从灰色改成蓝色，点击率能提升 ≥ 5%」
② 定义主指标（1 个）与护栏指标（3-5 个）
③ 计算样本量与实验周期（★ 先算，不要跑一半看）
④ 分流（随机、稳定、互斥）
⑤ 运行（不中途偷看结论，或采用序贯检验）
⑥ 分析（显著性 + 实际显著性 + 分群）
⑦ 决策（放量 / 回滚 / 继续观察）
⑧ 归档（记录结论，无论成败）
```

## 3. 指标设计

| 类型 | 说明 | 例子 |
|---|---|---|
| **主指标（1 个）** | 判断成败的唯一依据 | 提交转化率 |
| **护栏指标** | 不能变差的保护性指标 | 崩溃率、延迟、留存、成本 |
| **辅助指标** | 帮助解释原因 | 各步骤转化率、耗时 |

> 铁律：**主指标只能有一个**。多个主指标会导致「显著性的多重比较问题」——测 20 个指标，平均有 1 个会偶然显著。

## 4. 样本量与周期

```
影响样本量的因素：
① 基线转化率（baseline）
② 最小可检测效应（MDE，你想检测出的最小提升）
③ 显著性水平 α（通常 0.05）
④ 统计功效 power（通常 0.8）
```

经验公式（转化率类，α=0.05, power=0.8）：

```
每组样本量 n ≈ 16 × p(1−p) / (MDE)²      （MDE 用绝对差值）

例：基线 p=10%，想检测 +1pp（绝对）提升
n ≈ 16 × 0.1×0.9 / (0.01)² = 16 × 0.09 / 0.0001 = 14400
→ 每组 1.44 万人，两组共约 2.9 万
```

**MDE 越小，样本量按平方增长**：检测 0.5pp 需要的样本是 1pp 的 4 倍。

周期要求：
- 至少跑满 **1 个完整业务周期**（通常 7 天，覆盖周末效应）
- 新用户指标要跑够用户成熟期（如看 7 日留存至少要跑 7 天 + 观察期）

## 5. 分流原则

```
① 随机：用户 ID 哈希分流，不能用「奇数偶数」等有规律方式
② 稳定：同一用户每次进入都在同一组（否则体验不一致）
③ 互斥：同一层的实验不能重叠（用分层实验框架）
④ 均匀：两组的用户构成要一致（可做 AA 测试验证）
⑤ 同时开始：避免时间因素混入
```

**分层实验（正交）**：

```
用户 → 层1（UI 实验：按钮颜色 A/B）
    → 层2（算法实验：模型 v1/v2）
    → 层3（文案实验：文案 A/B）
各层独立哈希，互不干扰
```

## 6. 结果分析

### 显著性检验

| 指标类型 | 检验方法 |
|---|---|
| 转化率（二值） | 双比例 Z 检验 / 卡方 |
| 均值（时长、金额） | t 检验（注意长尾，可用 Mann-Whitney） |
| 计数（次数） | 泊松 / 负二项 |
| 留存（时间到事件） | 生存分析 / Log-rank |

p 值含义：**若两组真无差异，观察到这么大差异的概率**。p < 0.05 表示差异不太可能是随机波动。

### 置信区间比 p 值更有信息量

```
❌ 「提升了 3%，p=0.03」
✅ 「提升 3%，95% 置信区间 [0.4%, 5.6%]」
```

置信区间告诉你**效果的可能范围**，便于判断业务意义。

### 两个显著性都要看

| 类型 | 判断 |
|---|---|
| 统计显著 | 差异不是随机波动 |
| 实际显著 | 差异大到值得做（考虑实现成本、维护成本） |

**统计显著但业务上不值**：提升 0.2% 且实现成本高 → 不做。

## 7. 常见陷阱

| 陷阱 | 说明 | 应对 |
|---|---|---|
| **偷看（Peeking）** | 每天看结果，显著就停 | 预先定样本量跑完再判；或用序贯检验（如 SPRT） |
| 中途改指标 | 看到 A 显著就换主指标 | 实验前锁定指标 |
| 样本量不足 | 跑 2 天就下结论 | 先算样本量 |
| 新奇效应 | 新功能初期数据虚高 | 跑足够久 / 只看老用户 / 看平台期 |
| 分组不均 | 两组用户构成不同 | 做 AA 测试 / 检查分流均匀性 |
| 多重比较 | 测 20 个指标 | 只定 1 个主指标，其他做参考 |
| 只做均值分析 | 忽略分群差异 | 分群看（新老用户可能反向） |
| 忽略护栏指标 | 转化涨了但留存崩了 | 护栏指标一票否决 |
| 实验重叠污染 | 同一用户中了两个实验 | 分层互斥框架 |
| survivorship | 只看完成用户 | 看全量漏斗 |

## 8. ★ AI 产品的 A/B 特殊问题

| 问题 | 说明 | 应对 |
|---|---|---|
| **输出不确定** | 同一输入两次结果不同 | 实验对比的是「策略/模型」，需大量样本稀释随机性；对固定测试集要多次采样 |
| **成本高** | A/B 两组都要烧 token | 先离线 eval，再上小流量实验 |
| **延迟差异干扰** | 新模型更慢，可能因速度而非质量变差 | 控制变量或把延迟作为协变量分析 |
| **主观质量难量化** | 「文采更好」无法自动判定 | 人工盲评（双盲，随机顺序打分）+ 线上行为指标结合 |
| **小流量结论不稳** | AI 产品用户量小时难跑出显著性 | 用更长周期、更大 MDE、或改用前后对比+定性 |
| **prompt 改动也是实验** | 改 prompt 必须走 A/B，不能直接全量 | prompt 版本化 + 流量分桶 |
| **模型版本升级** | 供应商静默更新模型导致指标漂移 | 建立线上回归监控（见 36 篇） |

### AI 实验的推荐顺序

```
离线 eval（固定测试集，快且便宜）
   → 小流量线上实验（5-10%，看行为指标）
      → 人工抽检（盲评 100 条）
         → 全量 + 持续监控
```
