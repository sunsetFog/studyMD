# 24 · 商业模式：这个东西怎么赚钱

## 1. 商业模式的四要素

```
① 谁付钱（客户 ≠ 用户）
② 付多少（定价与定价单位）
③ 为什么付（价值主张匹配）
④ 成本结构（赚不赚钱）
```

## 2. 常见商业模式

| 模式 | 说明 | 适用 | 例子 |
|---|---|---|---|
| 订阅 SaaS | 按月/年付费 | 持续价值 | Notion、Figma |
| 按用量计费 | 用多少付多少 | 成本随用量增长 | ★ API、AI 产品 |
| Freemium | 免费+增值 | 大用户基数 | Dropbox |
| 免费+广告 | 用户免费，广告主付费 | 高频大流量 | 抖音 |
| 一次性买断 | 买断授权 | 工具型 | 早期软件 |
| 交易抽成 | 平台佣金 | 促成交易 | 淘宝、美团 |
| 许可/授权 | 企业 License | B 端大客户 | Oracle |
| 专业服务 | 项目制 | 定制化 | 咨询、集成 |
| 开源+商业版 | 社区版免费 | 开发者产品 | GitLab |

## 3. ★ AI 应用最适合的定价方式

| 方式 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| **按量（token/次数）** | 成本对齐，公平 | 用户难预测花费，不敢放开用 | API/开发者 |
| **订阅 + 额度** | 可预测，用户敢用 | 重度用户成本超支 | ★ 多数 AI 应用 |
| **按结果计费** | 与价值对齐（生成一篇多少钱） | 需定义「结果」 | 明确产出的场景 |
| **按席位** | 简单，B 端熟悉 | 与用量脱节，容易被共享账号 | B 端协作 |
| **混合（席位+额度）** | 兼顾 | 复杂 | 企业级 |

### 定价的关键考量

```
① 定价单位要与价值对齐：用户为「结果」付费更愿意，为「token」付费很抗拒
② 边际成本必须算清：重度用户是否会让你亏钱？（做「成本压力测试」）
③ 免费额度设计：够体验 Aha Moment，但不够白嫖
④ 升级触发点：用户感受到价值后再引导付费（不是一上来就拦）
```

### 成本压力测试（必做）

```
场景：一个付费用户每天用满额度
  日调用次数 × 单次成本 = 日成本
  月成本 vs 月费 → 毛利
再加：重度用户（P95）场景、恶意刷量场景
```

> AI 产品最常见的死亡原因：**定价低于重度用户的实际成本**。必须设置软/硬上限。

## 4. 定价策略

| 策略 | 说明 |
|---|---|
| 成本加成 | 成本 × (1+利润率)，简单但忽略用户价值 |
| 价值定价 | 按为用户创造的价值定价（省了 2 小时值多少钱） |
| 竞品锚定 | 参考竞品定价 |
| 分层定价 | 免费 / 基础 / 专业 / 企业，覆盖不同支付能力 |
| 撇脂定价 | 先高价后降价（新技术早期） |
| 渗透定价 | 先低价抢市场 |

### 分层设计要点

```
① 层级 3-4 档（多了决策困难）
② 差异点要清晰（功能 / 额度 / 席位 / 服务）
③ 中间档要有「推荐」标识（锚定效应）
④ 年付折扣（通常 2 个月免费，换现金流与留存）
⑤ 免费档要能体现价值但不解决全部问题
```

### 价格心理学

- **锚定**：先展示高价套餐，中档显得划算
- **99 结尾**：¥99 比 ¥100 感知便宜
- **左位数效应**：¥299 vs ¥300 差异大于 ¥299 vs ¥298
- **免费增值**：先给再收，比直接收费转化高
- **损失厌恶**：免费试用到期提醒比「限时优惠」更有效

## 5. 单位经济模型（Unit Economics）

```
ARPU（单用户平均收入）= 总收入 / 活跃用户数
LTV  = ARPU × 毛利率 × 用户平均生命周期（月）
CAC  = (市场花费 + 销售成本) / 获客数

判断：
  LTV / CAC > 3        健康
  LTV / CAC < 1        商业模式不成立
  CAC 回收期            理想 < 6 个月（SaaS）
```

★ AI 产品额外项：

```
毛利率 = 1 − (推理成本 + 存储/检索成本 + 人工支持成本) / 收入
目标毛利率：AI 应用通常 60-80%（低于传统 SaaS 的 80-90%）
```

## 6. B 端商业模式的特殊点

| 点 | 说明 |
|---|---|
| 客户 ≠ 用户 | 老板付钱，员工使用 → 要同时满足两者 |
| 决策链长 | 使用者→主管→IT→采购→财务 |
| 要求多 | 私有化、SSO、审计、SLA、发票 |
| 客单价高、周期长 | 需要销售与实施 |
| 续费是生命线 | NDR（净收入留存）> 100% 是健康标志 |
| 定制化陷阱 | 大客户定制会拖垮产品标准化 |
| 数据安全 | ★ AI 产品 B 端第一问：「我的数据会不会被用于训练」 |

## 7. 商业模式的验证顺序

```
① 先验证有人愿意用（留存）
② 再验证有人愿意付（付费意愿，可用假门/预售验证）
③ 再验证付费能覆盖成本（毛利为正）
④ 最后才规模化获取（放大）
```

**最小验证方法**：

| 方法 | 做法 |
|---|---|
| 预售/众筹 | 还没做出来就卖 |
| 假门 | 加「立即购买」按钮看点击率 |
| 直接问 | 「如果这个功能收费 ¥99/月，你会买吗」（参考性弱） |
| 小额付费测试 | 先收 ¥1 验证支付意愿（远强于口头） |

## 8. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 先做产品再想怎么赚 | 上线后发现赚不到钱 | 早期就算单位经济模型 |
| 定价单位不直观 | 卖 token 用户没概念 | 换算成「能做多少事」 |
| 重度用户亏损 | 用得越多亏越多 | 压力测试 + 软硬上限 |
| 免费额度过大 | 白嫖用户占满成本 | 额度分级 + 风控 |
| 忽略毛利率 | 收入涨但毛利不涨 | AI 成本进核心看板 |
| 层级太多 | 用户决策瘫痪 | 3-4 档 |
| 只靠单一模式 | 抗风险差 | 考虑组合（订阅+用量） |
| B 端过度定制 | 变成外包公司 | 坚持标准化，定制走配置 |

## 9. Checklist

- [ ] 能说清谁付钱、付多少、为什么付
- [ ] 定价单位与用户感知价值对齐
- [ ] 做过重度用户的成本压力测试，毛利为正
- [ ] 单位经济模型：LTV/CAC > 3，CAC 回收期合理
- [ ] 分层 3-4 档，差异清晰，有推荐档
- [ ] 免费额度能体验 Aha Moment 但不可白嫖
- [ ] B 端：明确了数据安全承诺与部署方式
