# 03 · 用户研究：怎么知道用户真正想要什么

## 1. 定性 vs 定量

| 维度 | 定性研究 | 定量研究 |
|---|---|---|
| 回答 | 「为什么」「怎么回事」 | 「有多少」「多大程度」 |
| 方法 | 访谈、观察、可用性测试 | 问卷、埋点数据、A/B |
| 样本 | 5-20 人 | 数百至数百万 |
| 产出 | 洞察、假设 | 验证、量化结论 |
| 局限 | 不能推广到全体 | 不解释原因 |

**正确顺序**：定性发现假设 → 定量验证规模 → 定性解释原因。

## 2. 用户访谈（最常用，最容易做错）

### 流程

```
① 明确这次要验证的假设（不要「随便聊聊」）
② 招募 5-8 名目标用户（找到行为同质的一群人）
③ 设计提纲（开放式问题为主）
④ 访谈 30-45 分钟
⑤ 当天整理，提取模式
```

### 好问题 vs 坏问题

| 坏问题（诱导/假设） | 好问题（开放/回溯） |
|---|---|
| 「你会用 AI 写作功能吗？」 | 「上次你写 XX 文档，是怎么完成的？」 |
| 「这个功能有用吗？」 | 「给我讲讲你最近一次做这件事的全过程」 |
| 「你愿意为它付 99 元吗？」 | 「你现在为这件事花多少钱/多少时间？」 |
| 「是不是因为太慢了？」 | 「哪个环节让你最想放弃？」 |

### 访谈技巧

- **追问行为而非观点**：「你上次是怎么做的」比「你觉得怎样」可靠 10 倍
- **沉默 3 秒**：别急着填补空白，用户会补充真话
- **避免推销**：一旦开始介绍你的方案，用户就会礼貌性说好
- **追问细节**：「然后呢」「当时你在哪」「用了多久」——细节里藏真相
- **5 Why**：遇到痛点往下挖，找到根因

> 一个反直觉：**用户说「会付费」不可信，用户已经付出的时间/金钱成本才可信**。

## 3. 问卷调研

### 设计原则

| 原则 | 说明 |
|---|---|
| 一份问卷 ≤ 15 题 | 超过后完成率断崖下跌 |
| 先行为后态度 | 先问做了什么，再问感受 |
| 选项互斥且穷尽 | 加「其他」和「不确定」 |
| 避免双重问题 | 「你喜欢它的速度和准确性吗」是两题 |
| 量表统一 | 全部用 1-5 分或 1-7 分，不要混 |
| 必答/选答分清 | 敏感信息（收入）放最后且可选 |

### 常用量表

- **NPS**：「你有多大可能推荐给朋友？」0-10 分 → 9-10 推荐者，7-8 被动者，0-6 贬损者。NPS = 推荐者% − 贬损者%
- **CSAT**：满意度 1-5 分，针对单次交互
- **CES（客户费力度）**：「完成这件事有多费劲」——**预测留存的能力常强于 CSAT**

### 样本量参考

| 目的 | 建议样本 |
|---|---|
| 定性发现 | 5-8 人访谈即可饱和 |
| 大方向验证 | 100-400 份问卷 |
| 比例推断（±5%） | 约 385 份 |
| A/B 实验 | 由效应量决定，见 22 篇 |

## 4. 观察法与情境调查

**去用户真实使用的现场看**。用户说的和你看到的常常不一致：

- 用户说「我每天都复盘」→ 观察发现他一周才打开一次
- 用户说「这个很好用」→ 观察发现他卡了 40 秒才找到按钮

做法：影子跟随（shadowing）、录屏回看、客服工单/聊天记录挖掘。

> ★ 成本最低的洞察来源：**客服记录 + 应用商店评论 + 搜索关键词**。做 AI 产品一定要看用户实际输入的 prompt 日志（脱敏后），那是需求金矿。

## 5. 可用性测试

```
任务设计：给 5 个真实任务，不告诉用户怎么做
观察点：完成率、耗时、错误次数、卡点、情绪
判定：单人发现约 30% 问题，5 人可发现约 85% 的可用性问题
```

常见误区：找同事当测试用户（他们知道答案）、边测边教（污染结果）、只测 happy path。

## 6. 用户反馈的分级处理

| 来源 | 特点 | 处理 |
|---|---|---|
| 主动投诉用户 | 声音大但可能是极少数 | 判断是否代表一类人 |
| 沉默大多数 | 不反馈，直接用脚投票 | 靠数据（流失、留存）发现 |
| 大客户/大 DAU 需求 | 价值高但可能带偏方向 | 单独评估，别影响主线 |
| 内部（老板/销售） | 高频且强势 | 追问证据，转成用户语言 |

需求池管理：**每条反馈记录「谁 + 场景 + 频次 + 影响」**，频次和付费意愿决定处理顺序。

## 7. ★ AI 产品的研究特殊点

| 特殊点 | 说明 |
|---|---|
| 用户不知道 AI 能做什么 | 不能用问卷问需求，要用**原型体验**激发 |
| 期望值管理 | 首次体验决定长期期望，demo 别过度包装 |
| 信任建立 | 观察用户对 AI 结果的**验证行为**（他会二次核对吗） |
| Prompt 日志 | 用户真实输入是最真实的需求表达 |
| 失败案例收集 | 重点研究**用户放弃的时刻**，比成功案例更有价值 |

## 8. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 只访谈忠实用户 | 结论全是好评 | 也访谈流失用户和非用户 |
| 问「会不会用」 | 得到虚假肯定 | 改问过去行为 |
| 样本太少就下结论 | 3 个人说好就做 | 定性只产出假设，需定量验证 |
| 研究完不落地 | 报告写完就归档 | 每条洞察转成需求 or 明确记为假设 |
| 把观点当事实 | 「用户说想要聊天」 | 看行为数据是否支持 |

## 9. Checklist

- [ ] 每次研究前写下要验证的假设
- [ ] 访谈提纲里没有诱导性问题
- [ ] 结论区分「洞察」与「假设」
- [ ] 定量验证过定性的发现
- [ ] 需求池每条都有「频次 + 影响 + 来源」
