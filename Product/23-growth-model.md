# 23 · 增长模型：用户从哪里来、怎么变多

## 1. AARRR 漏斗（增长经典框架）

```
Acquisition 获取 → Activation 激活 → Retention 留存
     → Revenue 收入 → Referral 推荐
```

| 阶段 | 关键问题 | 常见指标 |
|---|---|---|
| 获取 | 用户从哪来？成本多少？ | 渠道量、CAC、渠道留存 |
| 激活 | 第一次体验好吗？ | 激活率（完成核心行为）、首次耗时 |
| 留存 | 他还回来吗？ | 次留/7留/30留、DAU/MAU |
| 收入 | 能赚钱吗？ | 付费率、ARPU、LTV |
| 推荐 | 他会带人来吗？ | K 因子、邀请率、NPS |

**顺序很重要**：留没做好的时候做获取 = 往漏水的桶里加水。

## 2. Aha Moment（啊哈时刻）

> 用户第一次感受到产品核心价值的那一刻。找到它、优化它，是增长的第一杠杆。

| 产品 | Aha Moment |
|---|---|
| Facebook | 7 天内加 10 个好友 |
| Twitter | 关注 30 个人 |
| Dropbox | 在任意设备存取一次文件 |
| Slack | 团队发送 2000 条消息 |
| ★ AI 写作工具 | 第一次生成出「不用大改就能用」的稿子 |

**找 Aha Moment 的方法**：

```
① 定义核心行为（如「保存生成结果」）
② 分群对比：做过 X 次行为的用户 vs 没做过的，留存差多少
③ 找到留存曲线差异最大的那个「X 次/天内」
④ 那就是你的激活门槛，产品要做的就是让更多用户更快达到它
```

## 3. 增长飞轮 vs 漏斗

```
漏斗（线性）：拉新 → 转化 → 流失（每次都要重新买量）
飞轮（循环）：用户越多 → 数据/内容越多 → 体验越好 → 用户更多
```

飞轮的四种常见类型：

| 类型 | 机制 | 例子 |
|---|---|---|
| 内容飞轮 | UGC 内容吸引流量 → 吸引创作者 | 小红书、抖音 |
| 数据飞轮 | 用户使用 → 数据变多 → 模型/推荐更准 | 推荐系统、★ AI 产品 |
| 病毒飞轮 | 使用产品 → 触达他人 → 他人使用 | 协作工具、分享卡片 |
| 销售飞轮 | 客户成功 → 案例 → 新客户 | B2B SaaS |

> ★ AI 产品最有价值的飞轮：**用户反馈（👍👎、修正）→ 改进 prompt/模型 → 质量提升 → 更多使用**。因此**反馈入口不是可选项，是核心增长机制**。

## 4. 关键增长公式

```
K 因子（病毒系数）= 每个用户带来的新用户数
  K = 邀请率 × 邀请接受率
  K > 1：指数增长；K < 1：需要其他渠道补充

病毒周期时间：从使用到带来新用户的时间（越短越强）

LTV（用户生命周期价值）= ARPU × 平均生命周期
CAC（获客成本）= 渠道花费 / 获取用户数

健康标准：
  LTV / CAC > 3        （< 1 必死）
  CAC 回收期 < 12 个月  （SaaS 通常要求 < 6-12 月）
```

## 5. 增长杠杆的优先级

```
① 先修留存（留存是增长的乘数，1% 留存提升价值 > 10% 拉新提升）
② 再修激活（把新用户送到 Aha Moment）
③ 再优化转化与变现
④ 最后才放大获取（此时渠道才有效）
```

## 6. 渠道与获取

| 渠道类型 | 特点 | 适用 |
|---|---|---|
| 自然搜索 SEO | 长期复利，慢 | 内容型产品 |
| 应用商店 ASO | 被动流量 | App |
| 付费投放 | 快速、可控、要算 ROI | 有明确 LTV 后 |
| 内容/社媒 | 建立信任，适合专业产品 | B 端、工具类 |
| 口碑/推荐 | 成本最低、最优质 | 需要产品足够好 |
| 销售驱动 | 高客单价必需 | B2B |
| 社区/开源 | 开发者产品首选 | ★ 开发者工具 |

**渠道评估三问**：量够不够大？成本低不高？质量（留存/付费）好不好？

> 陷阱：投放渠道的「量」容易买，「留存好的量」很难。永远分渠道看留存。

## 7. 增长实验的组织方式

```
增长团队节奏（周为单位）：
① 周一：回顾上周指标，选题
② 本周：并行 2-4 个实验（ICE 排序）
③ 周五：实验结果评审
④ 获胜的实验固化为产品能力
```

**增长 backlog** 用 ICE 排序：`(Impact × Confidence) / Ease`。

## 8. ★ AI 产品的增长特点

| 特点 | 说明 |
|---|---|
| **边际成本高** | 每个用户的每次调用都要钱，用户越多成本越高（与传统软件相反） |
| **免费额度要算账** | 免费用户不是「零成本」，要有额度与风控（防刷） |
| **效果即增长** | AI 产品质量好会自带口碑（生成结果被分享 = 天然传播） |
| **分享卡是天然增长点** | AI 生成的结果（图/文）适合带品牌水印分享 |
| **模型能力跃迁是机会窗口** | 新模型发布时抢先适配，可获得一波自然流量 |
| **成本下降是增长杠杆** | 推理成本降低 → 可以放开免费额度 → 用户增长 |
| **警惕「AI 好奇用户」** | 大量用户试一次就走，要把他们转化为有真实场景的用户 |

## 9. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 留存没做好就猛投放 | 钱烧完用户也没剩 | 先达成留存门槛再放量 |
| 只看拉新数 | 渠道量好看但留存差 | 分渠道看 LTV/CAC |
| 补贴依赖 | 停止补贴就流失 | 补贴要用于培养习惯 |
| 忽视 Aha Moment | 新用户不知道干嘛 | 优化首次引导 |
| K 因子算错 | 把「分享次数」当 K | K = 实际带来的新用户 |
| 增长与体验冲突 | 弹窗骚扰、诱导分享 | 设体验护栏指标（投诉率、留存） |
| AI 免费额度无限 | 被薅羊毛烧穿 | 额度限制 + 异常检测 |
| 忽略单位经济模型 | 规模越大亏越多 | 单用户毛利必须为正 |

## 10. Checklist

- [ ] 定义了 Aha Moment，且有激活率指标
- [ ] 留存曲线走平（或正在改善）后再放大获取
- [ ] 每个渠道都有 CAC 与分渠道留存数据
- [ ] LTV/CAC > 3，CAC 回收期在合理范围
- [ ] 有增长实验节奏与 backlog（ICE 排序）
- [ ] AI 产品的单位经济模型为正，有额度与风控
