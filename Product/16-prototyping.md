# 16 · 原型：把想法变成可讨论的东西

## 1. 原型的目的

```
① 让抽象想法变具体（团队对齐）
② 低成本试错（改原型比改代码便宜 100 倍）
③ 获取用户反馈（可用性测试）
④ 作为 PRD 的补充说明（一图胜千言）
```

原型**不是**设计稿的替代品，**更不是**最终视觉标准。

## 2. 保真度选择

| 保真度 | 形态 | 用途 | 成本 |
|---|---|---|---|
| 纸面/草图 | 手绘、白板 | 探索方案、快速发散 | 分钟级 |
| 线框（Wireframe） | 灰框图，只有布局 | 讨论结构、流程 | 小时级 |
| 中保真 | 有布局+交互，无视觉细节 | 可用性测试、评审 | 天级 |
| 高保真 | 接近成品，含视觉与动效 | 用户测试、开发参照、Demo | 天-周级 |
| 可交互/代码原型 | 真能点、能跑逻辑 | 投资演示、真实验证 | 周级 |

**原则**：够用就好。用高保真验证结构问题是浪费。

| 要验证什么 | 用哪种 |
|---|---|
| 布局/信息优先级 | 线框 |
| 流程是否走得通 | 中保真可点击 |
| 交互是否顺手 | 中-高保真 |
| 视觉/品牌感受 | 高保真 |
| 用户会不会用/愿不愿付费 | 可运行 MVP |

## 3. 原型工具

| 工具 | 特点 | 适用 |
|---|---|---|
| Figma | 主流、协作强、组件化 | 全流程首选 |
| Axure RP | 强交互、条件逻辑、变量 | 复杂 B 端逻辑 |
| 墨刀 / 即时设计 | 国产、上手快 | 快速原型 |
| Sketch | macOS、生态成熟 | 视觉设计 |
| Framer | 高保真 + 可发布 | 落地页、动效 |
| HTML/代码原型 | 最真实 | 前端能直接参与时 |

★ AI 辅助：现在可用文本/截图生成原型的工具（v0、Galileo、Figma AI），适合快速出第一版草稿，但**复杂逻辑仍需人工整理**。

## 4. 画原型的规范

### 必备元素

```
① 页面标题与版本号（v1.2）
② 状态覆盖：空状态 / 加载中 / 正常 / 错误 / 无权限
③ 交互说明：点击后去哪、hover 效果、动效时长
④ 边界标注：最多多少字、截断规则、超出怎么办
⑤ 数据示例：用真实感的数据，别用 lorem ipsum
⑥ 链接与跳转标注（数字标号对应）
```

### 灰度规范（线框）

```
主内容：深灰 #333
次要：中灰 #888
占位/图片：浅灰 + 叉号
强调/主按钮：用唯一的高亮色（通常蓝）
禁用态：浅灰 + 斜线
```

线框不用彩色（除非表达状态），避免评审焦点跑偏到视觉。

## 5. 原型评审怎么开

```
会前：原型提前 1 天发出，附 PRD 与背景
会中：
  ① PM 讲背景与目标（5min）—— 不讲这个，评审必变审美讨论
  ② 演示主流程（5min）
  ③ 逐个功能点过（重点：异常与边界）
  ④ 开发/测试提问（可行性、工时、风险）
  ⑤ 当场记录待办与决策
会后：24h 内发出评审纪要（含决策 + 待办 + 负责人 + 时间）
```

### 评审常见问题与应对

| 问题 | 应对 |
|---|---|
| 纠结颜色/字号 | 「视觉下一轮再定，先定结构」 |
| 发散到新需求 | 「记进需求池，会后再评估」 |
| 沉默不表态 | 点名提问：「这个流程你实现上有风险吗」 |
| 老板拍板改方案 | 记录决策，同时补充影响分析 |

## 6. 用原型做可用性测试（低成本）

```
① 设计 3-5 个真实任务
② 找 5 个目标用户
③ 「你想完成 XX，请用这个原型试试」（不指导）
④ 观察：完成率、耗时、卡点、误操作、口头反馈
⑤ 记录问题并按严重度排序（阻断 > 严重 > 一般 > 建议）
⑥ 改原型 → 再测一轮（如问题严重）
```

## 7. ★ AI 产品的原型特殊要求

| 要求 | 说明 |
|---|---|
| **必须做状态原型** | AI 产品的核心体验在于「等待/流式/失败」，只画静态结果页是不够的 |
| **模拟真实延迟** | 用真实速度演示（可用假数据 + 定时输出），否则无法评估体验 |
| **覆盖失败态** | 模型超时、输出不合法、内容被拒答，都要画 |
| **多轮对话流** | 画清楚上下文如何延续、历史如何展示 |
| **结果的可编辑性** | 展示用户能不能改、改哪个部分 |
| **用真实输出做 demo** | 别用手写的理想结果，用模型真实跑出来的（含瑕疵） |
| **别过度包装 demo** | demo 太完美会拉高期望，上线后失望 |

## 8. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 只画 happy path | 空态/错误态开发瞎猜 | 五种状态全画 |
| 用假数据太理想 | 上线后真实数据撑爆布局 | 用最长/最短/极端数据验证 |
| 原型即需求 | 逻辑没写清 | 原型 + PRD 规则 + AC |
| 保真度错配 | 讨论结构却做高保真 | 按验证目标选保真度 |
| 评审变审美会 | 一小时讨论颜色 | 背景与目标先讲，视觉另开 |
| 不标版本 | 开发按旧版做 | 每次更新改版本号与日期 |
| AI 原型不做失败态 | 上线后异常体验崩坏 | 失败态与降级必须画 |

- [ ] 每个页面覆盖 空/加载/正常/错误/无权限 五态
