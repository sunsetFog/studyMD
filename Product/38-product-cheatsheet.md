# 38 · 产品速查清单与自测题

## 一、一句话速查

| 概念 | 一句话 |
|---|---|
| 产品思维 | 从用户 Job 出发，而不是从功能/技术出发 |
| JTBD | 当【情境】我想要【动机】以便【结果】 |
| 真伪需求 | 谁 + 频次 + 强度 + 规模 |
| KANO | 基本型先达标，期望型拉差距，兴奋型造惊喜 |
| 定位 | 为谁、是什么品类、提供什么价值、凭什么不同 |
| PRD | 背景目标 + 功能清单 + 边界异常 + AC + 埋点 |
| AC | Given-When-Then，可测试，覆盖异常 |
| MVP | 用最小成本验证风险最高的假设 |
| RICE | (Reach × Impact × Confidence) / Effort |
| 北极星 | 最能代表用户价值获得的单一指标 |
| Aha Moment | 用户第一次感受到价值的时刻 |
| 留存 | PMF 的判定标准：曲线走平 |
| LTV/CAC | > 3 健康；< 1 不成立 |
| PLG | 产品自己卖自己：TTV 短 + 免费体验 + 病毒循环 |
| ★ AI 选型 | 验证成本低的场景最适合 AI |
| ★ AI 成本 | 每次调用都有成本，必须算单位经济 |
| ★ Evals | AI 产品的单元测试，没有它改了就会悄悄变坏 |

## 二、常用公式

```
RICE      = (Reach × Impact × Confidence) / Effort
机会分     = 重要性 + (重要性 − 满意度)
A/B 样本量 ≈ 16 × p(1−p) / MDE²        （每组，α=0.05, power=0.8）
K 因子     = 邀请率 × 接受率（> 1 才指数增长）
LTV       = ARPU × 毛利率 × 生命周期
毛利率     = 1 − (推理+存储+人工) / 收入
单次成本   = 输入token × 输入单价 + 输出token × 输出单价
```

## 三、上线前 Checklist（通用）

```
需求侧
□ 说清了为谁解决什么问题（Job + 场景）
□ 有数据或访谈证据支撑（不是拍脑袋）
□ 写清了「不做什么」
□ 有可衡量的目标指标
□ AC 覆盖正常 + 至少 3 个异常场景

设计侧
□ 覆盖空/加载/正常/错误/无权限五态
□ 主路径 ≤ 3 步
□ 等待有反馈，> 3s 可取消
□ 错误提示含「发生了什么 + 怎么办」
□ 关键操作可撤销

工程侧
□ 埋点已设计并在预发验证
□ 有监控与告警
□ 有灰度与回滚方案
□ 性能与兼容性达标

发布后
□ 首日/首周看核心指标
□ 收集用户反馈
□ 复盘是否达成目标指标
```

## 四、上线前 Checklist（AI 功能专用）

```
可行性
□ 做过 spike，有真实样本的合格率
□ 定义了「合格」的质量基线
□ 与「非 AI 方案」比较过，确认 AI 是最优解

质量
□ 有 ≥ 50 条 evals 测试集
□ 跑过离线回归，通过率不退化
□ 做过人工抽检（盲评）
□ 线上有金丝雀集每日跑（检测漂移）

成本
□ 算过单次成本与重度用户月成本
□ 单用户毛利为正
□ 有成本上限、限流、降级方案
□ 成本告警已配置

体验
□ 流式输出，首 token < 2s
□ 结果可编辑、可复制、可再生成
□ RAG 有引用来源可核验
□ 低置信度有提示
□ 失败有明确文案与兜底
□ 有 👍👎 反馈入口

安全合规
□ 输入防注入，输出内容安全过滤
□ 检索做了权限过滤
□ 有 AI 标识
□ 日志脱敏、可追溯
□ 高风险场景有人工确认
□ 数据合规（备案/出境评估/是否用于训练）
```

## 五、自测题（检验是否真的懂了）

### 基础

1. 用户说「我要一个导出 Excel 的按钮」，你应该怎么回应？
2. KANO 中「基本型需求」没做好会怎样？做好了会怎样？
3. 一个需求用 RICE 打分最高，但它是 KANO 的基本型且未达标，先做哪个？
4. PRD 里为什么必须写「不做什么」？
5. 留存曲线走平意味着什么？

### 进阶

6. 你怎么判断一个 AI 功能该不该做？（至少 4 个判断维度）
7. 用户反馈「AI 生成的结果不好」，你怎么拆解这个问题？
8. 换了一个更强的模型，为什么不能直接全量上线？
9. 免费用户越来越多，成本飙升，你有哪些手段？
10. AI 产品的北极星为什么不该是「生成次数」？

### 参考思路

1. 追问 Why，找到真实目标（可能不需要导出按钮，而是需要「让领导看到进展」）
2. 没做好 → 极度不满；做好了 → 没感觉（不会提升满意度）
3. 先做基本型（底线优先，RICE 不考虑这个维度）
4. 防止范围膨胀，明确边界，也是团队共识的一部分
5. 找到了一群会长期留下来的用户 = 接近 PMF
6. AI 必要性、错误容忍度、准确率可行性、成本、延迟、失败代价、数据可得性
7. 分类拆解：是格式问题、事实错误、遗漏、语气、还是期望不匹配？看 bad case 与线上指标（采纳率/编辑幅度）
8. 需要跑 evals 回归 + 人工抽检 + 小流量实验；新模型可能风格不同、成本不同、延迟不同
9. 缓存、小模型路由、缩短上下文、限额度、额度分级、付费墙、异常检测
10. 生成次数多可能说明结果不好（反复重生成）；应衡量「被采纳的结果数」

## 六、常见数字基准（粗略参考，因品类而异）

| 指标 | 参考值 |
|---|---|
| 次日留存（C 端工具） | 40-60% |
| 30 日留存（C 端） | 15-25% |
| DAU/MAU 粘性 | 30-50% |
| SaaS 自助转化率 | 2-5%（优秀 5-10%） |
| LTV/CAC | > 3 |
| NDR（B 端） | > 100% |
| 崩溃率 | < 0.2% |
| 页面响应 | < 400ms（多尔蒂门槛） |
| 首 token 延迟（AI） | < 2s |
| AI 应用毛利率 | 60-80% |
| evals 通过率 | ≥ 90%（视场景） |
| 拒答率（RAG） | 5-15% |
