# 25 · 留存：产品生死的唯一指标

## 1. 为什么留存是第一指标

```
留存差 → 拉新再多也会漏光 → CAC 无法回收 → 商业模式不成立
留存好 → 用户自然积累 → 口碑传播 → 增长变便宜
```

**PMF（产品市场契合）的判定信号**：留存曲线**走平**（不再下降到 0），且留存率在行业基准之上。

| 阶段 | 判断 |
|---|---|
| 曲线持续下降到 0 | 没有 PMF |
| 曲线走平但低（如 10%） | 弱 PMF，需提升价值 |
| 曲线走平且较高（> 20-40%，视品类） | PMF 成立 |

## 2. 留存的定义（口径必须统一）

| 定义 | 说明 |
|---|---|
| 第 N 日留存 | 注册后第 N 日（当天）活跃的用户比例 |
| 第 N 日及以后留存 | 第 N 日或之后任意一天活跃过 |
| 滚动留存 | 第 N 日之后仍活跃（含当日） |
| 无限留存（Bracket） | 第 N 日之后任意时间活跃 |
| 回访留存 | 按「核心行为完成」定义活跃 |

> 同一个产品，不同定义算出的数字能差 2 倍。**团队必须统一一个定义并写进指标字典。**

## 3. 三层留存

```
① 短期留存（次日/3日）：反映新用户体验与激活
② 中期留存（7日/月留存）：反映核心价值是否成立
③ 长期留存（3月/6月）：反映习惯养成与持续价值
```

分别对应不同的产品工作：

| 层 | 主要影响因素 | 主要手段 |
|---|---|---|
| 短期 | 首次体验、引导、性能 | 新手引导、降低首次门槛 |
| 中期 | 核心价值交付、Aha Moment | 提升核心功能质量 |
| 长期 | 习惯、数据沉淀、网络效应 | 数据资产沉淀、提醒与召回 |

## 4. 提升留存的四个方向

### ① 优化新用户引导（Onboarding）

```
原则：
  - 减少注册摩擦（能后填的就后填）
  - 尽快给到价值（不是先填一堆资料）
  - 用示例/模板代替空白
  - 一次性只教一件事
  - 允许「先看看」（游客模式）
```

### ② 让用户更快到达 Aha Moment

```
① 量化：完成 X 次核心行为的用户留存显著更高
② 缩短路径：减少到达 X 次的步骤
③ 引导：主动提示「试试这个」
④ 降低门槛：提供模板、默认值、一键示例
```

### ③ 沉淀（让用户走不掉，正向意义上）

| 沉淀类型 | 例子 |
|---|---|
| 数据沉淀 | 历史记录、自定义模板、知识库 |
| 关系沉淀 | 好友、协作成员 |
| 习惯沉淀 | 每日任务、连续打卡 |
| 配置沉淀 | 个性化设置、工作流 |
| ★ AI 沉淀 | 用户的 prompt 库、历史产出、专属知识库、风格偏好 |

> ★ AI 产品的沉淀设计极其重要：用户上传的知识库、调好的 prompt、历史产出都是迁移成本。

### ④ 召回（唤醒沉默用户）

| 手段 | 说明 |
|---|---|
| 推送/邮件/短信 | 要有价值内容，不是广告 |
| 个性化内容 | 「你关注的 X 有更新」 |
| 周期性需求触发 | 周报工具每周一提醒 |
| 流失预警 | 行为下降时主动干预 |
| 回归礼包 | 谨慎使用，易吸引羊毛党 |

**召回的前提是产品本身有价值**，否则召回只是再流失一次。

## 5. 留存分析方法

### 分群留存（Cohort）

```
按注册日期/渠道/版本分组，看每组随时间的留存曲线
用途：判断产品改动是否真的提升了留存（新 cohort 曲线是否更高）
```

### 行为分群对比（找 Aha Moment）

```
对比「完成核心行为 ≥ N 次」vs「< N 次」用户的留存差异
差异最大的 N 就是魔法数字（Magic Number）
```

### 流失用户研究

```
① 找出流失用户（如 14 天未活跃）
② 看他们最后一次做了什么（在哪一步离开）
③ 抽样访谈（这是最有价值的信息）
④ 对比留存用户的早期行为差异
```

## 6. 流失原因分类

| 类型 | 原因 | 对策 |
|---|---|---|
| 价值不符 | 期望与实际不匹配 | 管理期望、改进核心体验 |
| 太难用 | 学习成本高 | 简化、引导 |
| 用完即走 | 一次性需求 | 拓展场景、沉淀数据 |
| 被替代 | 竞品更好 | 差异化、提升壁垒 |
| 技术原因 | 崩溃、慢、bug | 技术优化 |
| 忘记 | 无提醒、低频 | 建立触发机制 |
| ★ AI 特有 | 结果质量不稳定、第一次失望 | 质量基线、失败兜底、引导输入 |

## 7. 行业基准参考（仅供粗略对照）

| 类型 | 次日留存 | 7 日留存 | 30 日留存 |
|---|---|---|---|
| 社交/工具类 C 端 | 40-60% | 25-40% | 15-25% |
| 内容/资讯 | 25-40% | 15-25% | 8-15% |
| 电商 | 20-30% | 10-15% | 5-10% |
| B 端 SaaS | — | 60-80%(活跃) | 高（靠续费） |
| 游戏 | 30-50% | 15-25% | 5-10% |

> 基准因品类差异极大，**最可靠的基准是你自己过去的曲线**（看趋势变化）。

## 8. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 口径不统一 | 各部门留存数不同 | 写进指标字典 |
| 只看整体留存 | 掩盖新用户问题 | 必看 cohort 与分群 |
| 用拉新掩盖留存问题 | DAU 涨了但都是新客 | 看老用户留存 |
| 只做召回不做产品 | 召回后再流失 | 先解决价值问题 |
| 推送滥用 | 关推送/卸载 | 推送要有价值，可设置 |
| 忽略流失用户访谈 | 不知道为什么走 | 定期访谈流失用户 |
| 短期只看次日留存 | 中期迅速崩 | 三层次都看 |
| AI 忽略首次失望 | 试一次就永久放弃 | 优化首次成功率 |

## 9. Checklist

- [ ] 留存定义统一并写入指标字典
- [ ] 有 cohort 留存看板（按渠道/版本分群）
- [ ] 找到并验证了「魔法数字」（Aha Moment）
- [ ] 有沉淀机制（数据/配置/关系）
- [ ] 定期做流失用户访谈（每月 ≥ 5 人）
- [ ] 短期/中期/长期三层留存都有监控
- [ ] AI 产品：首次成功产出率与首次失望率被监控
