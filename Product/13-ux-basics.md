# 13 · UX 基础：可用性的底层逻辑

## 1. 用户体验的五个要素（从抽象到具体）

```
战略层：用户想要什么 + 我们要什么
范围层：做哪些功能、哪些内容
结构层：怎么组织（交互流程、信息架构）
框架层：界面布局、导航、控件位置
表现层：视觉呈现（配色、字体、质感）
```

**自下而上决定，自上而下才能改**：表现层发现的问题，根因可能在战略层。

## 2. 可用性的五个维度（Nielsen）

| 维度 | 含义 | 例子 |
|---|---|---|
| 易学性 | 新用户多久能上手 | 第一次就能完成核心任务 |
| 效率 | 熟练用户多快完成 | 快捷键、批量操作 |
| 可记忆性 | 隔一段时间回来还能用 | 一致的布局与命名 |
| 错误 | 出错频率与恢复难度 | 防错设计 + 撤销 |
| 满意度 | 使用感受 | 主观愉悦度 |

## 3. 认知负荷：体验好坏的物理根源

人的工作记忆容量有限（约 4±1 个组块）。一切 UX 设计都在做**认知负荷管理**。

| 负荷类型 | 说明 | 优化方式 |
|---|---|---|
| 内在负荷 | 任务本身的难度 | 拆分步骤、提供默认值 |
| 外在负荷 | 界面带来的额外负担 | 简化、去除无关元素 |
| 相关负荷 | 用于学习理解的负荷 | 引导、示例、渐进披露 |

### 降低认知负荷的实操手法

```
① 渐进披露：默认展示 3 项，高级设置折叠
② 提供默认值：80% 用户不改默认值
③ 分块（Chunking）：表单分组、数字分段（138-0013-8000）
④ 识别优于回忆：用下拉/示例，而非让用户凭记忆输入
⑤ 一致性：同类操作位置与样式统一
⑥ 减少选择：选项超过 7 个就要分类或搜索
```

## 4. 三大设计原则

### ① 可见性（Visibility）

**用户能看到什么状态、能做什么操作**。

- 系统状态可见：加载中、进度、成功/失败反馈（0.1s 内响应，1s 内给反馈，>10s 显示进度）
- 可供性（Affordance）：可点的东西看起来就可点（按钮有阴影/边框）
- 映射关系明确：控件与它的作用对象在位置上接近

### ② 反馈（Feedback）

每个操作都要有即时响应：

| 操作时长 | 应该给什么 |
|---|---|
| < 0.1s | 感觉是即时的，无需提示 |
| 0.1-1s | 有轻微反馈（按钮按下态） |
| 1-3s | 显示加载指示 |
| 3-10s | 显示进度 + 可取消 |
| > 10s | 后台处理 + 允许离开，完成后通知 |

### ③ 容错（Error Tolerance）

```
防错优于报错：
  - 删除前二次确认
  - 危险操作需要显式动作（输入名称确认）
  - 约束输入（日期选择器而非自由输入）

出错后易恢复：
  - 提供撤销（Ctrl+Z）
  - 保留用户输入不丢失
  - 错误信息：说清「发生了什么 + 为什么 + 怎么办」
```

错误提示三段式：

```
❌ 「操作失败」                          （没信息量）
❌ 「错误码 5003」                       （用户看不懂）
✅ 「生成失败：网络连接中断。
     你的输入已保存，点击重试即可继续。」
```

## 5. 一致性原则

| 层次 | 要求 |
|---|---|
| 内部一致 | 产品内同类操作一致 |
| 外部一致 | 遵循平台规范（iOS/Android/Web 惯例） |
| 隐喻一致 | 图标与含义符合常识（齿轮=设置，垃圾桶=删除） |

## 6. 尼尔森十大可用性启发式（速记版）

1. **系统状态可见性**
2. **系统与现实匹配**（用用户的语言）
3. **用户控制与自由**（撤销/退出）
4. **一致性与标准**
5. **错误预防**
6. **识别优于回忆**
7. **灵活高效使用**（新手/专家两条路径）
8. **美观与简约**（去掉无关信息）
9. **帮助用户识别、诊断并恢复错误**
10. **帮助与文档**（必要时才有）

## 7. ★ AI 产品的 UX 特殊要求

| 要求 | 说明 |
|---|---|
| **设定正确预期** | 首屏就要说清「AI 会做什么、可能不完美」 |
| **过程可见** | 流式输出、展示「正在分析…」中间态，降低等待焦虑 |
| **可控可中断** | 随时停止、可重试、可局部重生成 |
| **结果可编辑** | AI 输出必须能改，用户才敢用 |
| **不确定性表达** | 低置信度时明确提示「这条结果置信度较低」 |
| **可溯源** | 展示引用来源，让用户能验证（RAG 场景刚需） |
| **优雅降级** | 模型失败时给出可用的兜底，而不是空白 |
| **冷启动引导** | 空输入框是最难的，给示例/模板/推荐 |

## 8. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 只做视觉不做流程 | 界面好看但走不通 | 先跑通流程再美化 |
| 选项过多 | 首屏 20 个按钮 | 主路径只留 1-3 个 CTA |
| 加载无反馈 | 点了没反应，用户狂点 | 及时反馈 + 防重复提交 |
| 报错说人话失败 | 「系统异常，请重试」 | 三段式错误提示 |
| 清空用户输入 | 失败后输入没了 | 任何失败都要保留输入 |
| 弹窗滥用 | 一进页面三个弹窗 | 弹窗只用于阻断性事件 |
| AI 输出不可控 | 生成中无法停止 | 必须支持中断 |
| AI 结果不可改 | 只能整段重生成 | 支持局部编辑 |

## 9. Checklist

- [ ] 核心任务 3 步内完成
- [ ] 所有等待都有反馈，>3s 可取消
- [ ] 危险操作有确认，重要操作可撤销
- [ ] 错误提示包含「发生了什么 + 怎么办」
- [ ] 首屏主 CTA 不超过 2 个
- [ ] AI 功能：可中断、可编辑、可溯源、有降级
