# 20 · 指标体系：用什么衡量产品好坏

## 1. 指标的三层结构

```
北极星指标（1 个）：产品长期价值的单一衡量
      ↓ 拆解
一级指标（3-5 个）：构成北极星的关键因子
      ↓ 拆解
二级/过程指标：可被执行直接影响的指标
```

反例：一堆指标平铺（DAU、留存、时长、付费率、NPS…），没有结构 = 没有重点。

## 2. 北极星指标（NSM）

> 定义：**最能代表产品向用户交付价值**的那个指标。它增长 = 用户得到的价值增长 = 商业价值增长。

### 好北极星的标准

| 标准 | 说明 |
|---|---|
| 反映用户价值 | 用户得到价值时它就涨 |
| 领先于收入 | 它涨了，收入随后会涨 |
| 可被团队影响 | 团队行动能改变它 |
| 可理解可沟通 | 一句话说清，全员记得住 |
| 是比率或累积量，不是绝对数 | 避免单纯追求规模 |

### 案例对照

| 产品 | 北极星 |
|---|---|
| Airbnb | 预订间夜数 |
| Facebook | 日活跃用户数（早期：7 日内添加 10 个好友的用户数） |
| Slack | 团队发送的消息数 |
| Notion | 有内容的页面数 |
| ★ AI 写作工具 | **用户成功产出并采纳的文稿数**（不是生成次数！） |

> ★ AI 产品的陷阱：用「调用次数/生成次数」当北极星——用户反复生成说明结果不好。**要衡量「被采纳的结果」**。

## 3. OSM 模型（指标拆解）

```
O（Objective）目标：提升用户成功产出量
S（Strategy）策略：
   S1 提高首次成功率
   S2 提高单次产出质量
   S3 提高复用频率
M（Measure）度量：
   S1 → 首次会话产出率、首次产出耗时
   S2 → 采纳率、编辑幅度、👍 比例
   S3 → 周活跃天次、人均周产出数
```

**Uber 的 OMTM（One Metric That Matters）** 思想：每个阶段只盯一个指标，打完换下一个。

## 4. 常见指标定义（口径必须写清）

### 活跃

| 指标 | 定义要点 |
|---|---|
| DAU/WAU/MAU | 「活跃」的行为定义必须明确（打开？有核心操作？） |
| DAU/MAU 粘性 | 30%-50% 为健康，>50% 优秀 |
| 人均使用时长 | 警惕：时长高可能是体验差（找不到东西） |
| 核心行为完成率 | 访问 → 完成核心动作的比例 |

### 留存

| 指标 | 定义 |
|---|---|
| 次日/7日/30日留存 | 第 N 日回访的比例 |
| N 日留存定义分歧 | 「第 N 日活跃」vs「第 N 日及之后仍活跃」，必须统一 |
| 分群留存 | 按渠道、版本、行为分层看，整体留存会掩盖问题 |

### 转化

```
漏斗：曝光 → 点击 → 注册 → 激活 → 首次核心价值 → 付费 → 复购
每层记录：进入数、转化率、流失数、中位耗时
```

### 质量/健康度

| 指标 | 说明 |
|---|---|
| 崩溃率 | < 0.2% 为佳 |
| 接口错误率 / P95 延迟 | 技术健康 |
| 客服工单率 | 每百活跃用户的工单数 |
| NPS / CSAT / CES | 主观满意度 |

## 5. 虚荣指标 vs  actionable 指标

| 虚荣指标 | 可行动指标 |
|---|---|
| 累计注册用户数 | 周活跃用户数 |
| 总下载量 | 次日留存率 |
| 页面 PV | 核心任务完成率 |
| 生成总次数 | 采纳率（生成后被使用/保存的比例） |
| 曝光量 | 点击转化率 |

检验方法：**这个指标变了，你知道该做什么吗？** 不知道 → 虚荣指标。

## 6. 埋点设计（数据的基础）

### 事件设计三要素

```markdown
事件名：generate_result（动词_名词，全小写下划线）
触发时机：结果渲染完成时（不是点击时）
属性：
  - user_id, session_id
  - scene（场景）
  - model（模型版本）
  - input_length, output_length
  - latency_ms, first_token_ms
  - cost（本次成本）
  - is_stream（是否流式）
  - result_id（用于关联后续采纳/反馈事件）
```

### 埋点原则

```
① 先定指标体系，再定埋点（倒推）
② 公共属性自动带（用户、设备、版本、渠道）
③ 事件名与属性名全站统一，建数据字典
④ 关键路径必须有漏斗事件
⑤ 上线前验证埋点（抓包/看板核对）
⑥ 埋点变更要版本管理（改名等于断数据）
```

### 常见埋点方式

| 方式 | 特点 |
|---|---|
| 代码埋点 | 精确可控，成本高 |
| 全埋点/无埋点 | 自动采集点击，省事但脏 |
| 可视化埋点 | 圈选，平衡方案 |
| 后端埋点 | 可靠（不受前端拦截），适合关键业务事件 |

> 关键业务事件（付费、核心转化）**必须后端埋点**，前端埋点会丢失 5-20%。

## 7. ★ AI 产品的指标体系

| 类别 | 指标 |
|---|---|
| **使用** | 日活跃会话数、人均会话轮次、人均成功产出数 |
| **质量** | 采纳率、编辑幅度（改动比例）、👍率、重生成率、放弃率 |
| **性能** | 首 token 延迟、总延迟 P95、超时率、失败率 |
| **成本** | 单次成本、日/月总成本、单用户成本、毛利率 |
| **安全** | 拒答率、安全拦截率、投诉率、幻觉投诉 |
| **价值** | 节省时长（用户自评或实测）、付费转化、留存 |

**核心公式**：

```
单用户月毛利 = 付费额 − (月调用次数 × 单次成本) − 其他成本
```

如果这个数经常为负，产品规模越大亏得越多——AI 产品最常见的死法。

## 8. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 指标太多没重点 | 看板 50 个图 | 定北极星，一级指标 ≤ 5 |
| 口径不清 | 两个部门留存数不一样 | 写指标字典，统一定义 |
| 只看总量不看分群 | 平均留存掩盖新用户崩溃 | 按渠道/版本/分层看 |
| 埋点事后补 | 上线后才发现没数据 | 埋点随 PRD 评审 |
| 事件名随意改 | 历史数据断裂 | 埋点版本管理 |
| 只看 DAU 不看价值 | 用户来了没得到价值 | 加「核心价值完成率」 |
| 追求虚荣指标 | 注册数好看没人用 | 换成活跃与留存 |
| AI 不看成本 | 用户越多亏越多 | 成本指标进核心看板 |

## 9. Checklist

- [ ] 有一个明确的北极星指标，全员知道
- [ ] 用 OSM 拆解到可执行的过程指标
- [ ] 有指标字典（定义、口径、计算方式、负责人）
- [ ] 关键转化漏斗埋点完整且上线前验证过
- [ ] 看板按分群（渠道/版本/用户层）可下钻
- [ ] AI 产品：质量、成本、延迟指标与业务指标同屏
