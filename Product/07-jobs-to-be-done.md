# 07 · JTBD：用户「雇用」你的产品做什么

## 1. 核心思想

> 用户不是在购买产品，而是在**雇用**产品去完成某个「任务」（Job）。

经典案例：人们买奶昔，不是为了「好喝的奶制品」，而是早上通勤时**雇它来让无聊的通勤变有趣、撑到中午不饿**。

这解释了为什么「改进奶昔口味」（产品思维）无效，而「加果粒增加咀嚼趣味」（任务思维）有效。

## 2. JTBD 陈述句式（模板）

```
当【情境】，我想要【动机】，以便【期望结果】。

例：
当【我在周一早上要交上周的项目周报】，
我想要【快速把零散记录变成一段通顺的总结】，
以便【领导能一眼看懂进展，我不用花 40 分钟排版】。
```

比「用户故事」更强的点：它包含**情境与动机**，解释了用户为什么现在要行动（触发点）。

## 3. 四个要素

| 要素 | 内容 | 例子 |
|---|---|---|
| 情境 | 何时何地什么状态 | 周一早 9 点、被催交 |
| 动机 | 情绪/功能驱动 | 怕被说不专业 |
| 期望结果 | 想达成的状态 | 5 分钟交差且看起来专业 |
| 障碍 | 现在的困难 | 记录零散、不会排版 |

## 4. 挖掘 JTBD 的方法：时间线回溯

让用户回忆**第一次意识到需要改变的时刻**：

```
① 什么时候开始觉得「这样不行了」？（触发事件）
② 在那之前你一直在用什么？（旧方案）
③ 你考虑过哪些选择？（考虑集）
④ 最终为什么选了现在这个？（决策标准）
⑤ 用的时候是什么感受？（推动力与焦虑力）
```

- **推动力（Push）**：现有方案的不满（太慢、太贵、太烦）
- **拉力（Pull）**：新方案的吸引力（更快、更智能）
- **焦虑（Anxiety）**：对新方案的担忧（AI 写的不准怎么办）
- **惯性（Inertia）**：现有习惯的黏性（我已经有模板了）

**只有当 推动力 + 拉力 > 焦虑 + 惯性 时，用户才会切换**。这是判断 AI 产品能否被采用的钥匙。

## 5. 结果陈述（Desired Outcome）：把模糊需求变成可衡量

用户想要的「结果」应该写成可改进的指标：

```
「减少【对象】【度量】【方向】」

例：
- 减少【从开始写到发出周报】的【时间】【从 40 分钟到 5 分钟】
- 减少【文案被平台判违规】的【概率】【从 10% 到 1%】
- 增加【一次生成就可用】的【比例】【从 30% 到 80%】
```

实操方法：**机会算法（Opportunity Score）**

```
机会分 = 重要性 + (重要性 − 满意度)

重要性：这个结果对用户多重要（1-10）
满意度：当前方案满足程度（1-10）
机会分 > 10 表示存在明显未满足需求
```

## 6. JTBD vs 传统需求描述

| 传统 | JTBD |
|---|---|
| 「用户要导出 Excel」 | 「当领导要看进展时，我要一份随时能转发、不用登录就能看的快照」 |
| 「用户要 AI 摘要」 | 「当我打开一个 30 页文档没时间读时，我要 30 秒知道它跟我有没有关系」 |
| 「要支持多模型切换」 | 「当某个模型抽风时，我要有备选，不耽误交付」 |

看出区别了吗？JTBD 描述里往往**已经藏着更好的解法**。

## 7. ★ AI 产品怎么用 JTBD

| 场景 | 应用 |
|---|---|
| 定位 | 「雇 AI 干什么」决定它是工具（替代执行）还是顾问（辅助决策） |
| Prompt 设计 | JTBD 可直接转成系统提示词里的人物、目标、约束 |
| 功能取舍 | 雇来「省时间」→ 优化速度；雇来「不出错」→ 优化可靠性与可验证性 |
| 定价 | 按「任务完成」定价（完成一次周报多少钱）比按 token 更容易被理解 |
| 竞品 | 同一个 Job 可以由完全不同的产品完成，这才是真竞品集合 |

## 8. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| Job 写得太抽象 | 「用户想提高效率」 | 加情境与可衡量结果 |
| Job 写得太具体 | 「点这个按钮导出」 | 那是方案，往上抽象一层 |
| 把功能当 Job | 「用 AI 写文案」是方案 | Job 是「让商品看起来值得买」 |
| 忽略触发事件 | 不知道用户什么时候会想起你 | 一定要问「第一次是什么时候」 |
| 只算推动力不算焦虑 | 以为痛点够强用户就会换 | 评估焦虑+惯性，常是留存杀手 |

## 9. Checklist

- [ ] 核心 Job 用「当…我想要…以便…」句式写清了
- [ ] 知道触发事件是什么
- [ ] 列出了推动力、拉力、焦虑、惯性
- [ ] 结果陈述可衡量（减少/增加 + 度量）
- [ ] 算过机会分，找到未满足的高分需求
