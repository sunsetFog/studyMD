# 17 · UI 基础与设计系统

## 1. 开发者需要懂的 UI 四件事

你不必成为设计师，但要能和设计师对话，并在没有设计师时做出**不难看**的界面：

```
① 对齐：所有元素沿少数几条对齐线排布
② 对比：重要信息要明显区别于次要信息
③ 重复：同类元素样式统一（颜色、间距、字号）
④ 亲密性：相关的东西靠近，不相关的分开
```

这四条（CRAP 原则）能解决 80% 的「看起来有点乱」。

## 2. 视觉基础参数

### 间距系统（8pt 栅格）

```
4 / 8 / 12 / 16 / 24 / 32 / 48 / 64
```

所有间距取这套值，界面自然整齐。**不要用 13px、15px 这种随手值**。

### 字号与层级

| 层级 | 桌面字号 | 移动字号 | 用途 |
|---|---|---|---|
| H1 | 32-40 | 24-28 | 页面主标题 |
| H2 | 24-28 | 20-22 | 区块标题 |
| H3 | 18-20 | 16-18 | 小标题 |
| Body | 14-16 | 14-16 | 正文（最小 14，正文别用 12） |
| Caption | 12-13 | 12 | 辅助说明 |
| 行高 | 字号的 1.5-1.75 倍 | | 中文正文建议 1.6-1.8 |

**层级数量控制在 4-5 级**，多了等于没有层级。

### 颜色

```
主色（Brand）：1 个，用于主按钮、关键强调（占 10%）
辅助色：1-2 个，用于成功/警告/危险状态
中性色：白/灰阶 5-7 级（背景、边框、正文、次要文字）
语义色：success 绿 / warning 橙 / error 红 / info 蓝
```

60-30-10 法则：60% 背景中性色、30% 次要内容色、10% 强调色。

**对比度要求（WCAG）**：正文文本对比度 ≥ 4.5:1，大字号 ≥ 3:1。

### 圆角与阴影

- 圆角：一套值（如 4/8/16），小控件小圆角，卡片大圆角
- 阴影：3-4 级（卡片、悬浮、弹窗、拖拽），不要每个元素都加阴影

## 4. 设计系统（Design System）是什么

> 设计系统 = **设计原则 + 组件库 + 设计 Token + 文档规范**，是设计与开发之间的共同语言。

```
Design Token（源头）
  ├── color.primary = #1677ff
  ├── space.md = 16
  ├── radius.md = 8
  └── font.body = 14/1.6
        ↓ 同步生成
  设计侧变量（Figma Variables）  +  开发侧变量（CSS Variables / Tailwind config）
        ↓
  组件库（Figma 组件 + React/Vue 组件）—— 两套一一对应
```

**关键：Token 是单一事实来源**，设计改 Token，代码自动跟随。

### 主流参考

| 系统 | 特点 |
|---|---|
| Material Design (Google) | 完整、规范细致 |
| Human Interface Guidelines (Apple) | iOS 生态标准 |
| Ant Design (蚂蚁) | 国内 B 端事实标准，React 组件齐全 |
| Fluent (Microsoft) | Windows 风格 |
| Tailwind + shadcn/ui | 现代 Web 轻量化方案，可定制性强 |

## 5. 落地建议（中小团队）

```
① 别自己从零造轮子：直接用 Ant Design / Element Plus / shadcn
② 做一层「业务组件」：把自家的高频组合封装（如「商品卡片」「用户选择器」）
③ 定义 Token：主色、间距、圆角、字号，写进 Tailwind config 或 CSS 变量
④ 建立一份「一页规范」：颜色/字号/间距/圆角/常用组件用法
⑤ 代码 Review 时检查：是否用了硬编码颜色/间距（应走 Token）
```

## 6. 空状态与占位（常被忽略）

| 状态 | 要点 |
|---|---|
| 空状态 | 说清「为什么是空的」+「下一步做什么」+ 一个操作按钮 |
| 加载中 | 骨架屏优于转圈（感知更快） |
| 无权限 | 说明原因 + 申请入口 |
| 无结果 | 「没找到 XX」+ 放宽条件建议 |
| 错误 | 原因 + 重试 + 兜底路径 |

> 空状态是**最好的引导时机**，别浪费它。

## 7. 响应式与适配

| 断点 | 设备 | 布局策略 |
|---|---|---|
| < 576 | 手机 | 单列，底部导航 |
| 576-768 | 大手机/竖屏平板 | 单列为主 |
| 768-992 | 平板 | 两列 |
| 992-1200 | 小屏桌面 | 侧边栏 + 内容 |
| > 1200 | 桌面 | 完整布局 + 最大宽度 1200-1440 |

**移动优先还是桌面优先**：取决于主场景，不要两边同时设计。

## 8. ★ AI 产品的 UI 组件补充

| 组件 | 说明 |
|---|---|
| 对话气泡 | 区分用户/AI，支持 Markdown、代码高亮、复制 |
| 流式文本容器 | 支持 token 逐步渲染，光标闪烁 |
| 停止/重新生成按钮 | 生成中的控制条 |
| 引用卡片 | RAG 的来源展示（可点击跳转原文） |
| 置信度标识 | 低置信度结果的可视化标记 |
| Token/用量显示 | 消耗透明化（成本/额度） |
| 反馈按钮 | 👍👎 + 原因选择（数据回收的关键入口） |
| Prompt 输入增强 | 模板选择、变量填充、示例推荐 |
| 结果对比视图 | 多版本结果并排比较 |

## 9. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 随手取色取值 | 页面 20 种灰色 | 用 Token，限制色阶数量 |
| 层级太多 | 6 种字号 + 5 种字重 | 控制在 4-5 级 |
| 硬编码样式 | 改主题要改 100 处 | 全部走变量 |
| 忽略空/错误态 | 上线后一片空白 | 每个列表都要有 Empty |
| 组件重复造 | 三个版本的按钮 | 统一组件库，缺了就补 |
| 移动端直接缩放 | 手机上按钮太小 | 触控目标 ≥ 44×44px |
| 对比度不足 | 浅灰字在白底 | 检查 4.5:1 |
| AI 结果无反馈入口 | 无法收集质量数据 | 每条结果加 👍👎 |

## 10. Checklist

- [ ] 有统一的间距/字号/颜色 Token
- [ ] 使用成熟组件库，不重复造轮子
- [ ] 每个列表/页面都有空态与错误态
- [ ] 触控目标 ≥ 44px，文本对比度 ≥ 4.5:1
- [ ] 样式无硬编码，走变量
- [ ] AI 产品有反馈入口与流式输出组件
