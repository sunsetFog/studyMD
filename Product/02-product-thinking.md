# 02 · 产品思维：四种决定上限的思考方式

## 1. 用户思维：从「我想做」到「用户要什么」

```
错误路径：我有个 AI 技术 → 能做什么 → 找场景硬套
正确路径：用户在某个场景中卡住 → 这个痛有多痛、多频繁 → 什么方案最优 → AI 是否是最优解
```

三个自检问题：

1. **谁**在什么**场景**下，遇到了什么**问题**？
2. 他现在**怎么解决**的？（现有替代方案 = 你真正的竞品）
3. 你的方案比现有方案好**多少倍**？（10 倍才算切换理由，1.2 倍没人换）

> ★ AI 应用最常见的失败姿势：**拿着锤子找钉子**。先问「这个问题非用 AI 不可吗」——如果规则清晰、结果要求 100% 准确，用代码写死比用模型靠谱得多。

## 2. 本质思维：连续追问 5 个 Why

```
用户：能不能给报表加个导出 Excel 的功能？
Why1 为什么要导出？        → 要给领导发周报
Why2 为什么要发周报？      → 领导想知道项目进展
Why3 为什么领导不能自己看？ → 他不会登系统/没权限
Why4 为什么不给领导开权限？ → 权限体系太复杂，懒得配
Why5 ……                    → 真正的解法可能是「自动生成周报并推送」，而不是导出按钮
```

方法：**永远区分「用户提的方案」和「用户的目标」**。用户是解决方案的专家，不是需求的专家（他们对目标诚实，对方案不专业）。

## 3. 系统思维：看到要素之间的关系

产品不是功能列表，而是一个系统：

```
输入（用户/内容/流量）
   → 处理（匹配/推荐/生成/审核）
       → 输出（结果/体验）
           → 反馈（数据/评价/留存）
               → 回到输入（正/负循环）
```

系统思维的三问：

1. 这个改动会触发什么**连锁反应**？（改了推荐算法，内容生态会怎么变）
2. 存在**负反馈**吗？（没有约束的系统必然劣化，如内容农场）
3. 瓶颈在**哪个环节**？（优化非瓶颈环节 = 白干，先找约束点）

> ★ AI 产品里的系统效应：降低生成成本 → 内容量暴涨 → 质量下降 → 用户信任流失 → 留存下跌。**降本不等于增值**。

## 4. ROI 思维：一切决策都是投入产出比

```
优先级 ≈ (影响面 × 影响深度 × 信心) / (工作量 × 风险)
```

决策时永远问：

- 这件事如果**不做**，会怎样？（很多需求答案是「也没怎样」）
- 有没有**成本更低**的验证方式？（假门测试、人工后台跑一遍）
- 这是**一次性**投入还是**持续**投入？（AI 功能常有持续推理成本）

### 四种价值类型

| 类型 | 说明 | 例子 |
|---|---|---|
| 增收 | 直接带来钱 | 新付费点、提价 |
| 提效 | 降低自己或用户的成本 | 自动化客服、AI 写周报 |
| 留存 | 提高用户留下来的概率 | 个性化、习惯养成 |
| 拉新 | 带来新用户 | 裂变、SEO、口碑 |

## 5. 概率思维：承认不确定

产品决策几乎都是**在不完全信息下下注**。正确姿势：

1. 明确写出你的**假设**（「假设：用户愿意为自动摘要付费」）
2. 设计**最小成本验证**这个假设的实验
3. 设定**止损线**（什么数据出现就放弃）

> ★ AI 产品尤其如此：模型能力会变、成本会降、竞品会出。别做「三年规划」，做「可期权化的小步快跑」。

## 6. 反直觉清单（值得背下来）

| 直觉 | 反直觉真相 |
|---|---|
| 功能越多越好 | 功能越多，主路径越模糊，转化越低 |
| 用户知道自己要什么 | 用户能准确描述问题，但提的方案常常是错的 |
| 做得好自然会有人用 | 分发能力往往比产品本身更决定生死 |
| 先做完整再上线 | 越晚上线，学到的越晚；先上 60 分版本 |
| AI 越聪明越好 | 在特定场景里，可靠 > 聪明；可控 > 强大 |
| 追求零缺陷 | 交付节奏 × 质量的最优解不是 100 分 |

## 7. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 功能堆砌 | 什么都想做，没有主线 | 定北极星指标，只做服务于它的 |
| 幸存者偏差 | 只看活跃用户的反馈 | 也要看流失用户为什么走 |
| 沉没成本 | 做了半年舍不得砍 | 按未来价值决策，不看已投入 |
| 数据万能 | 只看数据不问原因 | 数据 + 定性访谈双验证 |
| 抄袭竞品 | 竞品做了我们也做 | 问竞品的用户群和定位是否和你一致 |

## 8. Checklist

- [ ] 每个需求都能说清「谁 + 什么场景 + 什么问题」
- [ ] 能说出用户现在的替代方案，以及你比它好多少
- [ ] 决策时写了假设，并设计了最小验证方式
- [ ] 知道这个功能属于增收/提效/留存/拉新中的哪一类
- [ ] 对 AI 功能，先验证过「非 AI 方案」是否更优
