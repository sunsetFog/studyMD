# 14 · 交互设计定律：可以背下来的那些规律

## 1. 菲茨定律（Fitts's Law）

> 到达目标的时间 = 与**距离**成正比，与**目标大小**成反比。

```
T = a + b × log2(距离/宽度 + 1)
```

**应用**：
- 主要按钮要大、要放在手指/鼠标容易到达的位置（底部、右下角）
- 危险操作按钮要小一点、离常用区远一点（但不能太难找）
- 屏幕边缘是「无限大」的目标（macOS 菜单贴边）
- 移动端：核心操作放在拇指热区（屏幕下半部）

## 2. 希克定律（Hick's Law）

> 选择越多，决策时间越长（对数关系）。

```
T = b × log2(n + 1)
```

**应用**：
- 菜单项控制在 5-7 个以内，多了要分组
- 首屏 CTA 不超过 2 个
- 用「推荐默认项」减少决策（「推荐这个方案」）
- 表单选项过多时改用搜索

## 3. 米勒定律（Miller's Law）

> 人的短期记忆容量约 **7±2**（现代研究认为工作记忆更接近 4±1）。

**应用**：
- 导航项 ≤ 7 个
- 表单分组，每组 ≤ 5 项
- 数字分段展示（银行卡号 4 位一组）
- 列表分页，每页 ≤ 20 条
- 一次只让用户记住一件事

## 4. 峰终定律（Peak-End Rule）

> 人对体验的记忆由**峰值时刻**和**结束时刻**决定，而非平均值或总时长。

**应用**：
- 在关键节点制造「峰值」：第一次成功产出结果时的庆祝动效
- 结束时给正面收尾：完成页展示成果摘要，而不是干巴巴的「成功」
- 避免在流程末尾安排痛苦步骤（如强制填问卷）
- 补偿策略：如果中间有等待，结束时给惊喜

## 5. 泰思勒定律（复杂度守恒）

> 系统的复杂度总量守恒，只能转移，不能消除——要么系统承担，要么用户承担。

**应用**：
- 好的设计把复杂度转移到系统侧（智能默认值、自动填充）
- ★ AI 的价值正是**吸收复杂度**：让用户说人话，系统去理解
- 但不要过度自动化导致失控感（用户需要控制感）

## 6. 雅各布定律（Jakob's Law）

> 用户期望你的产品和其他产品**行为一致**。

**应用**：
- 遵循平台惯例：返回在左上、确认在右、红色表危险
- 别为了「创新」改变通用交互（除非有巨大收益）
- 创新的成本要由体验收益来买单

## 7. 多尔蒂门槛（Doherty Threshold）

> 响应时间 **< 400ms** 时用户保持专注并进入心流；超过则会分心。

**应用**：
- 交互反馈 < 100ms 感觉即时
- 页面切换 < 400ms
- 无法加速时用**感知优化**：骨架屏、乐观更新、流式输出

★ AI 应用的关键手法：**流式输出（streaming）** 能把 15s 的等待变成「1.5s 出首字 + 持续输出」，主观体验提升巨大，虽然总时间没变。

## 8. 蔡格尼克效应（Zeigarnik Effect）

> 人对**未完成**的任务记忆更深，有强烈的完成欲望。

**应用**：
- 进度条、任务清单、打卡连续天数
- 「资料完成度 70%」引导补全
- 草稿保存 + 提示「上次未完成」
- 慎用：别用它做焦虑营销

## 9. 序列位置效应（Serial Position Effect）

> 列表首尾项记忆最好，中间最差。

**应用**：
- 重要项放首尾
- 导航中「最重要的」放两端
- 定价页把推荐套餐放中间或高亮（打破效应）

## 10. 冯·雷斯托夫效应（Von Restorff Effect）

> 在一组相似元素中，**最不同的那个**最容易被记住。

**应用**：主 CTA 用不同颜色/大小突出；列表中高亮当前项。

## 11. 奥卡姆剃刀（简约原则）

> 如无必要，勿增实体。能去掉的元素就去掉。

**应用**：
- 每加一个元素问：去掉它会死吗？
- 装饰性元素（无信息量的插画、渐变）能删就删
- 功能不等于价值：功能数量与用户满意度不相关

## 12. 其他常用规律速查

| 定律 | 要点 | 应用 |
|---|---|---|
| 帕金森定律 | 工作会膨胀到填满所有时间 | 给任务设时间盒 |
| 帕累托法则 | 80% 结果来自 20% 原因 | 聚焦核心 20% 功能 |
| 曝光效应 | 越熟悉越有好感 | 保持一致，别频繁改版 |
| 损失厌恶 | 失去的痛苦 > 得到的快乐（约 2 倍） | 强调「你会错过什么」比「你会得到什么」更有效 |
| 锚定效应 | 第一印象影响后续判断 | 定价先展示高价方案 |
| 选择支持偏差 | 人会合理化自己的选择 | 购买后给正向确认 |

## 13. ★ AI 产品中的定律应用

| 定律 | AI 场景应用 |
|---|---|
| 多尔蒂门槛 | 流式输出 + 骨架屏，把 10s 等待变可感知的 1s |
| 峰终定律 | 生成完成时的结果呈现要精心（这是记忆峰值） |
| 蔡格尼克 | 「生成中」的进度感降低放弃率 |
| 泰思勒 | AI 吸收 prompt 复杂度，但保留高级模式给专家 |
| 希克定律 | 不要给用户 20 个模型/参数选择，默认一套 + 高级折叠 |
| 损失厌恶 | 展示「不用的话你每周要花 5 小时」比「用了能省 5 小时」有效 |

## 14. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 生搬定律 | 「米勒定律说 7 个」就硬凑 7 个 | 定律是启发不是教条，以实测为准 |
| 忽略场景 | 桌面端把按钮放底部 | 定律要结合设备与人因 |
| 只记定律不验证 | 自认为符合定律 | 用可用性测试验证 |
| 过度追求速度 | 为 <400ms 投入巨大成本 | 感知优化常更划算 |
| 峰值体验缺失 | 流程平淡无记忆点 | 设计 1-2 个关键时刻 |

## 15. Checklist

- [ ] 主操作按钮足够大且在易达区域
- [ ] 首屏选项 ≤ 7 个（希克+米勒）
- [ ] 等待 > 400ms 有反馈，> 3s 可取消
- [ ] 流程结束有正面收尾（峰终）
- [ ] AI 生成使用流式输出
- [ ] 复杂度尽量被系统吸收而非推给用户
