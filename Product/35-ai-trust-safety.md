# 35 · AI 的信任、安全与合规

## 1. 信任是 AI 产品的核心资产

```
信任建立慢（需要多次正确体验），崩塌快（一次严重错误）
  → 信任设计不是「加分项」，是产品的地基
```

信任的三个支柱：

| 支柱 | 含义 | 做法 |
|---|---|---|
| **能力可信** | 结果确实有用 | 质量基线、evals |
| **过程可信** | 知道它怎么得出的 | 可溯源、可解释、过程可见 |
| **意图可信** | 相信它不会害我 | 隐私承诺、安全边界、人工兜底 |

## 2. 幻觉（Hallucination）：认知与应对

### 什么是幻觉

模型生成**看似合理但虚假**的内容：编造事实、引用、数字、法条、链接。

### 为什么会有

- 模型是概率生成，目标是「合理延续」而非「陈述事实」
- 训练数据中没有/记错
- 问题超出能力范围，但模型倾向于「给答案」而不是「说不知道」
- RAG 检索到无关内容，模型硬凑

### 降低幻觉的手段

| 手段 | 说明 | 效果 |
|---|---|---|
| **RAG + 只依据资料回答** | 明确「只依据给定资料，资料没有就说不知道」 | ★★★★★ |
| **要求引用来源** | 每个结论标注出处，便于核验 | ★★★★ |
| **降低温度** | temperature 调低（0-0.3） | ★★★ |
| **结构化约束** | 输出字段限定在资料范围内 | ★★★ |
| **自校验** | 让模型二次检查「这个结论在资料中有依据吗」 | ★★★ |
| **拒答规则** | 明确「不确定的情况输出『无法确定』」 | ★★★★ |
| **多模型交叉验证** | 两个模型一致性检查 | ★★（成本高） |
| **人工审核** | 高风险场景必需 | ★★★★★ |

### 产品层面的幻觉管理

```
① 设定合理的质量目标（不是 0%，而是可接受的错误率 + 兜底）
② 提供核验工具（引用、原文对照、高亮来源）
③ 明确标识 AI 生成
④ 关键场景人工复核
⑤ 建立幻觉 case 收集与快速修复机制
⑥ 高风险领域（医疗/法律/金融）必须加免责声明与人工环节
```

## 3. 不确定性表达

```
设计的目标：让用户知道「什么时候该相信、什么时候该核对」
```

| 手法 | 说明 |
|---|---|
| 置信度标识 | 低置信度结果加标记（「AI 对此不太确定」） |
| 引用与来源 | 可点击查看原文 |
| 缺失声明 | 明确「资料中没有相关信息」 |
| 差异高亮 | 对改动/生成的内容高亮，便于核对 |
| 限制语气 | 避免绝对化表述（「一定是」「绝对」） |
| 建议核对 | 对关键字段提示「请核对」 |

## 4. 安全设计

### 输入侧风险

| 风险 | 说明 | 防御 |
|---|---|---|
| **Prompt Injection** | 用户输入里藏指令，劫持系统 prompt | 结构化分隔、转义、权限最小化、输出校验 |
| **越狱（Jailbreak）** | 诱导模型绕过安全规则 | 安全守卫模型、输出过滤、规则加固 |
| **敏感信息输入** | 用户输入了密码/身份证 | 输入检测与脱敏、提示风险 |
| **恶意内容** | 用于生成违规内容 | 内容安全审核（输入+输出双向） |
| **数据泄露** | 通过 prompt 套取系统提示/他人数据 | 不把敏感信息放 prompt；检索做权限过滤 |

### 输出侧风险

| 风险 | 防御 |
|---|---|
| 违规内容 | 输出内容安全过滤（关键词 + 模型审核） |
| 隐私泄露 | 输出检测（手机号、身份证、密钥） |
| 错误信息导致损失 | 免责声明 + 人工确认 + 可追溯 |
| 侵权内容 | 版权提示、来源标注 |
| 代码/指令注入 | 输出转义，不直接执行生成的代码 |

### 权限与数据

```
① 检索必须做权限过滤（用户只能检索到自己有权限的内容）★ 最易被忽略
② 多租户场景严格隔离
③ 日志脱敏（记录用于排查，但要脱敏）
④ 明确数据留存策略（存多久、谁能看）
⑤ 是否用于训练要明示，提供关闭选项
```

## 5. 合规要求（按地区）

| 地区 | 主要要求 |
|---|---|
| 中国 | 生成式 AI 服务需**备案/登记**；内容需符合相关规定；需标识 AI 生成内容（**标识办法**要求显式/隐式标识）；数据安全与个人信息保护（PIPL）；数据出境评估 |
| 欧盟 | GDPR（数据最小化、可删除、可解释）；AI Act（按风险分级，高风险系统义务更重） |
| 美国 | 行业自律为主；部分州有隐私法（CCPA）；特定行业（医疗 HIPAA、金融）有专门规定 |
| 通用 | 未成年人保护、版权、广告法（不得虚假宣传） |

### AI 产品合规 checklist

```
□ 生成内容有 AI 标识（显式提示 + 文件元数据隐式标识）
□ 服务备案/登记已完成（国内上线前）
□ 用户协议与隐私政策中说明 AI 使用、数据用途、是否用于训练
□ 内容安全审核机制（输入输出双向）
□ 用户数据留存与删除机制（可导出、可删除）
□ 检索内容的版权与授权
□ 高风险场景有人工复核与免责声明
□ 未成年人保护措施（如适用）
□ 日志与审计能力（可追溯某次输出的过程）
□ 跨境数据传输合规（如用了境外模型 API）★ 国内常见风险点
```

## 6. 透明度与用户告知

| 场景 | 应该做什么 |
|---|---|
| 首次使用 | 说明这是 AI、能做什么、可能出错 |
| 结果展示 | 标注「AI 生成」 |
| 数据使用 | 说明输入会被如何处理，是否用于改进 |
| 出错时 | 说明失败原因，不掩盖 |
| 能力变化 | 重大变更（换模型）告知用户（尤其是 B 端） |
| 内容分享 | 分享出去的内容带 AI 标识 |

## 7. 责任边界设计

```
原则：AI 不做的决定，人要做的决定
```

| 场景 | 责任设计 |
|---|---|
| 内容草稿 | AI 生成，人审核后发布（人对结果负责） |
| 建议类 | 明确是建议，非专业意见 |
| 自动化执行 | 提供撤销与人工介入通道 |
| 高风险决策 | 必须人工确认 + 记录日志 |
| 事故追溯 | 保留完整请求日志（输入、prompt 版本、模型、输出） |

**必备的用户救济机制**：

- 一键反馈（结果有问题）
- 人工客服/专家通道
- 申诉与纠错流程
- 明确的联系方式与响应承诺

## 8. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 假装 AI 是人 | 信任崩塌 + 合规风险 | 明确标识 |
| 过度承诺准确性 | 用户完全信任后出错 | 诚实表达不确定性 |
| RAG 不做权限过滤 | 用户看到别人的数据 | 检索必须带权限 |
| 无内容安全审核 | 生成违规内容 | 输入输出双向审核 |
| 无 AI 标识 | 违反标识要求 | 显式 + 隐式标识 |
| 日志不脱敏 | 隐私风险 | 脱敏 + 访问控制 |
| 数据出境未评估 | 合规风险 | 立项即评估 |
| 失败无兜底 | 用户体验断崖 | 降级方案 |
| 无人工通道 | 用户求助无门 | 提供人工入口 |
| 无追溯能力 | 出事查不到原因 | 全量请求日志 |

## 9. Checklist

- [ ] 有 RAG + 引用来源 + 拒答机制（降低幻觉）
- [ ] 低置信度有明确表达
- [ ] 输入侧防注入、输出侧内容安全过滤
- [ ] 检索做了权限过滤与租户隔离
- [ ] 日志脱敏、留存策略明确、可追溯
- [ ] 生成内容有 AI 标识（显式 + 元数据）
- [ ] 备案/登记、用户协议、隐私政策齐备
- [ ] 高风险场景有人工确认与免责声明
- [ ] 有用户反馈与人工救济通道
