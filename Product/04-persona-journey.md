# 04 · 用户画像与用户旅程地图

## 1. 用户画像（Persona）：让团队对「用户」达成共识

### 为什么需要

团队的默认状态是「每个人心里都有一个不同的用户」，讨论必然发散。画像的作用是**把抽象用户变成具体的人**，让决策有统一锚点。

### 一个可用的画像长什么样

```markdown
姓名：李敏，34 岁，二线城市电商运营主管
画像类型：主要画像（Primary）

【场景】每天要写 5-10 条商品文案，交给设计配图，第二天上线
【目标】按时上线、文案不违规、点击率别太差
【痛点】
  - 写文案最耗时，一天 2-3 小时
  - 没灵感，反复改
  - 平台规则经常变，怕违规
【现有方案】自己写 + 抄竞品 + 偶尔用 ChatGPT（嫌麻烦，要来回复制）
【能力】熟练用办公软件，会用手机 App，不会写代码/不会调 API
【态度】对 AI 好奇但怕出错被老板说，需要「能改、可控」
【付费】个人不付费，公司有小额工具预算（月 100 元以内可报销）
【关键决策因素】① 出稿快 ② 能改 ③ 不出错
```

### 画像要素清单

| 要素 | 说明 |
|---|---|
| 基本属性 | 年龄、职业、城市、技术水平 |
| 场景 | 在什么时间/地点/状态下使用 |
| 目标 | 想达成什么（任务目标 + 情感目标） |
| 痛点 | 当前最大的 3 个卡点 |
| 现有方案 | 现在怎么解决（真正的竞品） |
| 决策因素 | 影响他选择的关键项，排序 |
| 付费意愿 | 谁付钱、预算量级 |

### 画像的常见错误

| 错误 | 正确做法 |
|---|---|
| 编造画像（没调研） | 基于访谈数据，至少 5 人 |
| 画像太多（5+ 个） | 1 个主要 + 2 个次要足够 |
| 只写人口统计 | 重点是目标、痛点、决策因素 |
| 写完就不管 | 贴在墙上，评审时点名「这对李敏有用吗」 |

> 反例：「25-40 岁白领，追求品质生活」——这不是画像，这是废话。

## 2. 用户旅程地图（Journey Map）：看清全流程的体验起伏

### 结构

```
阶段：  认知 → 考虑 → 首次使用 → 常规使用 → 遇到问题 → 流失/留存
          ↓        ↓         ↓           ↓          ↓          ↓
行为：  他做了什么（可观察的动作）
触点：  接触到你的哪些界面/人员/通知
想法：  他在想什么（「这靠谱吗」）
情绪：  😀 😐 😞 画出情绪曲线
痛点：  哪里卡住了
机会点：你可以在哪里改善
```

### 绘制步骤

1. 选定一个**具体画像**和**具体任务**（如「李敏第一次用 AI 写商品文案」）
2. 列出 5-8 个阶段
3. 每个阶段填行为、触点、想法、情绪分（-2 到 +2）
4. 找出**情绪最低点** —— 那里就是最高优先级机会
5. 对每个机会点评估：影响 × 成本

### 关键洞察点

- **情绪谷底** = 流失点 = 最值得投入的地方
- **阶段间的断层**（如「注册完不知道干什么」）比单页体验问题更致命
- **MOT（关键时刻）**：第一次成功产出结果的那一刻，决定留存

## 3. 同理心地图（Empathy Map）

四象限快速对齐：

```
        【说】用户说过的话          【做】用户实际的行为
        （访谈原话）                （观察到的，与「说」矛盾处最有价值）

        【想】用户在意但没说的      【感受】他的情绪与焦虑
        （怕出错、怕被评价）        （担心、期待、 frustration）
```

## 4. 从画像到需求的转化

```
画像 → 目标 → 障碍 → 需求 → 功能 → 验收标准

例：
李敏（画像）
  → 目标：每天 5-10 条合规文案
  → 障碍：写得慢、没灵感、怕违规
  → 需求：快速生成可改的初稿 + 违规自检
  → 功能：批量生成、一键改写、违禁词检测
  → 验收：单条生成 ≤ 8s，违禁词召回率 ≥ 95%，可二次编辑
```

## 5. ★ AI 产品中的画像与旅程要点

| 要点 | 说明 |
|---|---|
| 增加「AI 素养」维度 | 有人会写 prompt，有人只想要一键按钮 |
| 增加「容错度」维度 | 医疗/法务场景容错极低，营销场景容错高 |
| 旅程要包含「验证环节」 | 用户拿到 AI 结果后一定会核对，要为核对设计 |
| 关注「第一次失望」 | AI 第一次给出烂结果，用户可能永久放弃 |
| 画像要写「他愿意把多少控制权交给 AI」 | 决定你做 Copilot 还是 Agent |

## 6. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 画像凭空编 | 团队拍脑袋写用户 | 至少基于 5 次访谈 |
| 画像不更新 | 一年前的画像还在用 | 每季度回顾一次 |
| 旅程只画 happy path | 没画失败路径 | 一定包含出错/放弃分支 |
| 情绪凭感觉打分 | 主观臆断 | 用访谈原话支撑每个低分点 |
| 画完不行动 | 地图挂墙上 | 每个机会点转成需求进池子 |

## 7. Checklist

- [ ] 画像基于真实访谈，有原话支撑
- [ ] 画像包含目标、痛点、现有方案、决策因素
- [ ] 旅程地图有情绪曲线且标出谷底
- [ ] 旅程包含失败/流失分支
- [ ] 每个机会点都对应到具体需求
