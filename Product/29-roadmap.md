# 29 · 产品路线图：做计划又不被计划绑架

## 1. 路线图是什么

> 路线图 = **一段时间内产品要达成的目标与关键动作的沟通工具**。

它回答三个问题：为什么做（战略）、做什么（主题/成果）、什么时候（大致时间）。

**路线图的读者**：团队（对齐方向）、管理层（资源决策）、客户/销售（预期管理）。

## 2. 反模式：路线图 = 功能清单 + 日期

| 功能清单式路线图 | 目标导向路线图 |
|---|---|
| Q1: 批量生成、模板库、导出 PDF | Q1: 让重度用户日均产出提升 2 倍 |
| 每个功能都有确定日期 | 按季度/月份标注大致时间窗 |
| 完成度按功能交付计 | 完成度按目标达成计 |
| 变化即「违约」 | 变化是学习的结果 |

**原因**：功能是手段，不是目的。功能清单式路线图会导致「为了打勾而做」，而不是「为了解决问题而做」。

## 3. Now-Next-Later 路线图（推荐）

```
Now（本季度，确定性高）：正在做，有明确范围与承诺
Next（下季度，中等确定）：已规划，范围可能调整
Later（更远，低确定）：方向性，只是意向
```

优点：诚实反映不确定性，避免虚假承诺。

| 层级 | 承诺度 | 粒度 | 更新时间 |
|---|---|---|---|
| Now | 高（90%） | 具体功能/故事 | 每迭代 |
| Next | 中（60%） | 主题/目标 | 每月 |
| Later | 低（30%） | 方向 | 每季度 |

## 4. 路线图的构成要素

```markdown
# 2026 Q4 路线图

## 目标（Objective）
让 AI 写作工具成为电商运营的日更工具

## 关键结果（KR）
- 周活跃用户中「每周使用 ≥ 3 天」的比例从 25% → 45%
- 人均周产出从 4 篇 → 10 篇
- 付费转化率 2% → 4%

## 主题与动作
| 主题 | 关键动作 | 时间窗 | 负责 | 状态 |
|---|---|---|---|---|
| 降低首次门槛 | 模板库 + 示例引导 | Now | PM-A | 进行中 |
| 提升产出质量 | 接入新模型 + prompt 优化 | Now | 开发-B | 进行中 |
| 批量与复用 | 批量生成、历史复用 | Next | PM-A | 规划中 |
| 团队协作 | 共享模板、成员管理 | Later | — | 待评估 |

## 不在本季度范围
- 多语言、API 开放、移动端 App
```

## 5. 制定路线图的步骤

```
① 回顾现状：数据 + 用户反馈 + 上季度复盘
② 明确战略重点（最多 3 个）
③ 收集候选（需求池 + 技术债 + 战略项）
④ 评估排序（RICE / 战略匹配 / 依赖）
⑤ 容量规划（团队能承载多少）
⑥ 排布时间窗（考虑依赖与季节因素）
⑦ 与利益相关方对齐
⑧ 公开并持续更新
```

## 6. 容量规划

```
可用产能 = 团队人数 × 迭代数 × 每人每迭代有效点数
扣除：假期、值班、技术支持、会议、技术债(15-20%)、探索(10%)

例：5 人 × 6 个双周迭代 × 8 点 = 240 点
  − 技术债 20% = 192
  − 探索 10% = 168
  → 新功能约 168 点（按历史 velocity 校准）
```

**永远只承诺 70-80% 的容量**，留给意外与学习。

## 7. 处理变更

```
变更来源及处理：
① 新数据/学习 → 调整（正常，主动沟通）
② 战略转向     → 重排（需要负责人决策）
③ 大客户要求   → 单独评估，不轻易改主线
④ 老板拍板     → 记录影响，让决策者知情
⑤ 技术 blocker → 重排或换方案
```

**原则**：变更可以，但**必须同时说明「因此不做什么」**。资源守恒。

## 8. 路线图的沟通

| 对象 | 关注 | 呈现方式 |
|---|---|---|
| 团队 | 为什么做、优先级 | 完整版 + 目标 |
| 管理层 | 战略匹配、资源、风险 | 目标 + 关键结果 + 风险 |
| 销售/客户 | 什么时候有什么能力 | 简版（功能 + 时间窗，附「可能调整」说明） |
| 外部公开 | 方向信心 | 高度概括，避免具体日期 |

> 给客户的路线图要**慎之又慎**：一旦公开就是承诺。加免责说明。

## 9. ★ AI 产品的路线图特殊性

| 特殊性 | 应对 |
|---|---|
| **模型能力快速演进** | 路线图周期缩短到季度；预留「能力升级」缓冲位 |
| **外部依赖强** | 依赖模型厂商（价格、能力、可用性），要有备选方案与风险登记 |
| **效果不确定** | 用「目标 + 假设」而非「功能」描述，如「尝试将长文质量提升到 X，若不成转 Y」 |
| **成本可能突变** | 设成本阈值触发的预案（如涨价/降级/换模型） |
| **技术窗口** | 新模型发布 = 机会窗口，路线图要能快速插入 |
| **合规不确定** | 预留合规调整时间 |

**建议**：AI 产品路线图用「季度目标 + 月度重排」，不做半年以上的细节规划。

## 10. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 路线图变成承诺 | 每个日期都必须兑现 | 用 Now/Next/Later + 时间窗 |
| 只有功能没有目标 | 做完不知道有没有用 | 每项对应一个目标/KR |
| 排得太满 | 没有缓冲 | 只承诺 70-80% 容量 |
| 不与团队对齐 | 团队不知道为什么做 | 路线图宣讲 + 每季度回顾 |
| 做了不看 | 墙上贴着没人管 | 每月更新，纳入例会 |
| 频繁大改 | 团队疲惫 | 大的重排每季度一次 |
| 忽略技术债 | 越做越慢 | 路线图中显式列出技术债主题 |
| AI 规划太远 | 计划赶不上模型变化 | 缩短周期，保留弹性 |

## 11. Checklist

- [ ] 用目标 + 关键结果，而非纯功能清单
- [ ] 分 Now/Next/Later 三档，承诺度递减
- [ ] 每项对应明确的 KR（可衡量）
- [ ] 容量只承诺 70-80%，含技术债与探索配额
- [ ] 明确写了「不做什么」
- [ ] 每月更新，每季度与全员对齐
- [ ] AI 产品：周期 ≤ 季度，有外部依赖风险登记
