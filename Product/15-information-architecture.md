# 15 · 信息架构：让内容能被找到

## 1. 什么是信息架构（IA）

> IA = 如何**组织、标记、导航、检索**信息，让用户能找到并理解。

IA 三要素：**组织系统**（怎么分类）+ **标签系统**（叫什么）+ **导航系统**（怎么走）。

## 2. 组织方式

| 方式 | 适用 | 例子 |
|---|---|---|
| 按字母/时间 | 已知目标项的精确查找 | 通讯录、日志 |
| 按主题/类别 | 浏览型查找 | 商品分类 |
| 按任务 | 用户带着任务来 | 「我要开票」 |
| 按用户角色 | 不同角色用不同部分 | 买家端/卖家端 |
| 隐喻 | 借用熟悉概念 | 桌面、购物车 |

**判断标准**：用户来找东西时，他脑子里用的是哪种分类？用他的语言，不是你的内部结构。

## 3. 卡片分类法（Card Sorting）

验证 IA 的实测方法：

```
① 把内容/功能写成卡片（30-60 张）
② 让用户按自己的理解分组，并给每组命名
③ 统计分组结果（可用工具：OptimalSort、xSort）
④ 高频归到一起的 = 用户心智中的同类
⑤ 用户命名的词 = 应该采用的标签
```

| 类型 | 说明 |
|---|---|
| 开放式 | 用户自己分组并命名（探索阶段用） |
| 封闭式 | 给定分类，用户把卡片放进去（验证阶段用） |
| 反向卡片分类 | 给出词条，让用户去树上找（测试查找路径） |

## 4. 导航设计

### 导航类型

| 类型 | 作用 | 位置 |
|---|---|---|
| 全局导航 | 主功能区切换 | 顶部/侧边/底部 |
| 局部导航 | 当前区域内的子页面 | 侧边/标签页 |
| 辅助导航 | 帮助、设置、关于 | 底部/顶部右 |
| 上下文导航 | 相关文章、下一步 | 内容区 |
| 面包屑 | 显示位置与返回路径 | 顶部 |
| 页脚导航 | 全站地图 | 底部 |

### 导航原则

```
① 当前位置要清楚（高亮当前项 + 面包屑）
② 层级不超过 3 层（首页 → 列表 → 详情）
③ 全局导航项 ≤ 7 个（米勒定律）
④ 每个页面都要能回到上一级
⑤ 移动端优先底部导航（拇指热区）
⑥ 搜索是复杂 IA 的保险丝（内容 > 20 项就该有搜索）
```

### 「三次点击原则」（及其真相）

> 传言：任何内容应在 3 次点击内到达。
> 真相：**点击数不重要，每次点击是否清晰、是否让用户更接近目标才重要**。用户能准确判断下一步时，7 次点击也不觉得累。

## 5. 标签系统

| 原则 | 反例 | 正例 |
|---|---|---|
| 用用户语言 | 「内容管理」 | 「我的文章」 |
| 具体而非抽象 | 「服务」 | 「发票 / 售后 / 咨询」 |
| 简洁一致 | 同功能叫「我的」「个人中心」「账户」 | 全站统一叫「我的」 |
| 宽度合适 | 「删除」（太重）/「OK」（太轻） | 「删除草稿」 |

**标签测试方法**：给一个新用户看标签，问「你觉得点进去会看到什么」，答对率 < 80% 就要改。

## 6. 搜索设计

| 要素 | 说明 |
|---|---|
| 入口显眼 | 内容多时搜索框放在顶部 |
| 支持模糊 | 错别字、拼音、同义词 |
| 自动补全 | 输入时给建议 |
| 结果排序 | 相关性 + 时效 + 热度 |
| 无结果页 | 给建议而非空白（「你是不是要找…」） |
| 筛选器 | 结果 > 20 条时提供 |

★ AI 时代：**语义搜索（向量检索）大幅降低对 IA 的依赖**。但仍需保留结构化导航，因为用户有时候就是要「浏览」而非「搜索」。

## 7. IA 的产出物

```
① 站点地图（Sitemap）：页面层级树
② 用户流程图：任务路径（含分支与异常）
③ 页面结构图（Wireframe 的骨架）
④ 内容清单：每页有什么内容/数据
⑤ 元数据规范：命名、标签、分类字典
```

## 8. ★ AI 产品的 IA 特殊考虑

| 点 | 说明 |
|---|---|
| **对话即入口** | 对话界面是一种「搜索型 IA」，用户用自然语言找功能；但纯对话入口会让功能不可发现，需配合可见的功能入口 |
| **历史与上下文** | AI 产品的会话历史是核心内容，要有良好的组织（按项目/时间/标签） |
| **Prompt/模板库** | 模板是可浏览的 IA，也可被搜索；分类要按场景而非技术 |
| **结果与来源并列** | RAG 产品的信息架构要同时承载「答案」和「证据」 |
| **Agent 任务列表** | Agent 类产品的「任务/运行记录」需要清晰的状态与层级 |
| **不要只做对话框** | 纯对话框产品的功能可发现性极差，配合侧边栏/快捷入口 |

## 9. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 按内部结构分类 | 按部门/技术模块分导航 | 按用户心智做卡片分类 |
| 层级过深 | 5 层才能到内容 | 压到 3 层，或用搜索 |
| 术语不一致 | 同一个东西三个名字 | 建立术语表并全站统一 |
| 全靠导航 | 内容爆炸后找不到 | 加搜索与筛选 |
| 无结果页空白 | 用户死路一条 | 给相关推荐 |
| 只做 IA 不做流程 | 能找到但走不通 | IA 与流程一起设计 |
| 纯对话无入口 | 用户不知道能做什么 | 提供示例/模板/功能可见性 |

## 10. Checklist

- [ ] 分类方式来自卡片分类法，而非拍脑袋
- [ ] 层级 ≤ 3 层
- [ ] 全局导航 ≤ 7 项，当前位置清晰
- [ ] 内容 > 20 项有搜索
- [ ] 术语全站统一，有术语表
- [ ] 无结果页有兜底推荐
