# 33 · AI 交互范式：怎么设计人机协作

## 1. 六种主流 AI 交互范式

| 范式 | 形态 | 用户控制度 | 典型 |
|---|---|---|---|
| **对话（Chat）** | 来回对话 | 中 | ChatGPT |
| **Copilot（副驾）** | 在用户工作流中辅助 | 高 | GitHub Copilot |
| **Agent（智能体）** | 给定目标自主执行 | 低 | AutoGPT 类 |
| **嵌入式增强** | 现有功能里加 AI 按钮 | 高 | Notion AI、飞书智能助手 |
| **生成式创作** | 输入 → 产出作品 | 中 | 文生图、AI 写作 |
| **后台自动化** | 无感运行 | 无 | 智能分类、审核、推荐 |

**选择原则**：看用户的**容错度与控制需求**。

```
容错高 + 想省事 → Agent / 自动生成
容错低 + 要掌控 → Copilot / 嵌入式增强
探索性、不确定需求 → 对话
```

## 2. 各范式的设计要点

### 对话式

```
要点：
① 冷启动引导（空输入框是最难的）：示例问题、快捷入口、模板
② 多轮上下文可见：展示历史，支持回溯与编辑
③ 支持中断与重新生成
④ 结果可复制、可编辑、可继续追问
⑤ 明确能力边界（开场说明「我能做什么」）
陷阱：
  - 纯对话入口导致功能不可发现（配合侧边栏/模板）
  - 上下文无限增长 → 成本与质量下降（要摘要/截断策略）
```

### Copilot 式（推荐给大多数工具型产品）

```
要点：
① 嵌入用户已有的工作流，不另起炉灶
② 触发点明确（选中文本 → 出现 AI 菜单）
③ 结果以「建议」形式呈现，用户可一键接受/拒绝/修改
④ 不打断用户当前操作
⑤ 快捷键与浮层，避免弹窗
优势：用户保留控制权，容错高，接受度好
```

### Agent 式

```
要点：
① 任务开始前确认计划（让用户看到它要做什么）
② 过程透明（展示每一步与中间结果）
③ 可随时干预/叫停
④ 重要动作（花钱、发消息、删数据）必须确认
⑤ 结束后给完整总结与可回溯的操作记录
陷阱：
  - 完全黑盒执行 → 用户不敢用
  - 失控循环 → 必须有步数/成本上限
  - 失败无交代 → 必须说明卡在哪、为什么
```

### 生成式创作

```
要点：
① 输入引导（参数/参考/风格选择）
② 一次给多个候选（3-4 个），支持挑选与再生成
③ 结果可编辑、可局部重生成
④ 版本管理（保留历史版本可回溯）
⑤ 导出与分享
```

### 后台自动化

```
要点：
① 用户要能知道「这是 AI 做的」
② 提供纠正入口（错了能改，且会学习）
③ 低置信度时转人工
④ 可关闭
```

## 3. AI UX 的十条原则

```
① 设定正确预期：明确「AI 生成，可能有误」
② 降低冷启动成本：给示例、模板、默认值
③ 过程可见：流式输出、中间步骤、进度
④ 可控：可停止、可重试、可修改参数
⑤ 结果可编辑：AI 输出必须能改
⑥ 可溯源：给引用来源，让用户能验证
⑦ 不确定性表达：低置信度明确提示
⑧ 优雅降级：失败给兜底，不留空白
⑨ 收集反馈：👍👎 是数据飞轮入口
⑩ 保留人的最终决定权：关键决策必须人确认
```

## 4. 冷启动设计（最容易被忽略）

空输入框是 AI 产品最大的流失点——用户不知道该说什么、不知道你能干什么。

| 手法 | 说明 |
|---|---|
| 示例问题 | 3-5 个真实可用的示例（点击即填） |
| 场景模板 | 按场景分类的模板库 |
| 输入引导 | 占位符里给具体提示（「描述你的商品，如：夏季纯棉短袖…」） |
| 变量填充 | 结构化表单代替自由输入（对 B 端尤其有效） |
| 上传入口 | 支持上传文档/图片作为上下文 |
| 最近使用 | 展示历史会话/草稿 |
| 智能推荐 | 根据用户身份推荐场景 |

> 对非技术用户，**结构化输入（表单）往往比自由对话更好用**。别迷信对话框。

## 5. 等待体验设计

AI 响应慢（数秒到数十秒），等待体验决定成败。

| 手法 | 说明 |
|---|---|
| **流式输出** | 首 token 1-2s 内出现，边生成边显示（★ 最重要） |
| 中间态提示 | 「正在检索…」→「正在生成…」（让用户知道在干活） |
| 骨架屏 | 结果区占位，避免布局跳动 |
| 进度提示 | 多步任务显示「第 2/4 步」 |
| 可取消 | 随时停止 |
| 后台化 | 长任务允许离开，完成后通知 |
| 预估时间 | 「大约需要 30 秒」降低焦虑 |

> 关键认知：**感知性能 > 实际性能**。同样的 15 秒，流式输出的主观感受远优于转圈 15 秒后一次性出现。

## 6. 结果呈现设计

```
① 结构化：能用卡片/表格/列表，就别用大段文字
② 可操作：结果旁直接放「复制/应用/再生成/编辑」按钮
③ 可溯源：引用来源可点击跳转（RAG 必备）
④ 可对比：多候选时并排展示
⑤ 可折叠：长内容默认折叠，保留摘要
⑥ 可编辑：就地编辑，不必复制出去改
⑦ 展示元信息：用了什么模型、耗时、消耗额度（成本透明）
⑧ 反馈入口：👍👎 + 可选原因
```

## 7. 错误处理与降级

| 场景 | 处理 |
|---|---|
| 模型超时 | 提示 + 重试 + 保留输入；可后台继续 |
| 模型报错 | 友好文案 + 错误码（供反馈）+ 重试 |
| 输出格式不合法 | 自动重试一次 → 修复（如 JSON 修复）→ 兜底模板 |
| 触发安全策略 | 明确说明「内容可能不符合规范」+ 修改建议，不要只说「失败」 |
| 额度用尽 | 提示 + 升级引导 + 保留输入 |
| 服务不可用 | 降级到小模型/缓存/静态兜底 + 状态告知 |
| 结果质量差 | 提供「重新生成」「换一个模型」「人工协助」 |

> 原则：**绝不出现「生成失败，请重试」这种没有任何信息量的提示**。

## 8. Human-in-the-loop 设计

```
AI 建议 → 用户确认/修改 → 执行 → 反馈回收 → 改进
```

| 环节 | 设计要点 |
|---|---|
| 确认点 | 在哪里打断用户？（重要动作前，而非每一步都问） |
| 确认成本 | 一键接受 vs 需要审阅 → 按风险分级 |
| 修改体验 | 用户改了什么要能记录（这是最好的训练数据） |
| 反馈闭环 | 用户修改/拒绝 → 记入 bad case 库 |
| 自动化演进 | 高置信度且用户从不修改的部分，逐步减少确认 |

**分级控制**：

```
低风险（草稿、建议）→ 直接给结果，可一键撤销
中风险（发送邮件、发布内容）→ 展示预览 + 确认
高风险（付款、删除、对外承诺）→ 强确认 + 二次验证 + 可追溯日志
```

## 9. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 纯对话框无引导 | 用户不知道能干嘛 | 示例/模板/功能入口 |
| 一次性返回 | 等待焦虑、放弃率高 | 流式输出 |
| 结果不可编辑 | 用户不敢用 | 就地编辑 |
| 无引用来源 | 不敢相信 | RAG 展示来源 |
| 失败提示无信息 | 用户只能猜 | 说清原因 + 下一步 |
| 无反馈入口 | 无法改进入 | 每条结果 👍👎 |
| Agent 黑盒 | 不敢授权 | 展示计划与步骤 |
| 过度自动化 | 用户失控感 | 关键节点人工确认 |
| AI 伪装成人 | 信任崩塌 | 明确标识 AI |
| 上下文无限增长 | 成本与质量劣化 | 摘要/截断/重置 |

## 10. Checklist

- [ ] 选对了交互范式（按容错度与控制需求）
- [ ] 冷启动有示例/模板/引导
- [ ] 使用流式输出，首 token < 2s
- [ ] 结果可编辑、可复制、可再生成
- [ ] RAG 场景展示可点击的引用来源
- [ ] 所有失败场景有明确文案与下一步
- [ ] 每条结果有反馈入口
- [ ] 关键动作有人工确认与可追溯日志
- [ ] 低置信度结果有明确标识
