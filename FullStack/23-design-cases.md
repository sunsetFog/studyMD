# 23 - 经典设计题拆解

## 1. 秒杀系统（必考⭐⭐）

### 架构分层削流

```
前端：按钮防重 + 答题/验证码打散请求 + 静态页 CDN
网关：限流（令牌桶，如 1w/s）+ 黑名单
应用：Redis 预扣库存（原子）→ 成功者进 MQ
DB：MQ 消费落单（幂等）+ 乐观锁兜底
```

```java
// Redis 预扣（Lua 保证判断+扣减原子）
String lua = """
  local s = redis.call('GET', KEYS[1]);
  if tonumber(s) <= 0 then return 0 end;
  redis.call('DECR', KEYS[1]); return 1
  """;
// 扣成功 → 发 MQ → 消费创建订单 → 超时未支付回补库存（延迟消息）
```

### 必答细节

- 超卖：Redis 原子预扣 + DB `WHERE stock > 0` 双保险
- 少卖（回补失败）：对账任务兜底
- 黄牛：限流 + 设备指纹 + 实名/答题
- 订单超时关闭：延迟消息/Redis 过期监听/定时扫表（选延迟消息）

## 2. 短链接系统（⭐）

```
生成：发号器（自增/雪花）→ Base62 编码（6 位≈570 亿）→ 存映射
跳转：302（可统计）+ Location；缓存热点映射
去重：长链 hash + 布隆过滤器（可选）
```

- 追问：302 vs 301（301 浏览器缓存无法统计）；高 QPS 读 → 缓存+布隆防穿透

## 3. Feed 流（⭐）

| 模式 | 原理 | 适用 |
|---|---|---|
| 推模式 | 发布时写进所有粉丝收件箱 | 粉丝少 |
| 拉模式 | 读取时实时聚合关注者内容 | 大 V 多 |
| **推拉结合** | 大 V 拉、普通人推，读写折中 | 主流 |

- 存储：Redis ZSet（score=时间戳）存收件箱，分页用游标（lastTime）
- 关注关系独立存储 + 缓存

## 4. 支付系统要点（⭐）

- 对账：每日 T+1 与渠道账单核对（差弢单处理流程）
- 异步通知处理：验签 → 幂等（订单状态机）→ 返回 success；未收到通知走主动查询补偿
- 状态机：待支付→支付中→成功/失败，非法迁移拒绝
- 金额：DECIMAL 分为单位存储（int 分）

## 5. 排行榜（⭐）

```java
zincrBy("rank:day:20261106", score, userId);          // 实时更新
zRevrangeWithScores("rank:day:20261106", 0, 9);       // Top10
zRevrank("rank:day:20261106", userId) + 1;            // 我的排名
```

- 天级榜：key 带日期，过期自动清理
- 千万用户：只缓存头部 + 分段排名（预估区间）或 ClickHouse

## 6. 其他高频设计题速答

| 题目 | 核心方案 |
|---|---|
| 点赞 | Redis Set/ZSet 计数 + 异步落库 + 去重 |
| 分布式限流 | Redis+Lua 滑动窗口 |
| 延迟任务 | 延迟消息 > ZSet 轮询 > 时间轮 |
| 抢红包 | 发红包时拆分金额预分配（二倍均值法）+ 领取原子 CAS |
| URL 鉴权下载 | 预签名短时效 URL |

## 答题模板

```
1. 先问清量级与约束（QPS/数据量/一致性）——展示工程判断力
2. 画分层架构：入口→服务→存储
3. 每层给 2 个方案说 trade-off（面试官考察的是权衡能力）
4. 主动提故障场景：超卖/重复/宕机怎么办
```
