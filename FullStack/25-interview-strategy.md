# 25 - 面试实战策略

## 1. 答题方法论（通用四步）

```
1. 结论先行（10 秒内给出答案方向）
2. 原理展开（2~3 层深度，看面试官反应决定是否再深挖）
3. 结合实践（项目中的真实案例、踩过的坑）
4. 主动收尾或反问（"这块我还可以展开讲 XX"）
```

- 不会的题：说思路 + 承认边界——"这块我用过 X，Y 没实践过，但根据原理我猜测…"，**诚实远好于硬编**
- 开放题：先反问约束（量级/场景），再分层作答

## 2. 项目介绍模板（STAR 变体）

```
背景（1 句）：业务是什么、规模多少（QPS/数据量，要有数字）
难点（2 句）：最难的 1~2 个技术问题
方案（3 句）：怎么做的、为什么这么选（对比过什么方案）
结果（1 句）：量化收益（RT 下降 60%、支撑 X 万 QPS）
```

- 项目深挖必备：自己项目里每个技术点都要能画架构图、说清"为什么不用别的方案"
- 高频追问预演：事务失效怎么发现的、缓存一致性怎么保证的、灰度怎么做的——提前准备 3 个"踩坑故事"

## 3. 全栈岗的高频组合拳

| 追问链 | 准备 |
|---|---|
| 登录全流程：前端→JWT→后端校验→Redis 黑名单 | 19 |
| 下单流程：前端防重→接口幂等→事务→MQ→库存 | 17/18/23 |
| 首屏白屏排查：前端性能→网络→后端慢 SQL | 04/10/15 |
| 一个接口从 0 到上线：设计→文档→实现→测试→部署→监控 | 14/20/24 |

## 4. 手写题清单（全栈高频）

前端：防抖节流、Promise.all、并发池、深拷贝、事件循环判断输出
后端：单例（DCL/Holder）、生产者消费者、两个线程交替打印、LRU
SQL：分组 Top-N、连续登录天数、窗口函数

## 5. 反问环节（信号价值）

好问题：团队技术栈与挑战 / 需求到上线的流程 / 代码评审文化 / 新人前三个月预期
坏问题：加班多吗（一面别问）/ 纯薪资（留到 HR）

## 6. 复习节奏建议

```
T-14 天：本系列通读 + 每篇 Checklist 自测
T-7 天：项目故事打磨（3 个技术深挖 + 1 个协作冲突）
T-3 天：手写题过一遍 + 高频追问链模拟
T-1 天：简历上每个技术点一句话总结，不新增内容
```
