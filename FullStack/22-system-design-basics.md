# 22 - 高并发系统设计方法论

## 1. 设计万能框架（答题顺序背下来）

```
1. 明确指标：QPS 目标 / 数据量 / 延迟要求 / 一致性要求
2. 单机瓶颈推演：应用 → DB → 网络
3. 扩展三板斧：缓存（读）→ 异步（写）→ 水平扩展（一切）
4. 兜底：限流 → 熔断 → 降级 → 隔离
```

- 演进路径：单机 → 主从读写分离 → 缓存 → 分库分表 → 微服务/异步化
- 核心思想：**不重复造轮子，先测量再优化**；没有指标的优化都是空谈

## 2. 读多写少：多级缓存（必考⭐）

```
本地缓存（Caffeine，µs）→ Redis（ms）→ DB
一致性：Redis 删缓存（Cache Aside）+ 本地缓存短 TTL + 变更广播（Redis Pub/Sub 或 MQ 通知刷新本地）
```

- 场景：配置、字典、热点商品
- 穿透/击穿/雪崩三问（见 16）在此层必答

## 3. 写多读少/削峰：异步化（必考⭐）

```
用户请求 → 校验 + 落核心数据（同步事务）→ 发 MQ → 立即返回
下游：扣库存/积分/通知/统计 异步消费
```

- 前提：用户不需要立即看到结果（下单成功≠发货完成）
- 必配：消息可靠性三环节 + 消费幂等（见 17）

## 4. 数据层扩展

### 读写分离
- 主写从读，注意主从延迟的写后读问题（关键读走主库/GTID 等待）

### 分库分表
- 垂直（按业务）→ 水平（按数据）；sharding key 选 80% 查询能命中的列
- 带来：分布式 ID、跨片查询（异构索引/ES）、跨片事务 → 见 15/18

### 冷热分离
- 历史数据归档表/归档库，主表保持精瘦

## 5. 池化与资源预算

| 资源 | 配置原则 |
|---|---|
| DB 连接池 | 远小于 max_connections，cores*2+磁盘数经验 |
| 线程池 | 区分 CPU/IO 任务池，禁止 Executors 快捷方法 |
| HTTP 客户端 | 必须配超时+连接池（OkHttp/RestTemplate 默认坑） |
| JVM | 容器感知 -XX:MaxRAMPercentage |

**全链路超时预算**：网关 3s > 服务 2s > 下游 1s > DB 500ms，超时必须层层配置。

## 6. 扩展性设计原则

- 无状态服务（会话外置）→ 随意扩容
- 消息驱动削峰 → 拒绝洪峰直击 DB
- 幂等设计 → 重试/重复消息安全
- 灰度发布 → 新版本小流量验证

## 常见追问

1. QPS 100 万怎么扛？——先拆读（CDN→缓存 90%+）再拆写（异步+分片），单点不存在银弹
2. 双 11 零点高峰预案？——预热（缓存预热/扩容）、限流预案、降级开关清单、值班 oncall
3. 一致性级别怎么选？——交易强一致（锁/事务），互动最终一致（MQ），展示弱一致（缓存）
