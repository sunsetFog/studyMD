# 38 - 收发货地址管理

## 1. 需求背景与目标

- **背景**：地址是履约根基；行政区划数据错误、隐私保护（隐私面单）是两大痛点。
- **目标**：地址可达性校验准确率 ≥99%；隐私面单覆盖率 ≥90%（合作承运商）。
- **非目标**：不做地图选点精确到门牌（P2，行政区划 + 详细地址即可）。

## 2. 用户故事

- 作为买家，我想要管理多个收货地址并设默认，以便不同场景收货。
- 作为买家，我希望面单上不显示完整手机号，以便隐私安全。
- 作为商家，我想要管理发货地址与退货地址，以便分仓发货。

## 3. 数据模型（P0）

| 字段 | 规则 |
|---|---|
| 行政区划 | 省/市/区 三级级联（标准行政区划库，季度更新）+ 可选街道四级 |
| 详细地址 | ≤120 字符；禁纯表情/纯数字（格式校验） |
| 收件人 | 姓名 ≤20 字 |
| 手机号 | 格式校验；一个地址一个手机号 |
| 标签 | 家/公司/学校（自定义 ≤6 字） |
| 默认 | 全局唯一默认收货地址；删除默认地址时自动转移最近使用 |

## 4. 功能需求

| 条目 | 需求 | 优先级 |
|---|---|---|
| 38-4-1 | 地址 CRUD：增删改查 + 设默认；上限 20 条 | P0 |
| 38-4-2 | 行政区划服务：三级级联接口（下单页/地址页共用）；版本化管理（区划变更有迁移方案） | P0 |
| 38-4-3 | 可达性校验：偏远地区/不可达区域标识（37 承运商服务范围数据），下单时提示「该地区可能延迟/无法配送」 | P0 |
| 38-4-4 | 智能解析：粘贴文本自动识别省市区+详细（准确率 ≥90%） | P1 |
| 38-4-5 | 隐私面单：面单手机号脱敏（虚拟号中转 P1）；C 端地址展示脱敏（列表/订单页部分遮挡） | P0 |
| 38-4-6 | 商家地址簿：发货地址（多仓）+ 退货地址（多退回仓），按订单选择 | P0 |
| 38-4-7 | 地址删除保护：进行中订单（PAID/SHIPPED）引用的地址不可物理删除（逻辑删，履约仍可读） | P0 |

## 5. 流程

```
新增地址 → 区划选择/粘贴解析 → 校验（格式/可达性/手机号）
 → 保存 → 下单引用（14 校验通过才可提交）
 → 面单生成 → 隐私脱敏处理（37）
 → 删除 → 进行中订单引用校验 → 逻辑删
```

## 6. 异常与边界

| 场景 | 处理 |
|---|---|
| 行政区划变更（区划调整） | 区划库版本迁移任务：老地址 ID 映射到新区划；不可映射的标记待更新 |
| 下单后地址区域变不可达 | 已下单订单照常履约；提示承运商时效延长 |
| 智能解析歧义（同名区） | 列候选让用户确认 |
| 越权访问他人地址 | 归属校验（03/49），越权记风控日志 |
| 地址与运费模板不匹配（区域外） | 14 下单阻断并提示（37 模板计算联动） |

## 7. 数据与埋点

- 事件：`address_add/edit/delete/set_default` / `address_parse(auto)` / `unreachable_alert`
- 指标：地址保存成功率、智能解析使用率与准确率、不可达提示触发率、隐私面单覆盖率。

## 8. 依赖与接口

- 依赖：37 可达性/面单、14 下单校验。
- 提供：`地址 CRUD`、`行政区划查询`、`可达性校验`（全交易链路共用）。
