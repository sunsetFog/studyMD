# 01 - 产品全景：定位、业务架构与核心链路

## 1. 产品定位

**仿淘宝商城（ShoppingMall）**：一个多商家入驻的综合电商平台（Marketplace 模式）。

- 平台不持有库存，撮合「买家 × 商家」交易，收取技术服务费/佣金与广告费。
- 三方角色：**买家（C 端）**、**商家（B 端）**、**平台（运营/客服/风控）**。
- 商业模式：佣金（GMV 抽成）+ 广告（竞价排名/展示）+ 增值服务（会员、营销工具）。

## 2. 业务架构（分层）

```
┌─────────────────────────────────────────────────────┐
│ 表现层：App（iOS/Android）/ H5 / 小程序 / 商家后台 / 运营后台 │
├─────────────────────────────────────────────────────┤
│ 前台业务层                                              │
│  内容触达：搜索/推荐/直播/内容流/店铺                      │
│  交易链路：购物车→下单→支付→订单→履约                     │
│  逆向链路：退款/退货/换货/仲裁                           │
│  营销层：优惠券/秒杀/拼团/满减/跨店活动                    │
├─────────────────────────────────────────────────────┤
│ 业务中台层                                              │
│  商品中心（SPU/SKU/类目属性）│ 库存中心 │ 价格优惠引擎      │
│  订单中心（状态机）│ 支付网关 │ 结算中心 │ 用户中心/会员    │
│  物流对接 │ 消息中心 │ 风控引擎 │ 审核引擎                │
├─────────────────────────────────────────────────────┤
│ 基础设施：网关/缓存/消息队列/搜索索引/数据仓库/埋点          │
└─────────────────────────────────────────────────────┘
```

## 3. 核心用户旅程（买家正向链路）

```
触达（搜索/推荐/直播/分享）
 → 商品详情页（09） → 加购/立即购买（13）
 → 结算页：地址/优惠计算/运费（14/19）
 → 支付（15） → 订单生成（16）
 → 商家发货（34） → 物流跟踪（37）
 → 确认收货 → 评价（23） → 售后（20/21/22）
```

### 关键转化漏斗（北极星指标树）

| 层级 | 指标 |
|---|---|
| 北极星 | 月交易用户数（MTU）、GMV |
| 一级 | 曝光→点击率（CTR）、点击→加购率、加购→下单率、下单→支付率 |
| 二级 | 复购率、客单价 ARPU、退货率、纠纷率 |
| 反指标 | 支付取消率、超时关单率、差评率 |

## 4. 商家旅程

```
入驻（32）→ 资质审核（42）→ 缴保证金
→ 店铺装修（31/33）→ 发布商品（08）→ 审核（42）
→ 接单发货（34）→ 物流（37）
→ 售后处理（20/21）→ 平台仲裁（22）
→ 结算收款（35）→ 店铺评分（36）→ 违规处罚（43）
```

## 5. 平台角色旅程（运营）

- 商品审核（42）：机审 → 人审 → 抽检
- 活动运营（28）：报名审核 → 会场配置 → 数据复盘
- 规则治理（43）：违规检测 → 处罚 → 申诉
- 风控（41）：实时拦截 → 案件处理 → 规则迭代

## 6. 各域边界与依赖关系

| 域 | 上游依赖 | 下游被依赖 |
|---|---|---|
| 商品域 | 类目中心（10）、商家资质（32） | 交易（下单校验）、搜索（11）、推荐（12） |
| 交易域 | 商品/库存/价格引擎 | 履约（34）、结算（35）、售后（20-22） |
| 营销域 | 商品/店铺 | 价格引擎（19，优惠计算输入） |
| 治理域 | 全部业务数据 | 处罚/拦截反向作用于商品与交易 |
