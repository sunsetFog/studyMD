# 02 - PRD 文档规范与模板

> 本套 53 篇 PRD 统一遵循本规范。评审与撰写时按此模板校验完整性。

## 1. 文档命名与编号

- 文件名：`NN-english-name.md`（NN 为两位编号，见 00-index）。
- 文档内部标题层级：H1 文档名 → H2 章节号（1、2、3…）→ H3 子节（1.1、1.2）。
- 一个文档只覆盖一个需求域；跨域依赖用「依赖文档」标注，不复制粘贴内容。

## 2. 统一 PRD 模板

每篇功能 PRD 按以下骨架撰写（可裁剪但顺序不变）：

```
# NN - 功能名
## 1. 需求背景与目标
   背景（为什么做）、目标（可量化）、非目标（明确不做什么）
## 2. 用户故事
   作为 <角色>，我想要 <能力>，以便 <价值>
## 3. 功能需求
   3.1 功能清单（P0/P1/P2 标注）
   3.2 详细规则（含字段表、状态机、流程图）
## 4. 流程与状态机
## 5. 异常与边界
   网络异常、并发冲突、权限不足、数据缺失、降级策略
## 6. 数据与埋点
   关键事件、指标、报表需求
## 7. 依赖与接口
   依赖的域、提供的接口概要
## 8. 开放问题
   待确认事项 → 汇总至 51-open-questions.md
```

## 3. 全局写作约定

| 项 | 约定 |
|---|---|
| 优先级 | P0=MVP 必备 / P1=首年 / P2=远期；所有需求必须标注 |
| 角色 | 统一术语：买家、商家、平台运营、客服、风控、系统 |
| 金钱 | 单位元，保留两位小数；金额计算一律「分为最小单位存储」（见 49） |
| 时间 | 服务端时间统一 UTC 存储，展示按东八区；时间戳字段命名 `*_time` |
| 状态值 | 状态机中的状态用大写英文常量（如 `PAID`），展示文案单独定义 |
| ID | 用户 `user_id`、商家 `seller_id`、商品 SPU `spu_id`、SKU `sku_id`、订单 `order_no` |
| 流程图 | 用 ASCII 箭头流程（`A → B → C`），复杂分支用表格式规则描述 |
| 禁止 | PRD 中不出现具体技术选型（框架/库），只描述行为与验收标准 |

## 4. 需求条目编号规则

- 功能需求条目编号：`NN-x-y`（文档号-章-序），如 `14-3-2` 表示 14 篇 3 章第 2 条。
- 用途：测试用例、埋点、Bug 单均回溯到条目编号，保证可追踪。

## 5. 评审规则

| 节点 | 参与人 | 产出 |
|---|---|---|
| 需求初评 | 产品 + 对应域研发负责人 | 范围确认、排期粗估 |
| PRD 评审 | 产品 + 研发 + 测试 + 运营 | 评审意见表、开放问题清单 |
| 终稿 | 产品 | 更新开放问题归属与时间点 |
| 变更 | 产品 | 变更记录（谁/何时/改了什么/影响范围），重大变更重新评审 |

## 6. 本套文档间的引用约定

- 引用格式：`参见《NN 文档名》`，如「退款规则参见《20 仅退款》」。
- 全局性规则只写一次，位置如下，其余文档引用：
  - 幂等与并发：《49》
  - 性能与降级：《46》
  - 风控拦截标准：《41》
  - 违规处罚梯度：《43》
  - 金额精度：《49》
- 若引用规则与本文档特殊规则冲突：本文档优先，但必须在「开放问题」中登记冲突，由评审裁决。

## 7. 文档完成度自检

- [ ] 所有需求条目有 P0/P1/P2 标注与编号
- [ ] 有状态机的功能画出完整状态机（含异常态）
- [ ] 异常与边界覆盖：并发、超时、权限、数据缺失
- [ ] 数据埋点与指标定义完整，回溯到漏斗层级（01）
- [ ] 开放问题登记至 51 篇
- [ ] 引用的全局规则均用「参见」而非复制
