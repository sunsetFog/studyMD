## 2. 角色间关系

- 一个自然人可以同时是买家与商家（一个手机号两个身份，切换入口见 48）。
- 商家必须绑定 `user_id` 作为主账号；主账号可创建子账号（33）。
- 平台侧角色全部走后台账号体系，与 C 端账号隔离（独立登录域）。

## 4. 商家子账号权限（引用《33》）

子账号按岗位模板授权：运营岗（商品/装修）、客服岗（订单/售后回复）、发货岗（打单发货）、财务岗（账单只读）。主账号拥有全部权限并承担子账号操作责任。

## 5. 权限校验通用规则

1. **默认拒绝**：未在矩阵中明确的操作一律拒绝。
2. **双重校验**：前端隐藏入口 + 服务端强制校验（前端隐藏不是安全边界）。
3. **归属校验**：任何资源操作必须校验资源归属（如买家只能取消自己的订单），归属校验失败按越权处理并记风控日志（41）。
4. **越权响应**：统一返回「无权限」文案，不暴露资源是否存在（防枚举，见 49）。
5. **敏感操作二次确认**：涉及资金/不可逆操作（退款放款、处罚执行、结算放款）需二次验证（密码/OTP）并写审计日志。

## 6. 账号状态与权限联动

| 账号状态 | 影响 |
|---|---|
| 正常 | 全部权限 |
| 限制登录（41 风控） | 只能浏览，禁止交易操作 |
| 交易受限 | 禁止下单/使用营销资产，可浏览与咨询 |
| 封禁 | 禁止登录；未完结订单与售后仍按流程走完 |
| 注销 | 数据按 32 章/51 篇保留策略处理，资金须先清零 |
