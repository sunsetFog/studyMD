# 40 - 消息通知中心

## 1. 需求背景与目标

- **背景**：交易全链路依赖通知（支付/发货/签收/营销触达）；滥用通知会变成骚扰与卸载理由。
- **目标**：关键交易通知到达率 ≥99%、延迟 ≤10s；营销推送退订率 ≤0.5%。
- **非目标**：不做短信营销大规模群发（合规严格管控，仅交易类短信 P0）。

## 2. 用户故事

- 作为买家，我想要及时收到订单状态变化提醒，以便掌握物流进度。
- 作为买家，我想要自由开关各类推送，以免被打扰。
- 作为运营，我想要可控的营销触达（频控+圈选），以便转化不被骚扰抵消。

## 3. 通知类型矩阵

| 类别 | 场景示例 | 渠道 | 频控 | 优先级 |
|---|---|---|---|---|
| 交易强通知 | 支付结果、发货、签收、退款到账、超时关单 | App 推送 + 短信 | 必达，不频控 | P0 |
| 售后流转 | 退款审核结果、退货验收、仲裁通知 | App 推送 + 短信 | 必达 | P0 |
| 资产提醒 | 券临期、积分过期、预算预警 | App 推送 + 站内信 | 每类每日 ≤2 | P1 |
| 互动消息 | 客服回复、问大家邀请（24）、评价回复 | App 推送 + 站内信 | 实时 | P1 |
| 营销推送 | 活动开始、个性化推荐、开团邀请（27） | App 推送 | 单用户每日 ≤3 条，夜间（22:00-8:00）禁发 | P1 |
| 系统公告 | 规则变更、维护通知 | 站内信 + Banner | — | P0 |

## 4. 功能需求

| 条目 | 需求 | 优先级 |
|---|---|---|
| 40-4-1 | 统一消息中心：站内信列表（分类 Tab：交易/互动/营销/公告），已读/删除 | P0 |
| 40-4-2 | 推送开关：按类别粒度的用户设置（48 入口），交易类默认开且不可关（合规要求） | P0 |
| 40-4-3 | 发送服务：模板管理（变量渲染）、多渠道路由（App 推送→短信兜底）、失败重试（49 幂等） | P0 |
| 40-4-4 | 频控引擎：按「用户 × 类别」维度限流（上表规则），运营不可绕过 | P0 |
| 40-4-5 | 批量触达任务：圈选人群（45 数据）→ 审批（量大需两级审批）→ 定时/分批发送 → 到达率报告 | P1 |
| 40-4-6 | 免打扰时段：夜间营销推送自动顺延至次日 9:00 | P1 |
| 40-4-7 | 触达归因：营销消息点击 → 下单归因标记（45） | P1 |

## 5. 流程

```
业务事件（订单状态变更等）→ 消息服务订阅 → 匹配模板 + 用户开关校验 + 频控
 → 渠道路由（推送/短信/站内信）→ 发送（幂等键=事件ID+用户）
 → 失败重试 → 到达回执 → 数据报表
```

## 6. 异常与边界

| 场景 | 处理 |
|---|---|
| 推送通道故障 | 短信兜底（交易类）；纯营销类直接丢弃（不降级到短信） |
| 用户卸载 App/关闭推送 | 交易类走短信；营销类标记不可达 |
| 模板变量缺失 | 渲染校验：缺失变量禁止发送（防「您的订单{null}」事故） |
| 重复事件触发重复通知 | 幂等键去重（49） |
| 批量任务事故（发错人群） | 紧急撤回（未读可撤）、停发开关（46 应急） |

## 7. 数据与埋点

- 指标：各类通知到达率/点击率、频控拦截量、退订率、营销触达 ROI、通道故障时长。

## 8. 依赖与接口

- 依赖：各业务域事件（订阅制）、45 圈选、41 黑名单。
- 提供：`单发/批量发送 API`、`消息中心查询`。
