# 36 - 店铺评分体系

## 1. 需求背景与目标

- **背景**：店铺评分（DSR 类）是买家决策与平台分发的依据（11/12 排序因子）；必须可解释、抗刷。
- **目标**：评分计算周期内覆盖率 ≥95% 订单；评分与处罚/流量联动的规则全透明（商家可查）。
- **非目标**：不做店铺排行榜商业化售卖（P2）。

## 2. 用户故事

- 作为买家，我想要通过店铺评分判断商家可信度，以便放心下单。
- 作为商家，我想要清晰知道评分构成与改进方向，以便提升经营。
- 作为平台，我想要评分真实反映服务质量，以便流量分配公平。

## 3. 评分构成（P0）

| 维度 | 数据来源 | 计算窗口 |
|---|---|---|
| 描述相符 | 23 评价三维标签 | 近 90 天 |
| 物流/服务 | 发货时效（34：PAID→SHIPPED）+ 物流评分 | 近 90 天 |
| 服务态度 | 客服响应（39）/售后处理时效 | 近 90 天 |
| 综合指标 | 退货率（21）、纠纷率（22）、违规记录（43） | 近 90 天 |

- 展示形式：店铺页/详情页展示综合评分（5 分制，1 位小数）+ 三维分；订单数 <30 不展示（小样本保护，同 23 规则）。
- 计算：滚动 90 天加权（近期权重高）；每天凌晨重算（P0）。

## 4. 评分联动规则（P0，全透明）

| 联动 | 规则 |
|---|---|
| 流量 | 评分 ≥4.6：搜索/推荐加权（11/12 因子）；≤4.0：降权；≤3.6：搜索屏蔽候选（人工复核） |
| 活动资格 | ≥4.6 才可报名平台大促（28）；秒杀类目资格同 |
| 发货豁免 | 评分高的商家可申请延长发货时效（需平台审批，P1） |
| 处罚 | 评分连续 4 周 ≤3.6 → 店铺整治期：禁止上新 + 整改通知（43） |

## 5. 功能需求

| 条目 | 需求 | 优先级 |
|---|---|---|
| 36-4-1 | 评分计算任务：日更，多维数据聚合，去刷单数据（41 清洗后） | P0 |
| 36-4-2 | 商家评分看板：当前分/趋势/分维度明细/与类目均值对比/改进建议 | P0 |
| 36-4-3 | 评分异动告警：单日跌幅 >0.1 通知商家（可能遭遇恶意差评，联动 23 申诉） | P1 |
| 36-4-4 | 类目基准线：同类目评分分布参考（防跨类目不公平比较） | P1 |

## 6. 异常与边界

| 场景 | 处理 |
|---|---|
| 恶意差评拉低评分 | 23 申诉裁决后剔除；评分重算任务（当日生效） |
| 刷好评抬分 | 41 清洗，不进评分 |
| 低单量新店 | 新店保护期 30 天：不参与降权，仅展示「新店」 |
| 数据缺失（某维度无订单） | 维度缺省不计入，展示「暂无数据」 |
| 类目特性差异（生鲜天然退货高） | 类目内对比，基准线归一 |

## 7. 数据与埋点

- 指标：评分分布（平台/类目）、联动动作触发量（降权/屏蔽）、评分申诉量、整治期店铺数与整改通过率。

## 8. 依赖与接口

- 依赖：23 评价、21 退货、22 纠纷、34 发货时效、39 客服数据、41 清洗、43 处罚。
- 提供：`店铺评分查询`（C 端展示与排序因子）、`评分明细`（商家看板）。
