# 43 - 平台规则体系（违规与处罚）

## 1. 需求背景与目标

- **背景**：规则是治理的尺子——处罚要可预期（商家可查规则）、可申诉、可执行；规则混乱会引发商家群体事件。
- **目标**：处罚执行自动化率 ≥80%；申诉受理率 100%、处理时效 ≤72h；规则纠纷投诉 ≤0.5%。
- **非目标**：规则文本的法律效力解释归法务；本篇定义违规分类、处罚梯度与执行机制。

## 2. 违规类型与判责（P0）

| 类别 | 典型行为 | 举证来源 |
|---|---|---|
| 商品违规 | 假冒/侵权、禁售品、虚假宣传（极限词）、类目错挂滥用 | 42 审核、举报、品牌方投诉 |
| 交易违规 | 虚假发货（34）、延迟发货、刷单（41）、价格欺诈（19 划线价虚构） | 41/37 轨迹、19 对账 |
| 服务违规 | 售后敷衍、客服辱骂、诱导站外交易 | 39 会话质检、22 案件 |
| 资质违规 | 资质造假/过期（32） | 42 核验 |
| 营销违规 | 券套现、活动作弊（25/28）、虚假种草（30） | 41/25 对账 |
| 内容违规 | UGC 违禁（23/24/30）、直播违规（29） | 42 审核 |

## 3. 处罚梯度（P0，按累计扣分制）

### 3.1 通用梯度

| 梯度 | 扣分（每周期 12 分制，一年） | 处罚动作 |
|---|---|---|
| 提醒 | 情节轻微 | 站内提醒，限期整改 |
| 一般 | 扣 2-6 分 | 单品/行为限制（下架、降权 11、禁上新 3 天） |
| 严重 | 扣 8-10 分 | 店铺限制（活动禁报 28、提现冻结 07）、赔付买家（延迟发货类） |
| 特别严重 | 扣 12 分 / 直接触发 | 店铺清退、保证金扣除（32）、关联主体拉黑（41） |

- 扣分周期：自然年；扣满 12 分清退；年度末清零（清退除外）。
- 累犯加重：同类型违规 3 次 → 梯度上跳一级。

### 3.2 执行机制（P0）

| 条目 | 需求 |
|---|---|
| 43-3-1 | 处罚执行引擎：违规认定 → 自动匹配梯度 → 执行动作（各域接口：下架/冻结/限权）→ 通知商家（40） |
| 43-3-2 | 处罚通知：必须含违规依据（规则条目链接）、证据摘要、申诉入口与时限（72h） |
| 43-3-3 | 处罚记录：商家处罚历史页（33 看板），商家可见全量记录 |
| 43-3-4 | 申诉：72h 内提交，风控/审核复核（依类型分派 41/42），结论终局；申诉期间执行不暂停（严重违规）或暂缓（一般违规，可配） |
| 43-3-5 | 买家赔付类处罚：自动发起赔付（积分/红包，06）无需买家申请 |

## 4. 规则管理（P0）

- 规则库版本化：每条规则有编号、生效日期、历史版本；商家端规则中心可查（Web）。
- 规则变更：提前 7 天公告（40），不追溯历史行为（例外：资损类即时生效）。

## 5. 异常与边界

| 场景 | 处理 |
|---|---|
| 批量误判（规则 bug 导致大面积处罚） | 处罚执行支持批量撤销 + 影响回滚（评分/流量恢复）；事故复盘进 46 |
| 申诉期间买家权益受损 | 资金类以买家优先：退款先执行，商家申诉成功后平台补偿（22 联动） |
| 处罚与结算冲突 | 冻结提现时结算照常累计（35），解除后可提 |
| 规则与法规冲突 | 法务通道：即时下线该规则条款并公告 |
| 清退商家在途订单 | 已售订单正常履约；新单禁止；售后继续受理至完结（32 关店流程） |

## 6. 数据与埋点

- 指标：各类型违规量与趋势、处罚量分布（梯度）、申诉率与翻案率（判罚质量指标）、自动化执行率、买家赔付金额。

## 7. 依赖与接口

- 依赖：41（刷单/欺诈认定）、42（内容违规认定）、22（仲裁判责）、33（执行限制）、07/35（资金动作）。
- 提供：`处罚执行 API`（梯度映射）、`处罚记录查询`、`申诉工作流`。
