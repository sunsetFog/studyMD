# 45 - 数据分析与报表

## 1. 需求背景与目标

- **背景**：三方都需要数据：平台运营（大盘与治理）、商家（经营分析）、买家侧产品（体验优化）。埋点与指标口径必须先行统一。
- **目标**：核心报表 T+1 可用（实时看板 <5 分钟延迟）；指标口径文档化 100%。
- **非目标**：不做自助 BI 拖拽分析平台（P2）；不做用户级实时画像查询开放给商家（隐私）。

## 2. 指标体系（指标树）

### 2.1 平台大盘（P0）

| 层 | 指标 |
|---|---|
| 北极星 | GMV、MTU（月交易用户） |
| 交易漏斗 | 曝光→点击→加购→下单→支付（分渠道：搜索/推荐/直播/内容/广告 11/12/29/30/44） |
| 用户 | 新客数/获客成本/复购率/留存（次日/7日/30日）/会员等级分布（06） |
| 供给 | 在售商品数/动销率/商家数与活跃率（后台登录 33） |
| 体验 | 48h 发货率（34）、退款率（20/21）、纠纷率（22）、差评率（23） |
| 资金 | 佣金收入/广告收入/营销补贴/资损金额（35/25/41） |

### 2.2 商家报表（P0）

| 报表 | 内容 | 频率 |
|---|---|---|
| 经营日报 | 访客/转化/GMV/客单价（vs 类目均值） | T+1 |
| 商品分析 | 单品曝光/点击/转化/收藏加购；滞销预警 | T+1 |
| 流量来源 | 各渠道流量与转化（搜索词 TopN 11） | T+1 |
| 服务分析 | 发货时效/退款率/评分趋势（36 看板） | T+1 |
| 营销效果 | 券核销/活动 ROI（25/28）/广告 ROI（44） | T+1 |

### 2.3 埋点体系（P0）

- **事件规范**：`domain_event(params)`，统一字段（user_id/sku_id/seller_id/channel/source/timestamp/session_id）。
- 全局来源标记 `channel`（搜索/推荐/直播/内容/广告/分享/活动）与 `source_page`，归因体系的基础（44/40 转化归因共用）。
- 埋点验收：测试用例比对事件流（P0，埋点缺失=报表缺数）。

## 4. 异常与边界

| 场景 | 处理 |
|---|---|
| 埋点丢失/乱序 | 事件幂等（49）+ 批量补传；报表重跑任务 |
| 大促数据洪峰 | 明细数据采样上抛 + 报表延迟降级公告（46） |
| 指标口径变更 | 字典版本化；历史报表标注口径版本 |
| 数据权限越界 | 商家只能看自己数据；内部按角色（03 矩阵） |
| 刷单污染 | 全报表统一接入 41 刷单清洗标记（口径一致） |

## 5. 数据与埋点（本篇即埋点定义源）

- 核心 funnel 事件：`impress → click → add_cart → order_submit → pay_success → confirm_receipt → review`，每步带 channel/source。
- 指标：本篇 2.1/2.2 全量；看板健康度（各报表生成成功率/延迟）。

## 6. 依赖与接口

- 依赖：全域埋点（各 PRD 第 6 章）、41 清洗标记、16/35 交易资金事实。
- 提供：`看板/报表服务`、`指标查询 API`、`人群圈选`（40 批量触达）、`实验平台`。
