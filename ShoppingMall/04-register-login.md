# 04 - 注册与登录

## 1. 需求背景与目标

- **背景**：账号是所有交易链路的入口，需要兼顾转化率（低门槛）与安全（防批量注册）。
- **目标**：注册转化率 ≥85%（落地页→完成注册）；登录成功率 ≥99.5%；批量注册拦截率 ≥99%。
- **非目标**：不做第三方平台账号互通（P2 再议）；不做游客购物车跨端同步（游客态规则见 13）。

## 2. 用户故事

- 作为新用户，我想要用手机号快速注册，以便立即购物。
- 作为老用户，我想要多种方式登录（密码/短信验证码/生物识别），以便在安全与便捷间自由选择。
- 作为忘记密码的用户，我想要通过手机号找回，以便不丢失账号资产。

## 3. 功能需求

### 3.1 注册

| 条目 | 需求 | 优先级 |
|---|---|---|
| 04-3-1 | 手机号 + 短信验证码注册（唯一主注册方式） | P0 |
| 04-3-2 | 注册需完成滑块/行为验证（防机器人，41） | P0 |
| 04-3-3 | 注册协议勾选（《用户协议》《隐私政策》），未勾选无法提交 | P0 |
| 04-3-4 | 昵称自动生成（可后续改），头像默认系统图 | P0 |
| 04-3-5 | 一机一号风控：同设备高频注册触发人工验证 | P0 |
| 04-3-6 | 邮箱注册与第三方登录（微信/苹果） | P1 |

### 3.2 登录方式

| 方式 | 规则 | 优先级 |
|---|---|---|
| 手机号 + 密码 | 密码规则见 3.3 | P0 |
| 手机号 + 短信验证码 | 60s 限发一条；验证码 5 分钟有效，错误 5 次锁定 15 分钟 | P0 |
| 生物识别 | 已开启后本机快捷登录；触发风控时强制降级为验证码 | P1 |
| 扫码登录（PC 扫 App） | 二维码 2 分钟有效；需 App 端确认 | P1 |

### 3.3 密码与找回

- 密码规则：8-20 位，须含字母与数字；禁止与手机号相同；传输与存储加密（存储端哈希加盐，见 49）。
- 连续输错密码 5 次 → 锁定 15 分钟并短信通知。
- 找回密码流程：手机号 → 短信验证 → 设置新密码 → 全端强制下线 + 通知。

### 3.4 多端会话规则

| 项 | 规则 |
|---|---|
| 会话有效期 | Web 7 天 / App 30 天滑动续期 |
| 同端互踢 | 同设备类型新登录踢旧会话；App 多设备并存上限 1 台 |
| 强制下线 | 改密/异常风控/封禁 → 全端下线并通知 |

## 4. 流程

```
注册：输入手机号 → 风控前置校验（41：号段/频次/设备指纹）
 → 发验证码 → 校验通过 → 协议勾选 → 建号 → 进入引导（领新人券，25）
登录：凭证输入 → 密码错误计数 / 验证码校验 → 设备指纹风控
 → 低风险：直接登录；中风险：加滑块；高风险：拦截+通知
```

## 5. 异常与边界

| 场景 | 处理 |
|---|---|
| 验证码发送失败 | 提示稍后重试；连续失败 3 次提供人工通道 |
| 已注册手机号重复注册 | 引导登录，不提示「该号已注册」（防撞库信息枚举） |
| 异地/新设备登录 | 见《05 账号安全》 |
| 验证码接口被盗刷 | 号码维度+IP 维度频控（41），超限静默丢弃 |
| 注册中途退出 | 不建号；手机号 24h 内下次进入可续填 |

## 6. 数据与埋点

- 事件：`register_page_view` / `register_submit` / `register_success` / `login_attempt` / `login_success` / `login_fail(reason)`
- 指标：注册转化率、各登录方式占比、验证码成功率、风控拦截率。

## 7. 依赖与接口

- 依赖：短信网关、风控引擎（41）、设备指纹。
- 提供：`获取当前用户会话`、`登录态校验` 供全站使用。
