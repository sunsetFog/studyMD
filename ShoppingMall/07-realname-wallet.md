# 07 - 实名认证与平台钱包

## 1. 需求背景与目标

- **背景**：交易类合规要求实名（大额/提现/提货类）；平台钱包承载余额、退款中转、提现。
- **目标**：提现成功率 ≥99.9%；资金账务差错 0 容忍（每日对账，49）。
- **非目标**：不做借贷/理财等金融业务（合规边界，仅支付结算工具）。

## 2. 用户故事

- 作为买家，我想要完成一次实名认证长期使用，以便大额下单不被拦截。
- 作为用户，我想要余额随时可提现，以便资金自由支配。
- 作为商家，我想要结算款进入平台钱包并可提现，以便经营回款（35 引用）。

## 3. 功能需求

### 3.1 实名认证（P0）

| 项 | 规则 |
|---|---|
| 方式 | 姓名 + 身份证号 二要素校验（对接合规通道）；失败 3 次触发人工通道 |
| 触发场景 | 单笔支付 ≥ 阈值（默认 5000 元可配）、提现、提货类虚拟服务 |
| 信息安全 | 证件号展示脱敏（前 1 后 1），明文仅风控/财务权限可查且留痕（03） |
| 结果 | 认证通过永久有效；同一身份证最多绑定 5 个账号（合规要求） |

### 3.2 平台钱包（P0）

**账户模型**：钱包余额 = 可用余额 + 冻结金额；一切变动必须产生流水（不可直接改余额）。

| 功能 | 规则 |
|---|---|
| 入账 | 退款到余额（20/21 选择「退回余额」）、提现失败退回、平台赔付（22） |
| 消费 | 结算页「余额支付」（15 支付渠道之一，需实名） |
| 冻结 | 仲裁中订单相关款项冻结（22）；风控可疑资金冻结（41） |
| 提现 | 实名账户 → 绑定银行卡（四要素校验）；单笔 ≥1 元；免费额度每月 3 笔，超出 0.1% 手续费（可配） |
| 提现时效 | T+1 到账；单日上限 2 万元（可配） |

### 3.3 对账（P0，财务）

- 每日 T+1 与支付渠道对账（15）：渠道流水 vs 平台流水，差异 >0 自动告警并生成差错工单。
- 提现状态机：`发起 → 处理中 → 成功 / 失败退回`；失败自动退回余额并通知（40）。

## 4. 流程：提现

```
发起提现 → 校验（实名/绑卡/限额/冻结外余额）→ 创建提现单（幂等键）
 → 渠道代付 → 成功：扣账+流水 / 失败：退回余额+通知
 → 状态变更全程通知用户（40）
```

## 5. 异常与边界

| 场景 | 处理 |
|---|---|
| 提现渠道超时（结果未知） | 单据保持「处理中」，对账任务确认最终态；禁止超时即判失败 |
| 冻结金额 > 可用余额 | 可提现金额 = max(0, 余额-冻结)；界面展示冻结明细 |
| 余额支付与退款并发 | 按 49 幂等规则串行化处理同一钱包账户 |
| 身份证被占绑满 5 号 | 引导联系客服解绑历史账号（39） |
| 冻结资金处置 | 仲裁结论后按 22 自动解冻/扣划；风控冻结需专员审批解冻 |

## 6. 数据与埋点

- 事件：`realname_submit` / `realname_pass` / `wallet_recharge?`（无充值，仅退款入账）/ `withdraw_create` / `withdraw_success|fail`
- 指标：实名率、提现成功率/时效、对账差错数（目标 0）、冻结资金余额。

## 7. 依赖与接口

- 依赖：支付网关（15，退款入账/代付）、风控（41）、消息（40）。
- 提供：`钱包余额查询`、`冻结/解冻`、`提现单创建` 给 15/22/35。
