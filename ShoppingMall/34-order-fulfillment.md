# 34 - 商家发货履约

## 1. 需求背景与目标

- **背景**：发货时效是平台履约体验的底线（48h 规则）；打单发货效率决定商家运营成本。
- **目标**：48h 发货率 ≥95%；虚假发货率 ≤0.5%；打单耗时 ≤10s/单。
- **非目标**：不做商家自有 WMS 深度对接（标准回执接口即可，P2 深化）。

## 2. 用户故事

- 作为商家，我想要批量打单发货，以便高效处理爆单。
- 作为买家，我想要发货后立刻看到真实物流单号，以便跟踪。
- 作为平台，我想要识别虚假发货，以便保护买家权益。

## 3. 发货时效规则（P0）

| 规则 | 内容 |
|---|---|
| 48h 发货 | PAID 后 48h 内必须发货（预售/定制按 27/08 约定时效） |
| 超时后果 | 订单标「延迟发货」；买家可仅退款（20）；按 43 赔付（每单按比例赔付积分/红包） |
| 预警 | PAID 24h 未发货 → 商家工作台预警（33）；36h → 短信催办 |

## 4. 功能需求

| 条目 | 需求 | 优先级 |
|---|---|---|
| 34-4-1 | 待发货列表：按支付时间排序，筛选（地址区域/商品）；批量选择 | P0 |
| 34-4-2 | 单笔发货：填写/选择物流公司 + 运单号 → 校验单号格式 → 订单转 SHIPPED | P0 |
| 34-4-3 | 批量打单：上传单号文件（CSV 模板）或对接电子面单（37，一键取号）→ 批量发货，失败明细可重试 | P0 |
| 34-4-4 | 电子面单：一键取号 + 打印面单（P0 核心，37 对接） | P0 |
| 34-4-5 | 拆单发货：子订单独立发货；一子订单多包裹（分包裹发货） | P1 |
| 34-4-6 | 发货拦截响应：买家取消/改址（17）→ 30 分钟内回执（可拦截/不可拦截） | P0 |
| 34-4-7 | 虚假发货识别输入：发货后 24h 无揽收轨迹 → 标记「疑似虚假发货」（41+37 轨迹联动），商家需举证 | P0 |
| 34-4-8 | 无货报备：缺货商品报备缺货时长，超 72h 系统自动退款（买家知情） | P1 |

## 5. 流程

```
订单 PAID → 待发货列表 → 打单（电子面单取号）→ 出库发货（回传单号）
 → 订单 SHIPPED → 37 轨迹跟踪启动
 → 24h 无揽收 → 疑似虚假发货标记 → 举证/处罚（43）
 → 改址请求 → 回执（30 分钟）→ 更新面单信息
```

## 6. 异常与边界

| 场景 | 处理 |
|---|---|
| 运单号填错 | 24h 内可改一次（买家通知）；之后需客服介入（39） |
| 重复发货同一单 | 幂等：SHIPPED 后发货接口拒绝 |
| 电子面单取号失败 | 降级手写单号入口；失败率监控（37 渠道健康） |
| 爆单积压 | 列表按超时风险排序（剩余时效倒计时）；平台通知买家（40 透明度） |
| 分包裹部分丢失 | 按包裹维度售后举证（22） |

## 7. 数据与埋点

- 事件：`fulfill_view` / `ship_single/batch(count)` / `label_print` / `intercept_response(result)`
- 指标：48h 发货率、打单耗时、面单取号成功率、虚假发货识别量、改址回执率。

## 8. 依赖与接口

- 依赖：16 订单状态、37 电子面单/物流、17 拦截指令、43 处罚、40 通知。
- 提供：`发货接口`、`拦截回执`、`发货时效数据`（36 评分输入）。
