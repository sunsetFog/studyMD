# 46 - 非功能需求：性能、可用性、SLA 与降级

> 本篇是全站非功能需求的总纲；各 PRD 中的性能指标均引用本篇口径。

## 1. 可用性目标（SLA）

| 系统 | 目标 | 说明 |
|---|---|---|
| C 端交易核心链路（浏览/下单/支付） | 99.99%（年停机 ≤53 分钟） | 最高优先 |
| C 端其他（内容/社区） | 99.9% | |
| 商家后台 | 99.9%（大促期 99.95%） | |
| 审核后台 | 99.5% | 允许排队 |
| 计划内维护 | 低峰期（02:00-06:00），公告提前 7 天（40） | |

## 2. 性能预算（P99）

| 场景 | 指标 | 预算 |
|---|---|---|
| 首页/列表首屏 | LCP | ≤2s |
| 商品详情首屏 | LCP | ≤1.5s（09） |
| 搜索结果 | P99 | ≤500ms |

## 3. 容量与弹性

| 项 | 要求 |
|---|---|
| 容量规划 | 按「大促峰值 × 1.5」规划；日常自动弹性（HPA） |
| 压测 | 上线前全链路压测 + 大促前 2 次全量压测（含秒杀 26 场景） |
| 数据增长 | 订单/流水冷热分离：热 3 个月、温 1 年、冷归档（16/35） |
| 削峰 | 排队系统覆盖：秒杀下单、批量触达（40）、结算批任务（35） |

## 4. 降级预案（分级）

| 级别 | 触发 | 动作 |
|---|---|---|
| L1 轻度 | 非核心依赖故障 | 关闭非核心功能（推荐降热销榜 12、问答隐藏 24） |
| L2 中度 | 核心读服务降级 | 详情页缓存旧数据 + 交易继续（09 兜底） |
| L3 重度 | 写服务告急 | 下单排队限流（14）、营销功能全关（19 优惠仅展示不叠加） |
| L4 极端 | 支付全渠道故障 | 收银台维护态 + 公告；已下单订单保护性顺延关单倒计时 |

**降级总开关**：运营/技术可一键执行分级预案（审批留痕，03）；每次预案需演练（季度）。

## 5. 安全与合规（引用）

- 密钥管理、数据加密、审计：引用《32》。
- 接口安全：防重放（时间戳+签名）、防越权（03/49）。
- 用户隐私：最小化采集、脱敏展示（38）、删除权（32）。

## 6. 监控与值班（引用）

- 监控指标、告警分级、值班 SOP：引用《LLMOps/22-23》同构体系（本套文档体系外的运维规范按需另建）。
- 核心业务指标监控（业务可用性）：支付成功率、下单成功率、发货履约率——业务指标异常比技术指标先行。

## 7. 验收标准（P0 上线门槛）

- [ ] 全链路压测通过（2.2 预算内，峰值 1.5 倍）
- [ ] 降级预案 L1-L4 演练通过
- [ ] 监控告警覆盖全部核心接口
- [ ] 回滚方案（版本级 + 配置级）验证通过
- [ ] 故障演练：支付渠道故障切换、库存服务故障降级
- [ ] 数据备份与恢复演练（RPO ≤5 分钟，RTO ≤30 分钟）
