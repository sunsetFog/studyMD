# 41 - 风控反作弊

## 1. 需求背景与目标

- **背景**：电商平台四大风险：薅羊毛（营销资损）、刷单（数据污染）、盗号（资金/订单）、欺诈（交易安全）。
- **目标**：营销资损率 ≤0.1%；刷单识别准确率 ≥90%；误伤率（正常用户被拦截）≤0.3%。
- **非目标**：不做支付机构侧风控（15 联动即可）；不做内容安全（42 域）。

## 2. 风险场景清单

| 风险 | 典型手法 | 拦截点 | 优先级 |
|---|---|---|---|
| 薅羊毛 | 批量小号领券/新客补贴、抢秒杀脚本 | 注册（04）、领券（25）、秒杀（26） | P0 |
| 刷单 | 自买自卖、空包单、假聊天 | 订单画像（识别后清洗 11/12/23/36 数据） | P0 |
| 盗号 | 撞库、设备克隆、异地操作 | 登录（05）、交易二次验证 | P0 |
| 恶意退款 | 偷换退货、仅退款薅货 | 售后（20/21）、仲裁证据（22） | P0 |
| 恶意行为 | 恶意下单占库存、差评勒索 | 下单频控（14）、评价申诉（23） | P1 |

## 3. 功能需求

### 3.1 实时风控引擎（P0）

| 条目 | 需求 |
|---|---|
| 41-3-1 | 风控接入点（埋点清单）：注册/登录/领券/下单/支付/退款申请/评价，每点输出「放行/挑战（二次验证）/拦截」 |
| 41-3-2 | 设备指纹：设备 ID/模拟器检测/多账号关联（同设备多号图谱） |
| 41-3-3 | 规则引擎：运营可配规则（频次/金额/IP 黑名单/号段），规则变更走审批+灰度（防误伤事故） |
| 41-3-4 | 用户信用分：0-1000，由历史行为（违规/纠纷/退款率）动态评分；等级影响各链路策略（评价先审后发 23、退款人工审核 20） |

### 3.2 数据清洗与识别（P0）

| 条目 | 需求 |
|---|---|
| 41-3-5 | 刷单识别：订单网络图谱（买卖双方关联度/资金回流/物流空包特征），输出刷单订单标记 |
| 41-3-6 | 刷单数据清洗联动：销量（11 排序）、评分（36）、评价（23）、推荐（12）统一排除刷单标记数据 |
| 41-3-7 | 营销资产异常监控：领券/积分突增告警，触发资产冻结（06/07/25） |

### 3.3 案件处置（P0）

- 案件工作台：风控专员处理队列（拦截复核/冻结审批/处罚建议）。
- 处置动作：挑战验证、限制功能（03 账号状态）、资产冻结、封禁（43 处罚梯度）。
- 误伤申诉：用户申诉通道（05/39），24h 内响应；申诉成功自动解除 + 记录规则调优样本。

## 4. 流程：薅羊毛拦截

```
领券请求 → 实时规则（同设备多号/号段/行为轨迹异常）
 → 放行 / 挑战（行为验证码） / 拦截（静默，不给明确风控文案防探测）
 → 离线批量识别 → 资产追回（未核销券作废）→ 案件 → 处罚（43）
```

## 5. 异常与边界

| 场景 | 处理 |
|---|---|
| 误伤正常用户（规则过严） | 灰度发布规则（小流量验证误伤率）+ 申诉快速通道 |
| 新型作弊（规则未覆盖） | 异常指标监控（45 波动告警）→ 人工研判 → 补规则 |
| 风控引擎故障 | 降级策略：关闭「拦截」只记录（可用性优先），46 预案 |
| 冻结资金争议 | 22 仲裁同流程举证；冻结期 ≤30 天（合规） |
| 黑产对抗升级 | 识别策略与对抗周报机制（45 数据驱动） |

## 6. 数据与埋点

- 指标：各接入点拦截量/误伤率、信用分分布、刷单识别量与准确率（抽样标注）、营销资损金额、案件处理时效。

## 7. 依赖与接口

- 依赖：设备指纹服务、订单/行为数据（45）、43 处罚执行。
- 提供：`风控决策 API（同步）`、`用户信用分查询`、`刷单标记清洗事件`（各域消费）。
