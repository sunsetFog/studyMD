# 16 - 订单状态机与管理

## 1. 需求背景与目标

- **背景**：订单是全平台核心资产，状态机是交易域与售后/履约/结算的契约。
- **目标**：订单状态流转 100% 可追溯；状态不一致（对账）率 0。
- **非目标**：本篇为买家视角订单管理；商家发货细节在 34，逆向流程在 20-22。

## 2. 订单状态机（主流程）

```
CREATED（已创建未支付）
   ├─(支付成功)→ PAID（已付款待发货）
   │                ├─(商家发货)→ SHIPPED（已发货）
   │                │                 ├─(签收)→ DELIVERED（已签收/待确认）
   │                │                 │            ├─(确认收货/自动)→ COMPLETED（已完成）
   │                └─(发货前取消/退款)→ CLOSED
   ├─(超时未付)→ CLOSED（已关闭）
   └─(用户取消)→ CLOSED
COMPLETED 后进入售后窗口期（见 5.3）
```

| 状态 | 触发条件 | 用户可见文案 | 自动化规则 |
|---|---|---|---|
| CREATED | 14 下单成功 | 待付款 | 15 分钟倒计时关单 |
| PAID | 支付回调确认 | 待发货 | 商家 48h 未发货标「延迟发货」预警（34/36） |
| SHIPPED | 商家打单发货 | 待收货 | 物流轨迹驱动（37）；派送中提醒 |
| DELIVERED | 物流签收 | 待确认收货 | 签收后 7 天自动确认收货 |
| COMPLETED | 确认收货 | 已完成 | 触发结算（35 T+1）、积分发放（06 T+1） |
| CLOSED | 取消/超时/退款 | 已关闭 | 库存回补（18）、优惠券返还（25）、预支付退款（15） |

## 4. 关键规则

- **金额快照不可变**：订单金额以 14 下单时快照为准，任何后续优惠/价格变动不影响已生成订单。
- **状态单向性**：状态只能沿状态机正向流转或进入 CLOSED；禁止跳态（如 SHIPPED 直接收货关闭需走 17 补救流程）。
- **倒计时统一由服务端驱动**：客户端倒计时仅展示，关单以服务端任务为准（防客户端时间作弊）。
- **订单号规则**：主单 `order_no`、子单 `sub_order_no`；支付单 `pay_no` 可关联多子单（16-3-8）。

## 5. 异常与边界

| 场景 | 处理 |
|---|---|
| 支付成功但订单已超时关闭 | 15 章竞态规则：自动原路退款 |
| 签收异常（物流显示签收但用户未收到） | 引导联系商家/客服（39），仲裁凭据以 37 轨迹为准 |
| 自动确认收货期间发生退款申请 | 暂停自动确认，进入售后流程（20/21） |
| 拆单后部分发货 | 子订单独立状态；主单状态 = 子单聚合（全部发货才 SHIPPED） |
| 订单详情接口失败 | 列表页缓存兜底展示，详情重试（46） |

## 6. 数据与埋点

- 事件：`order_status_change(order_no, from, to, trigger)` / `confirm_receipt` / `order_search`
- 指标：各状态订单量与停留时长（PAID→SHIPPED 时长 = 发货时效核心指标 36）、超时关单率、自动确认收货占比。

## 7. 依赖与接口

- 依赖：15 支付、18 库存、25 优惠券、37 物流、40 消息。
- 提供：`订单状态查询`、`状态变更事件订阅`（结算/积分/风控/消息全订阅状态事件）。
