# 39 - 客服系统

## 1. 需求背景与目标

- **背景**：客服承接咨询（售前）与纠纷前置处理（售后），是减少仲裁（22）与差评（23）的第一道防线。
- **目标**：机器人自助解决率 ≥60%；人工首次响应 ≤30s（在线）；客服处理升级到仲裁的比例 ≤20%。
- **非目标**：不做电话客服中心（P2）；不做视频客服（P2）。

## 2. 用户故事

- 作为买家，我想要先问机器人快速解决常见问题，解决不了再转人工，以便省时。
- 作为商家，我想要用客服工作台统一接待并查看订单上下文，以便高效服务。
- 作为客服，我想要订单/物流/售后全上下文，以便一次解决不推诿。

## 3. 功能需求

### 3.1 买家侧（P0）

| 条目 | 需求 |
|---|---|
| 39-3-1 | 会话入口：店铺客服（31/33 配置时段）+ 平台客服（纠纷/投诉）；离线时段留言转工单 |
| 39-3-2 | 机器人问答：FAQ 知识库（订单查询/物流/退款进度自助卡片）；意图识别跳转自助工具 |
| 39-3-3 | 转人工：机器人两次未解决或用户主动；排队与预计等待时间 |
| 39-3-4 | 会话上下文：商品/订单自动携带（09-3-5 入口场景） |

### 3.2 商家客服工作台（P0）

| 条目 | 需求 |
|---|---|
| 39-3-5 | 会话分配：按子账号客服岗（33）轮询；接待上限与离线转移 |
| 39-3-6 | 工作台上下文：买家信息脱敏、关联订单/物流/售后单（16/37/20/21 查询卡片） |
| 39-3-7 | 快捷回复：话术库 + 常用操作卡片（发券 25/改地址 17 发起） |
| 39-3-8 | 售后协同：客服可直接代办买家售后申请（20/21 代发起，留痕） |

### 3.3 平台客服与工单（P1）

| 条目 | 需求 |
|---|---|
| 39-3-9 | 工单系统：来源（留言/会话升级/投诉）→ 分类分派 → SLA 计时（普通 24h/投诉 12h）→ 结案 |
| 39-3-10 | 升级仲裁：协商失败一键转 22（自动携带会话记录作证据） |
| 39-3-11 | 质检：会话抽样质检（响应时长/违规话术/服务态度），结果进 36 服务分 |

## 4. 流程

```
买家咨询 → 机器人（自助卡片/FAQ）→ 未解决 → 转人工排队
 → 商家客服接待（上下文注入）→ 解决/代办售后
 → 无法解决 → 平台客服工单 → 升级仲裁（22）
 → 结案 → 满意度评价 → 质检回流知识库
```

## 5. 异常与边界

| 场景 | 处理 |
|---|---|
| 客服全离线 | 自动切换留言工单 + 机器人兜底 |
| 会话中断（网络） | 消息重发与撤回幂等（49）；断线重连恢复记录 |
| 恶意刷会话攻击 | 频控 + 黑名单（41） |
| 敏感信息传输 | 会话中手机号/证件自动脱敏提示（42 词库） |
| 机器人答非所问 | 低置信度不强行作答，直接引导人工（体验优先） |

## 6. 数据与埋点

- 指标：会话量/机器人解决率/转人工率、首次响应时长、会话解决率、工单 SLA 达成率、满意度评分、升级仲裁率。

## 7. 依赖与接口

- 依赖：16/37/20/21 上下文数据、40 消息通道、42 词库、43 处罚（客服违规）。
- 提供：`会话/工单 API`、`满意度数据`（36 消费）。
