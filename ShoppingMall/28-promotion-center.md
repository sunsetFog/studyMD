# 28 - 营销活动中心

## 1. 需求背景与目标

- **背景**：满减/满赠/跨店活动是平台与商家共同的营销底座（大促核心玩法）；活动配置错误直接资损。
- **目标**：活动配置到生效 ≤5 分钟；活动期间算价一致性 100%（19）；报名审核时效 ≤24h。
- **非目标**：不做自动营销策略引擎（P2）；不做游戏化互动（P2）。

## 2. 活动类型

| 类型 | 规则 | 承担方 | 优先级 |
|---|---|---|---|
| 店铺满减/满折 | 商家创建，单店生效 | 商家 | P0 |
| 满赠 | 满额赠指定 SKU/赠品，赠品独立库存（18） | 商家 | P1 |
| 跨店满减 | 平台创建，多店商品可凑单（19 分摊） | 平台+商家按规则分担 | P1 |
| 平台大促 | 大促会场（11.11 类）：报名制 + 会场楼层 + 全站玩法叠加 | 平台/商家 | P1 |
| N 件折 | 第二件半价等 | 商家 | P2 |

## 3. 功能需求

### 3.1 商家侧（P0）

| 条目 | 需求 |
|---|---|
| 28-3-1 | 创建活动：类型/时间/门槛/力度/参与商品（类目或手动选择 ≤500 SKU）/预算 |
| 28-3-2 | 活动列表与状态：未开始/进行中/已结束/已驳回；进行中可提前结束（不可修改力度） |
| 28-3-3 | 报名平台大促：选会场类目 → 提交商品与活动价 → 审核价保（价格不高于历史 30 天最低价，价保规则 P1） |
| 28-3-4 | 活动效果报表：曝光/成交/ROI（45 数据） |

### 3.2 平台侧（P1）

| 条目 | 需求 |
|---|---|
| 28-3-5 | 平台活动创建：跨店满减配置（档位如满 300-50）、生效类目范围 |
| 28-3-6 | 大促会场配置：楼层（类目楼层/榜单楼层/直播楼层）/商品坑位/排序规则；会场页 H5+App |
| 28-3-7 | 报名审核台：按类目分派审核员（42 同款工作台），通过/驳回（原因） |
| 28-3-8 | 大促作战室：实时 GMV/峰值监控/资损护栏状态（45+46 联动） |

### 3.3 买家侧（P0）

- 会场页/商品页/结算页的活动透出（角标/标签/进度条如「还差 50 元减 30」）。
- 跨店凑单提示（13 购物车 + 19 算价联动）。

## 4. 流程：大促报名

```
平台发布活动 → 商家报名（选商品+活动价）→ 审核（价格保/资质/库存）
 → 通过 → 商品进会场池 → 会场配置发布
 → 活动开始（价格引擎叠加规则生效）→ 实时监控 → 结束 → 效果复盘
```

## 5. 异常与边界

| 场景 | 处理 |
|---|---|
| 活动价低于成本/历史最低价异常 | 审核拦截；上线后 19-4-5 护栏 |
| 活动中途商品下架/缺货 | 会场坑位实时摘除（08 状态联动）；已下单正常履约 |
| 满赠赠品缺货 | 提示改为等价赠品/红包补偿（P1），或赠品缺货时活动该 SKU 退出 |
| 跨店满减退款引发门槛失效争议 | 分摊退款按 19；门槛失效不追回已享受优惠（用户权益优先，规则明示） |
| 活动重叠冲突 | 19 叠加互斥规则统一仲裁；创建时预校验重叠时段同类活动 |

## 6. 数据与埋点

- 事件：`promo_create/audit/start/end` / `venue_view(venue_id)` / `venue_click`
- 指标：活动 GMV 占比、会场转化率、报名通过率、活动期间客诉率（算价类投诉重点监控）、预算消耗进度。

## 7. 依赖与接口

- 依赖：19 引擎（规则消费方）、08 商品、18 库存（满赠）、42 审核、45 数据、46 护栏。
- 提供：`活动查询（按商品反查生效活动）`——详情页/结算页透出依据。

- 价保（买贵退差价）是否 V2.0 提供？（转 51）
