# 13 - 购物车

## 1. 需求背景与目标

- **背景**：购物车是凑单决策场，是下单转化前的最后蓄水池；失效管理决定体验。
- **目标**：加购→下单转化率 ≥35%；购物车页 LCP ≤1.5s（46）。
- **非目标**：不做购物车分期/合单支付；不做收藏夹合并（收藏独立功能，48）。

## 2. 用户故事

- 作为买家，我想要把多个商品暂存购物车并统一结算，以便一次买齐。
- 作为买家，我想要购物车自动标出最优优惠组合与凑单建议，以便花得划算。
- 作为买家，我想要失效商品与可购商品分开显示，以便不被干扰。

## 3. 功能需求

| 条目 | 需求 | 优先级 |
|---|---|---|
| 13-3-1 | 加购：详情页/推荐位加购，需选 SKU；未登录加购 → 本地暂存，登录后合并 | P0 |
| 13-3-2 | 购物车分组展示：按店铺分组，组内勾选；全选/反选 | P0 |
| 13-3-3 | 数量调整：步进器（1-999，限购商品见 41/26 上限）；数量变更实时刷新价格 | P0 |
| 13-3-4 | 价格展示：小计（SKU 单价×数量）、店铺组优惠小计、全车合计；到手价口径同 19 | P0 |
| 13-3-5 | 失效管理：下架/缺货/改价商品自动移入「失效宝贝」，可一键清除或找相似（12） | P0 |
| 13-3-6 | 促销勾选：可叠加优惠默认勾选、互斥优惠二选一（19 规则），用户可改 | P1 |
| 13-3-7 | 凑单入口：距满减差额提示 + 凑单推荐（12） | P1 |
| 13-3-8 | 结算预校验：进入结算前校验库存/限购/价格变动，变动项弹窗确认 | P0 |
| 13-3-9 | 左滑删除/移入收藏 | P0 |
| 13-3-10 | 结算按钮：展示「结算(n)」与合计金额；n=勾选商品种类数（按订单拆分说明见 14） | P0 |

## 4. 数据与状态规则

- **价格快照规则**：购物车不锁价——展示实时价（19）；仅结算页有 15 分钟价格保护窗（14）。
- **合并规则**（登录后合并本地暂存）：同 SKU 累加数量；不同优惠活动分组冲突时，以「各自保留」原则展示，结算时按 19 重新计算。
- **容量**：购物车上限 120 个 SKU，超出提示先结算或清理。
- **限购**：命中限购（26/41）的商品置灰并标注「已达限购数量」。

## 5. 异常与边界

| 场景 | 处理 |
|---|---|
| 加购时商品下架瞬间 | 并发校验（49）：失败提示「手慢了，商品已下架」 |
| 多端购物车同步 | 服务端存储为准，登录设备拉取合并（本地暂存仅游客态） |
| 库存售罄但仍显示可购 | 结算预校验（13-3-8）兜底拦截 |
| 优惠活动过期 | 勾选自动取消并标注「活动已结束」，价格重算 |
| 勾选状态保存 | 按用户维度保存勾选态（服务端），跨端一致 |

## 6. 数据与埋点

- 事件：`add_cart(sku_id, source, quantity)` / `cart_view` / `cart_select_toggle` / `quantity_change` / `invalid_view` / `settle_click(n)`
- 指标：加购量、加购来源分布、购物车商品数分布、凑单转化率、失效率（失效 SKU/总 SKU）。

## 7. 依赖与接口

- 依赖：商品可售状态（08）、库存（18）、价格引擎（19）、营销（25/28）。
- 提供：`购物车 CRUD`、`结算预校验接口`（14 调用）。
