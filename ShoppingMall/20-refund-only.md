# 20 - 仅退款

## 1. 需求背景与目标

- **背景**：仅退款处理「未收到货」「商品严重问题协商不退货」等场景，是售后最快的通道；同时是薅羊毛高发区（41 联动）。
- **目标**：商家审核时效 24h 内 ≥90%（超时自动同意）；退款到账 ≤24h。
- **非目标**：不覆盖退货场景（21）；极速退款（黑卡自动同意）为 06 权益，本篇提供钩子。

## 2. 用户故事

- 作为买家，我想要在未收到货时快速退款，以便不用等待漫长沟通。
- 作为商家，我想要审核买家退款申请并附凭证驳回恶意申请，以便保护经营。
- 作为平台，我想要超时自动同意机制与风控约束，以便兜底体验与防资损。

## 3. 适用条件（入口校验）

| 条件 | 说明 |
|---|---|
| 订单状态 | PAID / SHIPPED / DELIVERED / COMPLETED（窗口见 5.3） |
| 未收到货 | SHIPPED 前直接可退；SHIPPED 后需「物流异常/拒收」佐证或商家同意 |
| 已收到货 | 仅限双方协商一致或商品严重问题（默认引导走 21 退货） |
| 退款金额 | 按 19 分摊额 + 运费规则（商家责任退运费，买家责任不退） |

## 4. 功能需求

| 条目 | 需求 | 优先级 |
|---|---|---|
| 20-4-1 | 申请流程：选仅退款 → 填原因（枚举：未收到货/空包裹/商品破损严重/协商一致/其他）→ 可附凭证（图/视频 ≤9 张）→ 提交 | P0 |
| 20-4-2 | 商家审核：同意→退款；驳回→附说明，买家可修改重新提交（≤3 次）→ 之后走 22 仲裁 | P0 |
| 20-4-3 | 超时自动同意：商家 24h（SHIPPED 前）/48h（其他）未处理 → 自动同意并退款 | P0 |
| 20-4-4 | 退款执行：原路退回（默认）或退回余额（07）；创建退款单走 15 退款链路 | P0 |
| 20-4-5 | 资产回冲：优惠券返还（25 有效期内）、积分扣回（06）、库存回补（18，若退货入库不适用） | P0 |
| 20-4-6 | 风控约束（41）：高危账号退款单人工审核；单账号 7 天仅退款率超阈值 → 限制入口 | P0 |
| 20-4-7 | 极速退款钩子：黑卡会员（06）PAID 态小额（≤100 元）自动同意 | P1 |
| 20-4-8 | 进度可视化：状态时间轴（申请→商家处理→退款中→到账） | P0 |

### 4.1 状态机

```
APPLIED（已申请）→ SELLER_AGREED → REFUNDING（退款中）→ REFUNDED（成功）
        ├→ SELLER_REJECTED → (买家改申请≤3次回 APPLIED) → ARBITRATION（22 仲裁）
        └→ AUTO_AGREED（超时自动）
REFUNDING → REFUND_FAIL → 重试/人工（15 对账）
```

## 5. 异常与边界

| 场景 | 处理 |
|---|---|
| 退款与发货竞态（同意退款瞬间发货） | 以退款单创建时间为准；已发货转 21 引导（拦截机制 17） |
| 退款失败（渠道） | 自动重试 3 次 → 人工差错工单（15 对账） |
| 买家撤销申请 | SELLER_AGREED 前可撤；之后不可撤（资金已发起） |
| 部分退款 | 本篇仅全额；部分退款 P1（按分摊 SKU 选择） |
| 风控拦截中的退款 | 冻结处理 48h，专员审核（41） |

## 6. 数据与埋点

- 事件：`refund_only_apply(reason)` / `seller_audit(result)` / `auto_agree` / `refund_success(duration)`
- 指标：仅退款率（按类目）、商家审核时长、自动同意占比、驳回后仲裁率、风控拦截率、到账时长。

## 7. 依赖与接口

- 依赖：15 退款、16 订单状态、25/06/18 资产回冲、22 仲裁、41 风控、40 通知。
- 提供：`仅退款单 CRUD`、`退款单状态查询`（39 客服可查）。
