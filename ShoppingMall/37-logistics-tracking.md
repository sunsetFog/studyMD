# 37 - 物流与跟踪

## 1. 需求背景与目标

- **背景**：物流体验占电商满意度权重大；平台需聚合多家承运商并统一轨迹模型。
- **目标**：轨迹更新延迟 ≤30 分钟；电子面单取号成功率 ≥99.5%；轨迹异常件识别率 ≥90%。
- **非目标**：不自建物流（合作承运商模式）；不做冷链温控轨迹（P2）。

## 2. 用户故事

- 作为买家，我想要实时看到包裹轨迹与预计送达时间，以便安心等待。
- 作为商家，我想要一键取号与打印面单，以便高效发货（34）。
- 作为平台，我想要统一轨迹数据与异常识别，以便履约治理（36）。

## 3. 功能需求

### 3.1 承运商对接（P0）

| 条目 | 需求 |
|---|---|
| 37-3-1 | 承运商接入：标准 API（下单/取号/轨迹订阅/取消）；支持主流快递 ≥6 家 + 平台合作寄件 |
| 37-3-2 | 电子面单：取号 → 面单数据下发（34 打印）→ 运单号绑定订单 |
| 37-3-3 | 轨迹订阅：揽收/干线/派送/签收/异常节点推送，统一节点模型 |
| 37-3-4 | 运费计算：运费模板（商家配置：包邮/固定/区域阶梯/重量计费）+ 地址库（38）解析 |

### 3.2 轨迹展示（P0）

| 条目 | 需求 |
|---|---|
| 37-3-5 | 物流卡片（16 详情页/订单列表）：承运商、单号（复制）、最新节点、预计送达 |
| 37-3-6 | 轨迹详情页：完整节点时间轴；多包裹分 Tab | 
| 37-3-7 | 关键节点通知（40）：揽收/派送中/签收/异常 |
| 37-3-8 | 预计送达时间：基于历史时效模型（准确率目标 ≥80%） |

### 3.3 异常件治理（P0）

| 异常类型 | 判定 | 处理 |
|---|---|---|
| 揽收超时 | 发货 24h 无揽收（34-4-7） | 疑似虚假发货标记 |
| 运输超时 | 超类目承诺时效 P95 | 买家可催办；商家联络承运商 |
| 派送失败 | 派送失败节点 | 通知买家联系派送员；拒收件按 21 引导 |
| 丢失/破损 | 签收异常/买家投诉 | 22 仲裁，承运商责任由商家先赔后追 |
| 回流件 | 拒收/地址错误回退 | 通知双方，商家收到后按 21 验收流程 |

## 4. 流程

```
商家发货 → 电子面单取号（绑定 order_no）→ 轨迹订阅启动
 → 节点推送 → 统一轨迹模型落库 → C 端展示 + 关键节点通知（40）
 → 签收 → 触发 16 自动确认收货倒计时
 → 异常节点 → 异常件工单 → 双方通知
```

## 5. 异常与边界

| 场景 | 处理 |
|---|---|
| 承运商接口故障 | 降级：手写单号发货（34）；轨迹延迟展示「更新中」 |
| 单号绑定错误 | 24h 可改（34-6）；跨承运商改号需重新订阅 |
| 轨迹丢失节点 | 轨迹允许乱序补传，按时间排序展示 |
| 同单多包裹部分签收 | 签收态按包裹；全部签收才触发自动确认（16） |
| 隐私面单 | 收件人手机号加密显示（面单脱敏 + 端内虚拟号，38 联动，P1） |

## 6. 数据与埋点

- 事件：`waybill_create/carrier` / `track_update(node)` / `delivery_exception(type)`
- 指标：时效达标率（按承诺）、异常件率（按承运商）、预计送达准确率、面单取号成功率、轨迹延迟分布。

## 7. 依赖与接口

- 依赖：34 发货、16 订单、38 地址库、40 通知。
- 提供：`运费计算`、`电子面单取号`、`轨迹查询/订阅`、`异常件上报`。
