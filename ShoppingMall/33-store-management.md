# 33 - 店铺管理

## 1. 需求背景与目标

- **背景**：店铺管理是商家日常经营的操作中枢（信息/商品/订单/数据的入口）；子账号分权是团队协作基础。
- **目标**：商家后台核心操作成功率 ≥99%；权限越权事件 0。
- **非目标**：不做商家 App（P1 末再议，V1 用 Web 后台）。

## 2. 用户故事

- 作为商家主账号，我想要管理店铺信息与子账号权限，以便团队分工协作。
- 作为商家，我想要一屏看到今日经营概况（待发货/待售后/异常），以便快速决策。

## 3. 功能需求

### 3.1 店铺信息管理（P0）

| 条目 | 需求 |
|---|---|
| 33-3-1 | 店铺基础信息：店名（改名校验：一年 2 次，重名/侵权校验）、Logo、简介 |
| 33-3-2 | 经营设置：客服在线时段、发货地址簿（38）、运费模板管理（37） |
| 33-3-3 | 商品类目分组（店铺内前台分组，供 31 分类导航/商品列表筛选） |
| 33-3-4 | 支付/结算信息：结算银行卡绑定（35，变更走 05 敏感操作保护） |

### 3.2 子账号与权限（P0）

| 条目 | 需求 |
|---|---|
| 33-3-5 | 子账号创建：手机号邀请，岗位模板（运营/客服/发货/财务）+ 自定义勾选（03 矩阵子集） |
| 33-3-6 | 权限变更审计：主账号操作留痕 |
| 33-3-7 | 子账号禁用/删除：即时生效，其进行中会话下线 |

### 3.3 经营工作台（P0）

| 模块 | 内容 |
|---|---|
| 今日概况 | 待发货单数（超 48h 红色预警）/待售后/待审核商品/今日 GMV |
| 待办中心 | 按优先级排序的任务列表（发货/售后/资质到期） |
| 数据摘要 | 昨日 GMV/访客/转化率趋势（45 详情报表） |
| 异常提醒 | 违规通知（43）/差评提醒（23）/库存预警（18） |

## 4. 流程：子账号授权

```
主账号创建子账号 → 选择岗位模板 → 微调权限勾选 → 生效
 → 子账号登录（04 独立会话）→ 按权限渲染后台菜单（服务端强校验 03）
 → 操作日志按子账号维度记录
```

## 5. 异常与边界

| 场景 | 处理 |
|---|---|
| 主账号被封（43） | 店铺进入「接管状态」：已有订单正常履约，禁止新发布与提现 |
| 子账号越权尝试 | 服务端拒绝 + 记录（41）；高频越权 → 冻结子账号 |
| 店名侵权投诉 | 43 流程：投诉 → 审核 → 强制改名 |
| 改名与装修/域名联动 | 店铺 ID 不变，展示名联动更新（31 配置不受影响） |
| 发货地址变更 | 仅影响之后订单，进行中订单地址不变（38 规则） |

## 6. 数据与埋点

- 事件：`store_info_update` / `subaccount_create/permission_change` / `workbench_view`
- 指标：商家日活（后台登录）、待发货超时率（36 联动）、子账号渗透率（多账号商家占比）。

## 7. 依赖与接口

- 依赖：03 权限矩阵、32 入驻、38 地址、37 运费模板、45 数据、43 处罚。
- 提供：`店铺信息查询`（C 端展示）、`权限校验服务`（03 落地执行）。

## 8. 开放问题

- 商家 App 是否 P1 交付（发货/客服移动场景强需求）？（转 51）
- 是否支持多店铺切换（集团商家）？（转 51）
