# 27 - 预售与拼团

## 1. 需求背景与目标

- **背景**：预售解决「先销后产」（定制/新品/大促蓄水），拼团解决「社交裂变获客」。两者共享下单-资金-履约的时序复杂性。
- **目标**：预售定金→尾款转化率 ≥70%；拼团开团成功率 ≥60%。
- **非目标**：不做众筹类目（P2）；不做阶梯拼团（P2）。

## 2. 预售

### 2.1 模式（P1）

| 模式 | 流程 | 定金规则 |
|---|---|---|
| 全款预售 | 全款下单 → 约定日期发货 | 无 |
| 定金预售 | 定金下单（锁价锁资格）→ 尾款期付尾款 → 发货 | 定金不退（用户违约）；商家违约双倍返还定金 |

### 2.2 功能需求

| 条目 | 需求 | 优先级 |
|---|---|---|
| 27-2-1 | 预售商品发布（08 特殊类型）：定金/总价/尾款期/发货期，详情页强提示「预售」与发货时间 | P1 |
| 27-2-2 | 尾款期：开始/结束时间；尾款期结束未付尾款 → 定金不退、订单关闭（自动） | P1 |
| 27-2-3 | 定金下单锁库存（18 锁定池，占位时长=尾款期）；付尾款走 15 | P1 |
| 27-2-4 | 商家违约（逾期发货）→ 双倍定金赔付 + 43 处罚 | P1 |
| 27-2-5 | 预售订单列表标识与尾款倒计时（16/40 提醒） | P1 |

## 3. 拼团

### 3.1 模式（P1）

- 拼团价低于单买价；开团者先下单支付 → 邀请好友参团（分享卡片/链接）→ 成团人数满足 → 全员发货；人数不满 → 到期自动全额退款。

### 3.2 功能需求

| 条目 | 需求 | 优先级 |
|---|---|---|
| 27-3-1 | 拼团配置：拼团价/成团人数（2-10）/有效期（默认 24h）/参团上限（每人限 1） | P1 |
| 27-3-2 | 开团：支付成功即开团，生成团号；分享卡片（29/30 渠道） | P1 |
| 27-3-3 | 参团：加入已有团（剩余名额展示）；成团即时性校验（最后一单支付成功瞬间成团，竞态见 5） | P1 |
| 27-3-4 | 成团 → 团内订单批量转 PAID 发货流（34）；团员各自订单独立售后（20/21） | P1 |
| 27-3-5 | 拼团失败：到期未成团 → 全额原路退款（15）+ 券/积分返还；失败通知（40） | P1 |
| 27-3-6 | 「团状态可视化」：进度条（2/3 人）、剩余时间 | P1 |
| 27-3-7 | 虚拟成团（最后一小时内机器人补位，商家可选开） | P2 |

## 4. 流程：拼团资金时序

```
开团者支付 → 订单 PAID_HOLDED（拼团待定，资金按普通支付）
参团者支付 → 成团判定 → 成团：订单转 PAID → 发货
                        → 超时未成团：全员退款（15 原路）
```

## 5. 异常与边界

| 场景 | 处理 |
|---|---|
| 最后一人支付成功瞬间前一人退款 | 串行化：成团判定前禁止退款操作（49 锁）；已退款则该人支付失败 |
| 成团后一人退款 | 仅该人退，团不解散；剩余成员继续履约（业务规则） |
| 拼团链接过期点击 | 引导重新开团 |
| 自买自团（刷单） | 41 关联账号识别：命中则不成团/退款 + 43 处罚 |
| 预售+秒杀叠加 | 禁止叠加（08 发布校验，一种活动类型） |

## 6. 数据与埋点

- 事件：`presale_deposit_paid` / `presale_final_paid` / `presale_default` / `group_open` / `group_join` / `group_success|fail`
- 指标：定金转化率、尾款逾期率、开团率/成团率/平均成团时长、拼团裂变系数（新客/开团数）、失败退款金额。

## 7. 依赖与接口

- 依赖：14/15 下单支付、18 锁定池、34 发货、40 分享与提醒、41 反刷。
- 提供：`拼团单状态查询`、`成团事件`（发货/结算消费）。
