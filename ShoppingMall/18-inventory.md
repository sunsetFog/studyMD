# 18 - 库存体系

## 1. 需求背景与目标

- **背景**：库存决定「能不能买到」，超卖是资损事故，虚占是转化杀手。
- **目标**：超卖率 0（强约束）；下单链路库存操作 P99 < 100ms（46）。
- **非目标**：不做商家多仓调拨优化（P2）；不做需求预测补货（P2）。

## 2. 数据模型

### 2.1 库存层级（P0）

```
商家总库存（可售池）
  ├─ 可售库存 available（展示与购买依据）
  ├─ 锁定/预占 locked（下单未支付 15 分钟）
  └─ 已扣减 deducted（支付成功，等待出库核销）
```

| 字段 | 说明 |
|---|---|
| `sku_id` | 库存归属 SKU（08） |
| `total` | 商家设置的总量 |
| `available / locked / deducted` | 三个池子，恒等式：`total = available + locked + deducted - 已出库` |
| `safety_stock` | 商家安全库存（低于阈值自动下架提示，P1） |

### 2.2 操作原子性（P0）

所有库存变更必须**原子操作**（单 SKU 行级锁/原子指令），禁止「读-算-写」三步式更新（超卖根源）。见《49》并发约定。

## 3. 功能需求

| 条目 | 需求 | 优先级 |
|---|---|---|
| 18-3-1 | 预占：下单成功即预占（14），15 分钟超时自动释放；支付成功转实扣 | P0 |
| 18-3-2 | 释放：关单/取消/超时自动释放，幂等（重复释放不可回补超量） | P0 |
| 18-3-3 | 库存校验：详情页展示（09 三态）、结算页强校验、支付回调后二次校验（预占期内被冻结库存场景） | P0 |
| 18-3-4 | 商家调库存：后台加减库存（+为补货，-为盘亏），全量流水可查 | P0 |
| 18-3-5 | 缺货自动下架：available=0 且 locked=0 → 自动下架（08 状态机）；补货自动恢复 | P0 |
| 18-3-6 | 限购库存联动：单用户限购量校验（41/26），预占时一并校验 | P0 |
| 18-3-7 | 库存预警：低于安全库存通知商家（40），低于阈值不影响售卖 | P1 |
| 18-3-8 | 区域库存（按仓发货，37 分仓路由） | P2 |

## 4. 流程

```
下单：校验 available ≥ n → available-=n, locked+=n（原子）
支付：locked-=n, deducted+=n（原子）→ 出库核销：deducted-=0（出库即减）
关单：locked-=n, available+=n（原子，幂等）
退款：COMPLETED 后退货重新入库 → available+=n（21 验收合格后，P1 自动）
```

**秒杀特例（26）**：秒杀库存独立池，预热时从主库存划拨；结束后未售出回拨主库存。

## 5. 异常与边界

| 场景 | 处理 |
|---|---|
| 并发抢购同 SKU | 原子扣减，失败即「库存不足」，排队策略由 46 削峰 |
| 释放重复消息（MQ 重投） | 幂等键 `order_no+action`，见《49》 |
| 对账发现账实不符 | 每日任务：流水重放校验恒等式，不符告警 + 生成盘点工单 |
| 商家误加超量库存 | 允许（商家自负）；系统提示异常波动 |
| 支付回调时预占已释放（超时关单竞态） | 15 章竞态规则：退款路径；库存可用性由释放幂等保证 |

## 6. 数据与埋点

- 事件：`stock_prelock` / `stock_deduct` / `stock_release` / `stock_manual_adjust`
- 指标：预占成功率、超时释放量、锁库存峰值（秒杀水位）、账实差异数（目标 0）、缺货下架量。

## 7. 依赖与接口

- 依赖：08 商品（SKU）、14 下单、16 订单状态事件、26 秒杀。
- 提供：`库存校验`、`预占/实扣/释放`、`库存流水查询`（35/42/41 审计）。
