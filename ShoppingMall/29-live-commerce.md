# 29 - 直播电商

## 1. 需求背景与目标

- **背景**：直播是「人带货」的高转化场：讲解冲动消费 + 限时限量 + 主播信任背书。
- **目标**：直播间→下单转化率 ≥5%；挂链商品点击率 ≥15%。
- **非目标**：不做自建直播推流基础设施（用第三方直播云，本篇只做交易与互动产品层）。

## 2. 用户故事

- 作为买家，我想要边看直播边买，点击讲解中的商品直接下单，以便即时决策。
- 作为商家/主播，我想要在直播间挂商品卡与发券，以便转化讲解流量。
- 作为平台，我想要直播内容与商品合规可控，以便降低虚假宣传风险。

## 3. 功能需求

### 3.1 直播间（P1）

| 条目 | 需求 |
|---|---|
| 29-3-1 | 开播：商家/达人实名开播（07 实名 + 平台直播协议）；开播设置标题/封面/类目 |
| 29-3-2 | 播放器：拉流播放、清晰度切换、连麦（P2）、回放（P1） |
| 29-3-3 | 互动：评论/点赞/进场横幅；评论机审（42 词库+频控） |
| 29-3-4 | 商品卡：右侧商品列表（讲解中置顶标记）；点击弹商品卡→下单（不离开直播间或小窗，可配置） |
| 29-3-5 | 讲解锁定：主播「讲解中」商品置顶+呼吸灯；历史讲解商品列表可回看 |
| 29-3-6 | 直播专属价/专属券：挂链商品可用直播价（26 库存池机制复用）与直播间专属券（25 定向发放） |

### 3.2 交易联动（P0 关键点）

| 条目 | 需求 |
|---|---|
| 29-3-7 | 下单流程：直播间下单走 14 标准链路（快照/库存/优惠一致），订单来源标记 `channel=live`（归因） |
| 29-3-8 | 库存抢购：直播限量商品走 26 排队机制（讲解瞬间流量峰值） |
| 29-3-9 | 售后归因：直播订单售后率单独统计（36 评分不受直接惩罚，运营侧分析） |

### 3.3 治理（P0）

| 条目 | 需求 |
|---|---|
| 29-3-10 | 实时审核：内容画面抽帧审核 + 语音转文字审核（42），违规即时告警与断播（43） |
| 29-3-11 | 宣传管控：禁绝对化用语（机审）、禁功效承诺（类目敏感词库） |
| 29-3-12 | 录屏存证：全程录制保留 ≥60 天（22 仲裁举证材料） |

## 4. 流程：直播下单

```
观众看到商品卡 → 点击（无需退出直播间）→ 详情卡（SKU/价/库存实时）
 → 下单（标准链路，来源归因 live）→ 支付 → 主播端实时成交提示音（可选）
```

## 5. 异常与边界

| 场景 | 处理 |
|---|---|
| 直播中断/黑屏 | 播放器自动重连 3 次；交易入口不受影响 |
| 讲解商品售罄 | 商品卡实时置灰「已抢完」 |
| 主播违规断播 | 直播间冻结，已生成订单正常履约；回放下架（43） |
| 直播价与结算价不一致 | 一切以 19 结算为准；主播端报价与系统价差异 >5% 告警 |
| 弹幕刷屏攻击 | 频控 + 精华评论模式兜底 |

## 6. 数据与埋点

- 事件：`live_view(live_id, duration)` / `product_card_click(item_id)` / `live_order(channel=live)` / `comment_send`
- 指标：观看人数/时长、在线峰值、挂链 CTR、转化率、GMV/GPM（千次观看成交额）、违规断播次数。

## 7. 依赖与接口

- 依赖：直播云、14/15/18 交易链路、26 排队、25 定向券、42 实时审核、40 互动消息。
- 提供：`直播间商品上下文`（下单归因）。
