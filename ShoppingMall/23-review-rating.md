# 23 - 评价体系

## 1. 需求背景与目标

- **背景**：评价是买家决策依据与商家服务质量的反馈回路；同时是刷单与恶意差评的重灾区。
- **目标**：订单评价率 ≥30%；评价审核自动化率 ≥95%；恶意差评申诉处理 ≤48h。
- **非目标**：不做评价带货返现引导（违规，43）；不做匿名评价强制（默认脱敏昵称）。

## 2. 用户故事

- 作为买家，我想要对订单打分并写下真实体验，以便帮助他人决策。
- 作为买家，我想要看到真实有用的评价（带图、按相关度排序），以便快速参考。
- 作为商家，我想要回复评价并对恶意评价申诉，以便维护店铺信誉。

## 3. 功能需求

### 3.1 发布评价（P0）

| 条目 | 规则 |
|---|---|
| 23-3-1 | 评分维度：整体 1-5 星（主分）；可选标签（描述相符/物流/服务 各 1-5，聚合为 DSR 36） |
| 23-3-2 | 内容：文字 ≤500 字 + 图 ≤9 张 + 视频 ≤1（60s） |
| 23-3-3 | 评价窗口：确认收货后 90 天；默认好评规则——确认收货后 15 天未评 → 系统默认好评（不计入晒图统计） |
| 23-3-4 | 追评：首评后 30 天内一次追评（使用一段时间后的补充） |
| 23-3-5 | 脱敏：买家昵称默认展示脱敏（「张**」）；可选完全匿名 |
| 23-3-6 | 审核：先发后审 or 先审后发——按账号风险分级（41）：正常用户先发后审，高危先审后发 |

### 3.2 展示与排序（P0）

| 条目 | 规则 |
|---|---|
| 23-3-7 | 详情页评价区（09）：好评率（≥10 条才展示，23/09 规则）+ 标签云（「质量好 x125」）+ 按类目分组（全部/带图/追评/差评） |
| 23-3-8 | 排序：默认「有用数+权重」排序；差评置顶强制规则——前 3 条中至少 1 条中差评（决策公平性） |
| 23-3-9 | 「有用」点赞：买家对评价点赞，累计影响排序 |
| 23-3-10 | 敏感信息过滤：评价中手机号/微信号等自动脱敏（防导流，42 词库） |

### 3.3 商家互动（P1）

- 商家回复：每条评价可回复一次（≤500 字），展示在评价下方。
- 恶意评价申诉：商家可申诉（证据：聊天记录显示买家勒索等），48h 平台裁决（43），核实后评价屏蔽且不计分。

## 4. 流程：默认好评与追评

```
确认收货 → 评价窗口开启(90天) → 用户评价/15天默认好评
 → 首评后追评窗口(30天) → 追评
 → 90 天窗口关闭
```

## 5. 异常与边界

| 场景 | 处理 |
|---|---|
| 刷好评识别 | 41：同设备/同 IP 批量、订单金额异常小的「刷单评价」不计入好评率与销量 |
| 恶意差评（未收到货就打差评） | 商家申诉 + 仲裁 |
| 评价中含违规内容 | 42 机审拦截；已发布的可被举报下架（43） |
| 部分退款订单 | 已评价不删除；退款后评价保留但标记「已退款」（透明度） |
| 评价图片含个人隐私 | 42 人脸/证件检测，命中屏蔽 |

## 6. 数据与埋点

- 事件：`review_submit(stars, has_media)` / `review_like` / `merchant_reply` / `review_appeal`
- 指标：评价率、带图率、好评率分布（店铺/类目）、默认好评占比（异常监控）、申诉量与翻案率。

## 7. 依赖与接口

- 依赖：16 订单完成事件、42 审核引擎、41 风控、43 处罚。
- 提供：`店铺/商品评分聚合查询`（09/36 消费）、`DSR 三维分数`（36 依据）。

## 8. 开放问题

- 评价「商家删除差评」需严防——申诉屏蔽是否需双人工复核？（转 51）
- 是否展示「评价者购买同店次数」（识别铁粉评价）？（转 51）
