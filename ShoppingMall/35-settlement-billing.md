# 35 - 结算与账单

## 1. 需求背景与目标

- **背景**：结算把 GMV 变成商家真实收入；佣金规则、退款冲抵、对账精度是资金安全核心。
- **目标**：结算差错 0（每日对账）；结算单生成时效 T+1；商家账单疑问响应 ≤48h。
- **非目标**：不做提前放款/供应链金融（P2 合规另评）。

## 2. 用户故事

- 作为商家，我想要清楚看到每笔订单的佣金与实际到账，以便经营核算。
- 作为商家，我想要按周期提现货款，以便资金周转。
- 作为财务，我想要自动化对账与差错处理，以便资金安全。

## 3. 结算模型

### 3.1 资金流（P0）

```
买家支付 → 支付渠道 → 平台收款账户（代收）
 → 订单 COMPLETED（16）→ 进入可结算池（T+1）
 → 扣除：佣金（类目费率 10）+ 营销费用分摊（商家承担券 25）+ 违约赔付（43）
 → 生成结算单 → 可提现余额（07 钱包）→ 商家提现
 → 退款：从可结算池/余额冲抵（不足则挂负）
```

### 3.2 结算周期（P0）

| 项 | 规则 |
|---|---|
| 结算时点 | 订单确认收货（或自动确认）后 T+1 生成结算明细 |
| 结算周期 | 自然周/自然月两种模式（商家入驻时选定） |
| 提现 | 结算单生效后可提现（07 提现链路） |
| 售后冻结 | 售后中订单款项冻结（07），仲裁/退款后按结果结算 |

### 3.3 费用明细（P0）

| 费用 | 计算 | 说明 |
|---|---|---|
| 技术服务费（佣金） | 实付金额 × 类目费率（10 配置，0.5%-5%） | 按单计；退款按比例退佣 |
| 营销费用 | 商家承担的券/活动补贴（25/28） | 结算时冲减 |
| 物流费用 | 平台合作寄件运费（21 逆向） | 按使用扣减 |
| 违约赔付 | 延迟发货赔付（43） | 按单扣 |

## 4. 功能需求

| 条目 | 需求 | 优先级 |
|---|---|---|
| 35-4-1 | 结算单生成任务：T+1 批处理（幂等，重跑不重复生成），按商家+周期聚合 | P0 |
| 35-4-2 | 账单查询：明细级（每订单：实付/佣金/营销费/实际入账）；可导出 CSV | P0 |
| 35-4-3 | 余额与提现：可提现余额 = 结算生效额 - 提现中 - 冻结（07 联动）；提现走 07 | P0 |
| 35-4-4 | 退款冲抵：退款发生 → 原结算单冲抵或负数账单；提现已发生则挂应收（后续结算扣减） | P0 |
| 35-4-5 | 对账：平台内部（订单-结算-钱包）每日三方对账，差异 0 容忍，告警出工单 | P0 |
| 35-4-6 | 发票：平台向商家开「技术服务费」发票；商家开票给买家（16-3-9） | P1 |
| 35-4-7 | 账单争议工单：商家对账单疑问发起工单（39），财务 48h 响应 | P1 |

## 5. 流程

```
订单 COMPLETED → T+1 结算批任务（幂等）
 → 明细入账（佣金/营销/赔付逐项）→ 周期结算单 → 余额可提现
 → 退款事件 → 冲抵（幂等）→ 对账任务 → 差异工单
```

## 6. 异常与边界

| 场景 | 处理 |
|---|---|
| 结算任务失败重跑 | 幂等键（商家+周期+版本），见《49》 |
| 退款金额 > 当期结算 | 挂负应收，后续结算优先冲抵；提现禁止至冲平 |
| 商家保证金不足扣罚（32） | 保证金欠款 → 从货款结算优先划补 |
| 结算期间商家违规冻结提现（43） | 冻结到期自动解除；仲裁案按 22 处置 |
| 渠道退款与结算竞态 | 以内部流水为准，渠道对账兜底（15 对账） |

## 7. 数据与埋点

- 指标：日结算总额、佣金收入、结算差错数（目标 0）、提现成功率、负应收商家数、账单工单量。

## 8. 依赖与接口

- 依赖：16 订单完成事件、10 佣金率、25/28 营销分摊、07 钱包/提现、22 仲裁资金划扣。
- 提供：`结算单查询`、`余额明细`、`对账接口`（财务后台）。
