# 08 - 商品发布

## 1. 需求背景与目标

- **背景**：商品发布是商家侧最高频操作，质量决定搜索、推荐、交易全链路的数据基础。
- **目标**：平均发布耗时 ≤ 5 分钟（标准类目）；审核通过率 ≥ 90%；字段完整率 ≥ 98%。
- **非目标**：不做批量导入模板编辑器（P2）；不做跨平台搬家工具。

## 2. 用户故事

- 作为商家，我想要按类目引导填写商品信息，以便一次发布成功。
- 作为商家，我想要为商品设置多规格 SKU 与独立库存价格，以便差异化售卖。
- 作为运营，我想要商品数据结构规范统一，以便搜索/推荐/比价等下游直接消费。

## 3. 数据模型

### 3.1 SPU / SKU（P0）

| 概念 | 定义 | 示例 |
|---|---|---|
| SPU | 标准产品单元，一个商品主体 | 「XX 手机 墨绿色 256G」为一个 SPU？——否：SPU=「XX 手机 型号」 |
| SKU | 最小销售单元（规格组合） | 「墨绿色/256G」「白色/128G」为同 SPU 下两个 SKU |
| 规格属性 | 组成 SKU 的维度（颜色/容量） | 类目约束可选属性（10） |

### 3.2 商品关键字段（P0）

| 字段 | 规则 | 校验 |
|---|---|---|
| 标题 | ≤60 字符，禁极限词（「最」「第一」43 违禁词库） | 机审（42） |
| 类目 | 必须选叶子类目（10）；商品属性由类目驱动 | 系统校验 |
| 主图 | 1-5 张，800×800 起，第一张白底（可选） | 尺寸/比例校验 |
| 详情图 | ≤20 张，单张 ≤3MB | 合规机审 |
| SKU 价格 | 0.01-999999 元 | 类目限价区间 |
| SKU 库存 | ≥1 才可上架；库存模型见《18》 | 系统校验 |
| 运费模板 | 引用 37 章运费模板（包邮/固定/区域阶梯） | 必选 |
| 售后模板 | 7 天无理由（默认开）/ 15 天 / 定制类不可退 | 按类目约束 |

## 4. 功能需求

| 条目 | 需求 | 优先级 |
|---|---|---|
| 08-4-1 | 类目引导式发布：选类目 → 动态渲染该类目必填属性表单 | P0 |
| 08-4-2 | 多规格生成器：勾选规格维度 → 自动笛卡尔积生成 SKU 表（≤2 维×各 20 值） | P0 |
| 08-4-3 | 草稿箱：自动保存，草稿保留 30 天 | P0 |
| 08-4-4 | 提交后进入审核（42），审核中可看不可售；驳回给出原因与修改入口 | P0 |
| 08-4-5 | SKU 独立条码（商家编码）与库存联动（18） | P0 |
| 08-4-6 | 商品编辑：审核通过后改价格/库存即时生效；改标题/类目/规格需重新审核 | P0 |
| 08-4-7 | 上下架：下架即时生效，已生成订单不受影响；上架走状态机 | P0 |
| 08-4-8 | 商品复制（同店复制，改 20% 以上字段才能提交，防铺货泛滥） | P1 |
| 08-4-9 | 类目推荐：输入标题自动推荐类目（准确率目标 ≥80%） | P1 |
| 08-4-10 | 多多店铺批量工具 | P2 |

### 4.1 商品状态机

```
草稿 → 待审核 →(通过)→ 在售 →(手动/违规)→ 下架
        │驳回→ 草稿（附驳回原因）
在售 → 缺货下架（全部 SKU 库存=0 自动触发，18）
```

## 5. 异常与边界

| 场景 | 处理 |
|---|---|
| 重复提交（双击/网络重试） | 提交幂等键，见《49》 |
| 笛卡尔积 SKU 超限 | 截止 2 维 × 20 值；超出提示拆分商品 |
| 类目已禁售（43/10） | 提交被拦，提示替代类目 |
| 编辑与审核并发（审核通过瞬间商家又改） | 版本号控制：审核针对版本快照；编辑生成新版本重新排队 |
| 在售商品被违规下架 | 通知商家（40），购物车中标记失效（13） |

## 6. 数据与埋点

- 事件：`publish_start/submit/audit_pass/audit_reject/listing`（按类目维度统计）
- 指标：发布耗时分布、驳回原因 TopN、SKU 数分布、上架商品数（商家活跃度核心指标）。

## 7. 依赖与接口

- 依赖：类目中心（10）、审核引擎（42）、库存中心（18）、运费模板（37）。
- 提供：`SPU/SKU 查询`、`商品可售状态校验` 给交易域与搜索。
