# 22 - 交易纠纷与平台仲裁

## 1. 需求背景与目标

- **背景**：买家与商家协商失败后需要平台介入；仲裁质量决定平台信任度。
- **目标**：仲裁受理 ≤2h；结案 ≤72h（复杂案 ≤5 天）；仲裁后投诉率 ≤5%。
- **非目标**：不做仲裁员自由裁量的大面板（标准化的举证清单制，保证一致性）。

## 2. 用户故事

- 作为买家，我想要在商家驳回退款时请平台评判，以便获得公正处理。
- 作为商家，我想要在买家恶意退款时提交证据，以便免受不白损失。
- 作为平台，我想要标准化举证清单与判例库，以便仲裁结果可预期、可复用。

## 3. 进入仲裁的条件

| 来源 | 条件 |
|---|---|
| 仅退款驳回 | 20：买家修改申请 3 次仍被驳回 |
| 退货验收争议 | 21：验收不合格驳回 |
| 发货纠纷 | 34：延迟发货/虚假发货投诉 |
| 客服升级 | 39：双方协商失败，客服转仲裁 |

## 4. 功能需求

| 条目 | 需求 | 优先级 |
|---|---|---|
| 22-4-1 | 仲裁申请：说明争议点 + 全量证据上传（订单快照、聊天记录自动带入） | P0 |
| 22-4-2 | 举证期：对方 48h 内提交反驳证据；举证期锁定订单状态（不自动关单/退款） | P0 |
| 22-4-3 | 仲裁员处理台：案件队列、争议焦点展示、双方证据对照、历史判例参考 | P0 |
| 22-4-4 | 裁决模板：按争议类型给出标准裁决项（退款全额/部分退款/驳回/补偿券），需选理由 | P0 |
| 22-4-5 | 资金处置：裁决退款→冻结资金直接划扣（07 冻结解冻）；裁决商家胜→解冻 | P0 |
| 22-4-6 | 结果执行与通知：双方同步通知（40），附裁决理由 | P0 |
| 22-4-7 | 复议：任一方 72h 内可复议一次（更高级别仲裁员复核），复议终局 | P1 |
| 22-4-8 | 判例库沉淀：裁决记录结构化入库，同类案件推荐参考（内部） | P1 |
| 22-4-9 | 恶意仲裁识别（41）：高频败诉申请方限流 | P1 |

## 5. 争议类型与裁决标准（摘要）

| 争议类型 | 默认裁决倾向 |
|---|---|
| 未收到货（物流无轨迹/超期） | 支持买家全额退款；有签收轨迹 → 双方举证签收人 |
| 虚假发货（有单号无揽收） | 支持买家；商家按 43 处罚 |
| 质量争议 | 双方举证；商家无质检凭证 + 买家有实拍 → 支持买家退款（退货） |
| 验收标准争议 | 以 21 章验收标准清单为准 |
| 恶意仅退款（买家证据不足） | 驳回；账号行为进入 41 画像 |

## 6. 流程

```
申请 → 受理(2h 内分派) → 锁单+冻结相关资金 → 举证期(48h)
 → 仲裁员裁决(模板化) → 资金执行 → 双方通知
 → (可选)复议 → 终局
```

## 7. 异常与边界

| 场景 | 处理 |
|---|---|
| 举证期双方均未补充 | 依据现有证据裁决 |
| 案件积压 | 优先级排序（资金额/等待时长），超 72h 未结案升级告警（46） |
| 仲裁期间订单状态变更冲突 | 锁单规则：仲裁中禁止双方执行资金类操作 |
| 裁决金额 > 商家保证金 | 保证金划扣 + 欠款追缴（32/35 联动，43 处罚） |
| 仲裁员利益冲突（同店高频案件） | 分派规则规避 |

## 8. 数据与埋点

- 指标：仲裁案件量/结案时长/各类型占比、买家支持率与商家支持率（平衡监控）、复议翻案率（仲裁质量指标）、恶意案件识别率。

## 9. 依赖与接口

- 依赖：16 锁单、07 资金冻结、39 客服升级、41 画像、40 通知。
- 提供：`仲裁案件 CRUD`、`裁决执行`（资金/状态变更统一出口）。
