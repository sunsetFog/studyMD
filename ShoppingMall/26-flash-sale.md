# 26 - 秒杀 / 限时抢购

## 1. 需求背景与目标

- **背景**：秒杀是瞬时高并发场景（瞬时 QPS 可为日常 100 倍），核心是「不超卖、不崩、体验公平」。
- **目标**：峰值下单成功率 ≥95%（排除售罄）；超卖 0；服务可用性 100%（46 降级预案）。
- **非目标**：不做万人团/整点签到抢福利（P2）。

## 2. 用户故事

- 作为买家，我想要在整点公平抢到低价商品，以便获得实惠。
- 作为商家，我想要报名秒杀并限定库存，以便低成本引爆单品销量。
- 作为平台，我想要秒杀不拖垮全站，以便大促日整体稳定。

## 3. 功能需求

| 条目 | 需求 | 优先级 |
|---|---|---|
| 26-3-1 | 场次管理：运营创建场次（如 20:00 场），商品报名审核（28 报名流），预热展示（开始前 24h） | P0 |
| 26-3-2 | 秒杀价与库存池：商家设秒杀价与限购量；独立库存池（从 18 主库存划拨，活动结束回拨） | P0 |
| 26-3-3 | 限购：每人每场次每 SKU 限购（默认 1，可配 1-5）；风控黑名单禁入（41） | P0 |
| 26-3-4 | 预热倒计时：开始前页面倒计时，禁止提前下单；到点开闸 | P0 |
| 26-3-5 | 排队与削峰：进入后置统一排队（46 削峰层），前端展示「排队中」进度 | P0 |
| 26-3-6 | 抢购结果：成功→锁定订单 5 分钟支付（15-3-1 特例）；失败→「已抢完」+ 候补提示（有人放弃即时释放） | P0 |
| 26-3-7 | 售罄兜底：详情页自动转「已结束」态 + 相似商品推荐（12） | P0 |
| 26-3-8 | 秒杀日历/会场页：按场次聚合所有商品，分类目 Tab | P1 |
| 26-3-9 | 候补队列：售罄后登记候补，释放库存按序递补（≤1.2 倍库存量） | P1 |

## 4. 流程与容量策略

```
预热(24h) → 开场 → 请求进入排队削峰(46) → 库存原子扣减(18)
 ├─ 成功 → 订单创建(14 快照价) → 5 分钟支付窗口 → 超时释放回池
 └─ 失败 → 售罄提示 / 候补登记
活动结束 → 未售库存回拨主库存(18)
```

**容量三板斧**（产品需求侧的约束，技术实现见 46）：
1. 库存读多写少：预热期静态化详情数据。
2. 下单限流：单 SKU 峰值 QPS 上限配置，超出进入排队。
3. 支付超时短窗口（5 分钟）快速回血库存。

## 5. 异常与边界

| 场景 | 处理 |
|---|---|
| 开场瞬间雪崩 | 排队 + 限流 + 静态兜底（46 分级预案） |
| 机器人抢购 | 41 设备指纹 + 行为验证码前置；异常账号秒杀资格取消 |
| 支付超时库存回池并发 | 18 释放幂等 + 候补递补原子操作 |
| 秒杀价低于成本（商家失误） | 报名时校验秒杀价 ≥ 门槛（可配，防资损纠纷） |
| 活动中商品被违规下架（43） | 场次实时摘除，已下单订单不受影响 |

## 6. 数据与埋点

- 事件：`flash_view(session)` / `flash_attempt(sku_id)` / `flash_win` / `flash_fail(reason)` / `flash_pay_timeout`
- 指标：峰值 QPS、抢购成功率、支付转化（抢到→支付）、候补转化率、限流触发次数、秒杀 GMV。

## 7. 依赖与接口

- 依赖：18 库存独立池、14 下单快照、15 短支付窗、41 风控、46 削峰、28 会场。
- 提供：`场次/商品查询`、`抢购入口`。
