# 23 · List 实现详解

## 1. ArrayList

### 底层结构

```java
transient Object[] elementData;   // 存储数组
private int size;                 // 实际元素数
private static final int DEFAULT_CAPACITY = 10;
```

### 扩容机制

1. 首次 `add` 时，`elementData` 从 `DEFAULTCAPACITY_EMPTY_ELEMENTDATA` 扩容到 **10**（懒初始化）。
2. 容量不足时：`newCapacity = oldCapacity + (oldCapacity >> 1)`，即 **1.5 倍**。
3. `Arrays.copyOf` 复制到新数组（O(n)）。
4. 若新容量仍不够，直接用所需最小容量。

```java
// 扩容核心（JDK 源码简化）
private Object[] grow(int minCapacity) {
    int oldCapacity = elementData.length;
    int newCapacity = oldCapacity + (oldCapacity >> 1);   // 1.5x
    if (newCapacity - minCapacity < 0) newCapacity = minCapacity;
    return elementData = Arrays.copyOf(elementData, newCapacity);
}
```

### 常用操作复杂度

| 操作 | 复杂度 | 说明 |
|---|---|---|
| `get(i)` / `set(i, e)` | O(1) | 数组随机访问 |
| `add(e)` | O(1) 均摊 | 尾部追加，扩容时 O(n) |
| `add(i, e)` | O(n) | 需要移动后续元素 |
| `remove(i)` | O(n) | 移动后续元素 |
| `remove(Object)` | O(n) | 先查找再移动 |
| `contains` | O(n) | 线性扫描 |
| `indexOf` | O(n) | |
| `iterator` | O(1) | |

### 使用建议

```java
// 1. 预估容量，避免多次扩容
List<User> users = new ArrayList<>(1000);

// 2. 批量删除用 removeIf（内部一次遍历 + 一次移动）
list.removeIf(u -> u.isDeleted());

// 3. 头部插入多 → 换 LinkedList 或 ArrayDeque
// 4. 频繁 contains → 换 HashSet
```

### 遍历性能

```java
// 普通 for：直接数组访问，最快
for (int i = 0, n = list.size(); i < n; i++) { list.get(i); }

// 增强 for：内部用 Itr，有 modCount 检查，略慢但可读
for (User u : list) { }

// forEach：内部仍是索引遍历 + Lambda 调用，JIT 后接近普通 for
list.forEach(this::handle);
```

## 2. LinkedList

### 底层结构

```java
transient int size;
transient Node<E> first;
transient Node<E> last;

private static class Node<E> {
    E item;
    Node<E> next;
    Node<E> prev;
}
```

双向链表，同时实现 `List` 与 `Deque`。

### 复杂度

| 操作 | 复杂度 |
|---|---|
| `get(i)` | O(n)（从头或尾遍历，取近端） |
| `add(e)` | O(1) |
| `addFirst/addLast` | O(1) |
| `removeFirst/removeLast` | O(1) |
| `remove(Object)` | O(n)（先找） |
| `contains` | O(n) |

### 实际性能陷阱

```java
// 极慢：每次 get 都是 O(n)，整体 O(n²)
for (int i = 0; i < list.size(); i++) {
    process(list.get(i));
}
// 且 list.size() 每次调用是 O(1)，但 get(i) 是 O(n)
```

正确：用迭代器或增强 for（O(n)）。

### LinkedList 的真实定位

**几乎不应该用**：

- 作为 List：随机访问差、内存开销大（每个元素 24+ 字节 vs ArrayList 4-8 字节引用）。
- 作为 Deque：`ArrayDeque` 更快、内存更省。
- 唯一优势：中间插入/删除已知节点 O(1)，但 Java 的 List 接口不暴露节点，实际拿不到这个优势。

```java
// 结论：需要队列/栈 → ArrayDeque；需要 List → ArrayList
Deque<Task> queue = new ArrayDeque<>();
```

## 3. CopyOnWriteArrayList

### 原理

写操作时复制整个数组，读操作无锁（读旧数组）。

```java
public boolean add(E e) {
    synchronized (lock) {
        Object[] es = array;
        int len = es.length;
        es = Arrays.copyOf(es, len + 1);
        es[len] = e;
        array = es;
        return true;
    }
}
```

### 特性

| 维度 | 说明 |
|---|---|
| 读 | 无锁，极快 |
| 写 | 加锁 + 全量复制，O(n) |
| 内存 | 写时双倍占用，频繁写会 GC 压力大 |
| 迭代器 | 快照，遍历期间的修改不可见，**不会** ConcurrentModificationException |
| 一致性 | 弱一致（读到的是某个时刻的快照） |

### 适用场景

- **读多写极少**：监听器列表、白名单、配置项、路由表。
- 事件回调注册表。

```java
private final List<Listener> listeners = new CopyOnWriteArrayList<>();

public void register(Listener l) { listeners.add(l); }

public void fire(Event e) {
    for (Listener l : listeners) l.onEvent(e);   // 遍历时新增不会影响本次
}
```

### 不适用

- 写频繁（每次 add 都复制整个数组）。
- 数据量大（内存翻倍）。
- 需要强一致性的场景。

## 4. Vector 与 Stack（遗留）

```java
Vector<String> v = new Vector<>();    // 所有方法 synchronized
Stack<String> s = new Stack<>();      // 继承 Vector
```

为什么不推荐：

- 全表锁，单线程也付同步成本。
- Stack 的 `push/pop/peek` 与 `List` API 混杂。
- 迭代器不是 fail-safe，仍需手动同步。

替代：

```java
List<String> list = Collections.synchronizedList(new ArrayList<>());  // 仍不推荐
List<String> cow = new CopyOnWriteArrayList<>();
Deque<String> stack = new ArrayDeque<>();
```

## 5. List 常用操作片段

```java
// 去重（保持顺序）
List<String> distinct = new ArrayList<>(new LinkedHashSet<>(list));

// 排序
list.sort(Comparator.comparing(User::getAge).reversed());
list.sort(null);                      // 自然序，要求元素 Comparable
list.sort(Comparator.naturalOrder());

// 反转
Collections.reverse(list);

// 打乱
Collections.shuffle(list);

// 不可变视图
List<String> ro = Collections.unmodifiableList(list);

// 分页
List<String> page = list.subList(from, Math.min(to, list.size()));

// 交换
Collections.swap(list, i, j);

// 填充
Collections.fill(list, defaultValue);

// 最大/最小
Collections.max(list);
Collections.min(list, comparator);

// 二分查找（必须先排序）
Collections.binarySearch(sortedList, key);

// 批量添加
list.addAll(other);

// 交集/并集/差集
List<String> intersection = new ArrayList<>(a); intersection.retainAll(b);
List<String> union = new ArrayList<>(a); union.addAll(b);
List<String> diff = new ArrayList<>(a); diff.removeAll(b);
```

> `retainAll`/`removeAll` 对 ArrayList 是 O(n*m)，大数据量用 `HashSet` 优化。

## 6. subList 陷阱

```java
List<String> list = new ArrayList<>(List.of("a","b","c","d"));
List<String> sub = list.subList(1, 3);     // 视图，不是拷贝

sub.set(0, "B");          // 影响原 list → [a, B, c, d]
list.add("e");            // 结构性修改
sub.get(0);               // ConcurrentModificationException

// 正确：需要独立副本
List<String> copy = new ArrayList<>(list.subList(1, 3));
```

`subList` 适合**临时切片**（如分页查询结果处理），不要长期持有。

## 7. 线程安全对比

| 实现 | 读 | 写 | 迭代 | 适用 |
|---|---|---|---|---|
| ArrayList | 快 | 快 | fail-fast | 单线程 |
| Collections.synchronizedList | 锁 | 锁 | 需手动同步 | 低并发遗留 |
| CopyOnWriteArrayList | 无锁 | 全量复制 | 快照 | 读多写极少 |
| Vector | 锁 | 锁 | fail-fast | 不要用 |

## 8. 内存占用估算（64 位压缩指针）

| 实现 | 每元素额外开销 |
|---|---|
| `ArrayList` | 4 字节引用（+ 数组对象头 ~16B） |
| `LinkedList` | 24 字节 Node（对象头 16 + 3 引用 12 → 对齐 24）+ 引用 |
| `CopyOnWriteArrayList` | 同 ArrayList，但写时双份 |

100 万个 Integer：

- `ArrayList`：约 4MB 引用 + Integer 对象（若未缓存，每个 16B）= 20MB
- `LinkedList`：24MB Node + Integer 16MB = 40MB

> 数值集合优先 `int[]` 或专用库（fastutil、Eclipse Collections），避免装箱。

## 9. 常见坑

1. `List.of()` / `Arrays.asList()` 返回不可变/固定大小列表。
2. `subList` 视图 + 原列表修改。
3. 增强 for 中 `remove`。
4. `remove(int)` 与 `remove(Object)` 重载混淆。
5. `LinkedList` 用索引 for 遍历。
6. `contains` 在 List 上是 O(n)，循环里嵌套 O(n²)。
7. `Collections.unmodifiableList` 是视图不是拷贝。
8. `List<Integer>` 的 `remove(1)` 删的是索引 1 而不是元素 1。
9. `new ArrayList<>(Arrays.asList(...))` 才是可变副本。
10. 用 `==` 比较 List 内容（应 `equals`）。

```java
// 删除元素 1 的正确写法
List<Integer> nums = new ArrayList<>(List.of(1, 2, 3));
nums.remove(Integer.valueOf(1));   // [2, 3]
nums.remove(0);                    // 删索引 0 → [3]
```

## 10. 选型总结

| 需求 | 选择 |
|---|---|
| 通用列表 | `ArrayList` |
| 只读常量列表 | `List.of(...)` |
| 频繁头尾增删 / 栈 / 队列 | `ArrayDeque` |
| 读多写极少的并发列表 | `CopyOnWriteArrayList` |
| 需要去重且保持顺序 | `LinkedHashSet` |
| 需要排序 | `TreeSet` / 排序后的 ArrayList |
| 数值密集 | `int[]` / 专用集合库 |
