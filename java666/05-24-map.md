# 24 · Map 实现详解（含 HashMap 原理）

## 1. HashMap 数据结构

### JDK 8+：数组 + 链表 + 红黑树

```
table: Node<K,V>[]
  [0] → Node → Node → Node        链表（长度 < 8）
  [1] → TreeNode（红黑树）          链表长度 ≥ 8 且 table.length ≥ 64
  [2] → null
```

```java
static class Node<K,V> implements Map.Entry<K,V> {
    final int hash;
    final K key;
    V value;
    Node<K,V> next;
}
```

### 核心字段

```java
transient Node<K,V>[] table;         // 桶数组，长度总是 2 的幂
transient int size;                  // 元素个数
int threshold;                       // 扩容阈值 = capacity * loadFactor
final float loadFactor;              // 默认 0.75
static final int TREEIFY_THRESHOLD = 8;      // 链表转树阈值
static final int UNTREEIFY_THRESHOLD = 6;    // 树退化链表阈值
static final int MIN_TREEIFY_CAPACITY = 64;  // 转树的最小表容量
```

## 2. 哈希计算

```java
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}

// 索引计算
int index = (n - 1) & hash;      // 等价于 hash % n，但更快（n 是 2 的幂）
```

### 为什么要 `h ^ (h >>> 16)`（扰动函数）

- 索引只用低几位（n-1 的掩码）。
- 若 hashCode 高位差异大、低位相同，会全部冲突。
- 异或高 16 位到低 16 位，让高位也参与索引计算，**降低碰撞概率**。

### 为什么容量必须是 2 的幂

`(n-1) & hash` 只有在 n 为 2 的幂时等价于取模，且分布均匀。

`tableSizeFor(cap)` 会把任意容量向上取整到 2 的幂：

```java
// 传入 10 → 16；传入 17 → 32
```

## 3. put 流程

```
1. table 为 null → resize() 初始化（默认 16）
2. 计算索引 i = (n-1) & hash
3. table[i] == null → 直接 newNode 放入
4. 否则：
   a. 首节点 key 相同（hash 相同 && (k == key || key.equals(k))）→ 覆盖 value
   b. 是 TreeNode → 走红黑树插入
   c. 遍历链表：
      - 找到相同 key → 覆盖
      - 到尾部 → 尾插，若链表长度 ≥ 8 → treeifyBin
5. ++size > threshold → resize()
```

```java
// 简化版核心逻辑
final V putVal(int hash, K key, V value) {
    Node<K,V>[] tab; Node<K,V> p; int n, i;
    if ((tab = table) == null || (n = tab.length) == 0)
        n = (tab = resize()).length;
    if ((p = tab[i = (n - 1) & hash]) == null)
        tab[i] = newNode(hash, key, value, null);
    else {
        Node<K,V> e; K k;
        if (p.hash == hash && ((k = p.key) == key || (key != null && key.equals(k))))
            e = p;
        else if (p instanceof TreeNode)
            e = ((TreeNode<K,V>)p).putTreeVal(this, tab, hash, key, value);
        else {
            for (int binCount = 0; ; ++binCount) {
                if ((e = p.next) == null) {
                    p.next = newNode(hash, key, value, null);
                    if (binCount >= TREEIFY_THRESHOLD - 1) treeifyBin(tab, hash);
                    break;
                }
                if (e.hash == hash && ((k = e.key) == key || (key != null && key.equals(k))))
                    break;
                p = e;
            }
        }
        if (e != null) { V old = e.value; e.value = value; return old; }
    }
    ++modCount;
    if (++size > threshold) resize();
    return null;
}
```

## 4. 扩容（resize）

- 容量翻倍：`newCap = oldCap << 1`，阈值同样翻倍。
- JDK 8 的优化：元素新位置只有两种可能——**原位**或**原位 + oldCap**（因为 n 翻倍后掩码多一位）。

```java
// 判断依据：hash & oldCap
if ((e.hash & oldCap) == 0) → 低位链表（原位）
else                        → 高位链表（原位 + oldCap）
```

这样避免重新计算 hash，且保持链表相对顺序（JDK 7 头插法会逆序且并发下成环）。

### JDK 7 的并发死循环

JDK 7 扩容用**头插法**，多线程并发 resize 可能形成环形链表，导致 `get` 死循环 CPU 100%。JDK 8 改尾插法解决。

> 但 JDK 8 的 HashMap 仍然**不是线程安全**的（会丢数据、size 不准），并发场景必须用 `ConcurrentHashMap`。

## 5. 红黑树转换

为什么阈值是 8：

- 哈希分布均匀时，链表长度服从泊松分布，长度 8 的概率约 0.00000006。
- 树节点占用约 2 倍空间，转换有成本，8 是空间与时间的折中。

为什么还要 ≥ 64 容量：

- 小表时冲突多是因为容量小，扩容即可解决，不必建树。

退化条件：扩容或删除后树节点 ≤ 6 时退化为链表。

## 7. 容量与负载因子

```java
new HashMap<>();                    // 默认 16 / 0.75
new HashMap<>(100);                 // 会调整为 128（tableSizeFor(100) = 128）
new HashMap<>(100, 0.5f);           // 更高查询性能，更多空间
```

正确预估：

```java
// 要放 n 个元素，避免扩容：
int capacity = (int) Math.ceil(n / 0.75);
Map<K,V> map = new HashMap<>(capacity);
// 或简单写 new HashMap<>(n * 4 / 3 + 1)
```

负载因子权衡：

| 值 | 空间 | 查询性能 | 冲突 |
|---|---|---|---|
| 0.5 | 大 | 高 | 少 |
| 0.75（默认） | 中 | 中 | 中 |
| 0.9 | 小 | 低 | 多 |

## 8. 遍历方式与性能

```java
// 推荐：entrySet（一次取键值）
for (Map.Entry<K, V> e : map.entrySet()) {
    e.getKey(); e.getValue();
}

// 较慢：keySet + get（两次查找）
for (K k : map.keySet()) { V v = map.get(k); }

// forEach（Java 8，简洁）
map.forEach((k, v) -> { });

// 只遍历值
for (V v : map.values()) { }
```

## 9. 常用 API 与技巧

```java
map.getOrDefault(key, 0);
map.putIfAbsent(key, value);
map.computeIfAbsent(key, k -> new ArrayList<>()).add(item);   // 分组神器
map.computeIfPresent(key, (k, v) -> v + 1);
map.compute(key, (k, v) -> v == null ? 1 : v + 1);
map.merge(key, 1, Integer::sum);                              // 计数神器
map.replaceAll((k, v) -> v * 2);
map.remove(key, value);                                       // 仅当值匹配时删除
```

### 经典：分组

```java
Map<String, List<Order>> byUser = new HashMap<>();
for (Order o : orders) {
    byUser.computeIfAbsent(o.getUserId(), k -> new ArrayList<>()).add(o);
}
```

### 经典：计数

```java
Map<String, Integer> count = new HashMap<>();
for (String w : words) count.merge(w, 1, Integer::sum);
```

### 多值 Map


## 10. LinkedHashMap

在 HashMap 基础上增加双向链表维护顺序。

```java
new LinkedHashMap<>();                        // 插入序
new LinkedHashMap<>(16, 0.75f, true);         // 访问序（LRU 基础）
```

### 实现 LRU 缓存

```java
public class LruCache<K, V> extends LinkedHashMap<K, V> {
    private final int capacity;

    public LruCache(int capacity) {
        super(capacity, 0.75f, true);   // accessOrder = true
        this.capacity = capacity;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > capacity;
    }
}
```

> 生产环境用 Caffeine / Guava Cache（支持过期、统计、并发）。

## 11. TreeMap

红黑树实现，按 key 排序。

```java
TreeMap<Integer, String> tm = new TreeMap<>();          // 自然序
TreeMap<String, Integer> byLen = new TreeMap<>(Comparator.comparingInt(String::length));

tm.firstKey(); tm.lastKey();
tm.floorKey(5);      // ≤ 5 的最大 key
tm.ceilingKey(5);    // ≥ 5 的最小 key
tm.headMap(5);       // < 5 的视图
tm.tailMap(5, true); // ≥ 5
tm.subMap(2, 8);
tm.descendingMap();
```

- 不允许 null key（自然序时）。
- 操作 O(log n)。
- 适合范围查询、排行榜（也可用 `ConcurrentSkipListMap`）。

## 12. ConcurrentHashMap（简述）

JDK 8+：

- 数组 + 链表 + 红黑树，与 HashMap 类似。
- **CAS + synchronized 锁单个桶**（不再分段锁）。
- `size` 用 `baseCount + CounterCell[]` 分散计数。
- **不允许 null key / null value**（避免并发二义性）。
- 弱一致性迭代器，不会抛 `ConcurrentModificationException`。

```java
ConcurrentHashMap<String, Integer> chm = new ConcurrentHashMap<>();
chm.put("a", 1);
chm.computeIfAbsent("b", k -> 0);       // 原子操作
chm.merge("a", 1, Integer::sum);        // 原子累加

// 复合操作必须用原子方法，不能 get 后 put
// 错误
if (!chm.containsKey(k)) chm.put(k, v);   // 非原子
// 正确
chm.putIfAbsent(k, v);
```

详见 09-41 并发容器篇。

## 13. 其他 Map

| 实现 | 特点 | 场景 |
|---|---|---|
| `Hashtable` | 全表 synchronized，禁 null | 遗留，勿用 |
| `EnumMap` | 数组实现，极快 | key 是枚举 |
| `IdentityHashMap` | 用 `==` 比较 key | 需要按引用区分 |
| `WeakHashMap` | key 弱引用，可被 GC | 缓存/元数据（易踩坑） |
| `Properties` | Hashtable 子类，String 键值 | 配置文件 |

## 14. 常见坑

1. **可变对象作 key**（hash 变了找不回）。
2. 只重写 `equals` 不重写 `hashCode`。
3. 并发使用 HashMap（丢数据、死循环历史问题）。
4. 遍历中 `map.remove`（用 `Iterator.remove` 或 `map.entrySet().removeIf`）。
5. `ConcurrentHashMap` 存 null（抛 NPE）。
6. `computeIfAbsent` 的映射函数里修改同一个 map（可能死循环/CME）。
7. 用 `keySet()` 遍历再 `get`（性能差）。
8. 容量未预估导致多次扩容。
9. 大量删除后期望内存释放（HashMap 不缩容）。
10. `Map.of` 不允许 null 值/键。

```java
// computeIfAbsent 递归陷阱
Map<String, Integer> m = new HashMap<>();
m.computeIfAbsent("a", k -> m.get("b"));   // 可能 ConcurrentModificationException
```

## 15. 面试速答

- **HashMap 为什么线程不安全**：并发 put 可能覆盖、size 不准；JDK 7 扩容成环。
- **为什么容量 2 的幂**：`(n-1) & hash` 等价取模且更快、分布均匀。
- **为什么负载因子 0.75**：空间与冲突的折中（泊松分布 + 实测）。
- **为什么树化阈值 8**：链表长度 8 的概率极低，树化成本高。
- **HashMap 与 HashTable 区别**：线程安全、null 支持、性能、迭代器。
- **HashMap 与 ConcurrentHashMap 区别**：锁粒度、null、弱一致性、并发扩容（多线程协助 transfer）。
