# 61 · JDBC

## 1. 标准流程

```java
// 1. 加载驱动（JDBC 4.0+ 可省略，SPI 自动注册）
Class.forName("com.mysql.cj.jdbc.Driver");

// 2. 获取连接
String url = "jdbc:mysql://localhost:3306/demo?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=utf8";
try (Connection conn = DriverManager.getConnection(url, "root", "123456")) {

    // 3. 创建 Statement
    try (PreparedStatement ps = conn.prepareStatement(
            "SELECT id, name FROM user WHERE age > ?")) {
        ps.setInt(1, 18);                    // 参数从 1 开始

        // 4. 执行
        try (ResultSet rs = ps.executeQuery()) {
            while (rs.next()) {
                long id = rs.getLong("id");
                String name = rs.getString("name");
            }
        }
    }
}
```

## 2. Statement vs PreparedStatement

| 维度 | Statement | PreparedStatement |
|---|---|---|
| SQL 注入 | 易受攻击 | 预编译，安全 |
| 性能 | 每次编译 | 可复用执行计划 |
| 参数 | 字符串拼接 | `setXxx` 绑定 |
| 可读性 | 差 | 好 |
| 二进制/大文本 | 麻烦 | `setBinaryStream` / `setClob` |

```java
// ✘ SQL 注入
String sql = "SELECT * FROM user WHERE name = '" + name + "'";
// name = "a' OR '1'='1" → 查出所有用户

// ✔ 参数化
ps = conn.prepareStatement("SELECT * FROM user WHERE name = ?");
ps.setString(1, name);
```

**永远使用 PreparedStatement**，即使没有用户输入（性能也更好）。

## 3. 执行方法

```java
ps.executeQuery();     // SELECT → ResultSet
ps.executeUpdate();    // INSERT/UPDATE/DELETE → 影响行数
ps.execute();          // 任意 → boolean（true 表示有 ResultSet）

// 批量
ps.addBatch();
ps.executeBatch();
```

## 4. ResultSet

```java
while (rs.next()) {
    rs.getInt(1);              // 按索引（1 开始）
    rs.getString("name");      // 按列名（推荐）
    rs.getObject("created_at", LocalDateTime.class);
    rs.wasNull();              // 上次读取是否为 NULL
}

// 可滚动/可更新（需在创建 Statement 时指定）
conn.createStatement(ResultSet.TYPE_SCROLL_INSENSITIVE, ResultSet.CONCUR_UPDATABLE);
rs.first(); rs.last(); rs.absolute(3); rs.previous();
```

### NULL 处理

```java
int age = rs.getInt("age");
if (rs.wasNull()) {
    // age 实际是 NULL（getInt 返回 0）
}

// 推荐：用包装类型
Integer age = (Integer) rs.getObject("age");
```

## 6. 事务

```java
Connection conn = dataSource.getConnection();
boolean oldAutoCommit = conn.getAutoCommit();
conn.setAutoCommit(false);                   // 开启事务

try {
    updateA(conn);
    updateB(conn);
    conn.commit();
} catch (Exception e) {
    conn.rollback();
    throw e;
} finally {
    conn.setAutoCommit(oldAutoCommit);
    conn.close();
}
```

### 隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 |
|---|---|---|---|
| READ_UNCOMMITTED | ✔ | ✔ | ✔ |
| READ_COMMITTED | ✘ | ✔ | ✔ |
| REPEATABLE_READ | ✘ | ✘ | ✔（MySQL InnoDB 用间隙锁基本解决） |
| SERIALIZABLE | ✘ | ✘ | ✘ |

```java
conn.setTransactionIsolation(Connection.TRANSACTION_REPEATABLE_READ);
```

### 保存点

```java
Savepoint sp = conn.setSavepoint("beforeB");
try { updateB(conn); }
catch (Exception e) { conn.rollback(sp); }
conn.commit();
```

## 7. 批处理

```java
try (PreparedStatement ps = conn.prepareStatement("INSERT INTO user(name, age) VALUES(?, ?)")) {
    conn.setAutoCommit(false);
    for (int i = 0; i < 10000; i++) {
        ps.setString(1, "user" + i);
        ps.setInt(2, 20 + i % 50);
        ps.addBatch();

        if (i % 1000 == 0) {          // 分批提交，避免大事务
            ps.executeBatch();
            conn.commit();
        }
    }
    ps.executeBatch();
    conn.commit();
}
```

MySQL 需在 URL 加 `rewriteBatchedStatements=true` 才真正批量（否则逐条发送）。

## 8. 连接池

直接 `DriverManager.getConnection` 每次创建物理连接（TCP + 认证，几十毫秒），必须用连接池。

### HikariCP（Spring Boot 默认，推荐）

```java
HikariConfig cfg = new HikariConfig();
cfg.setJdbcUrl("jdbc:mysql://localhost:3306/demo");
cfg.setUsername("root");
cfg.setPassword("123456");
cfg.setMaximumPoolSize(20);
cfg.setMinimumIdle(5);
cfg.setConnectionTimeout(3000);       // 获取连接超时
cfg.setIdleTimeout(600000);
cfg.setMaxLifetime(1800000);          // 小于数据库 wait_timeout
cfg.setConnectionTestQuery("SELECT 1");
cfg.setPoolName("HikariPool-main");

DataSource ds = new HikariDataSource(cfg);
```

Spring Boot 配置：

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/demo?useSSL=false&serverTimezone=Asia/Shanghai&rewriteBatchedStatements=true
    username: root
    password: 123456
    hikari:
      maximum-pool-size: 20
      minimum-idle: 5
      connection-timeout: 3000
      max-lifetime: 1800000
      pool-name: main-pool
```

### 连接池参数

| 参数 | 建议 |
|---|---|
| `maximumPoolSize` | CPU 核数 × 2 ~ 4（不是越大越好） |
| `minimumIdle` | 与 max 相同（避免动态扩缩） |
| `connectionTimeout` | 3s（快速失败） |
| `maxLifetime` | 小于 DB 的 `wait_timeout`（MySQL 默认 8h） |
| `idleTimeout` | 10min |

> 连接池过大会拖垮数据库（上下文切换、锁竞争）。公式：`连接数 = ((核心数 * 2) + 有效磁盘数)`。

## 9. DAO 模板

```java
public class UserDao {
    private final DataSource ds;

    public UserDao(DataSource ds) { this.ds = ds; }

    public Optional<User> findById(long id) throws SQLException {
        String sql = "SELECT id, name, age FROM user WHERE id = ?";
        try (Connection conn = ds.getConnection();
             PreparedStatement ps = conn.prepareStatement(sql)) {
            ps.setLong(1, id);
            try (ResultSet rs = ps.executeQuery()) {
                return rs.next() ? Optional.of(map(rs)) : Optional.empty();
            }
        }
    }

    public int insert(User u) throws SQLException {
        String sql = "INSERT INTO user(name, age) VALUES(?, ?)";
        try (Connection conn = ds.getConnection();
             PreparedStatement ps = conn.prepareStatement(sql, Statement.RETURN_GENERATED_KEYS)) {
            ps.setString(1, u.getName());
            ps.setInt(2, u.getAge());
            int rows = ps.executeUpdate();
            try (ResultSet keys = ps.getGeneratedKeys()) {
                if (keys.next()) u.setId(keys.getLong(1));
            }
            return rows;
        }
    }

    private User map(ResultSet rs) throws SQLException {
        User u = new User();
        u.setId(rs.getLong("id"));
        u.setName(rs.getString("name"));
        u.setAge(rs.getInt("age"));
        return u;
    }
}
```

## 10. 常见坑

1. SQL 拼接（注入 + 无法复用执行计划）。
2. 忘记关闭 Connection/Statement/ResultSet（连接池耗尽）。
3. 在连接池外长期持有 Connection。
4. 事务中做远程调用（长事务锁表）。
5. `setAutoCommit(false)` 后忘记 `commit`（连接归还时回滚）。
6. 大结果集一次读入内存（用游标/分页）。
7. 未设置 `maxLifetime`，连接被数据库主动断开（`Communications link failure`）。
8. 批量插入未开 `rewriteBatchedStatements`（性能差 10 倍）。
9. `getInt` 遇 NULL 返回 0 未检查 `wasNull`。
10. 时区不一致（`serverTimezone` 未配置，时间差 8 小时）。
11. 连接池过大导致数据库连接数打满。
12. 在 `finally` 中 `close` 抛异常覆盖业务异常（try-with-resources 解决）。
