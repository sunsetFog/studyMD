# 07 · 成本优化：从 20 个手段里挑适合你的

## 1. 优化优先级总览

```
先结构性降本，再参数级调优：

第一梯队（效果大、风险低）：
  ① 缓存重复请求        ② 分级路由（小模型处理简单任务）
  ③ 压缩上下文          ④ 限制输出长度

第二梯队（效果大、有约束）：
  ⑤ 批量 API（半价）    ⑥ 缩短系统 prompt
  ⑦ 检索优化（top-k/分块） ⑧ 结果复用（模板化答案）

第三梯队（投入大、长期）：
  ⑨ 蒸馏/微调小模型     ⑩ 自建推理（量大时）
```

## 2. 各手段详解

### ① 缓存（见 08 篇详述）

```
命中即免费。优先级最高的手段。
典型命中率：FAQ 类 30-60%，通用对话 10-20%
```

### ② 分级路由（性价比之王）

```
原则：任务越简单，用越便宜的模型。

实现：先用便宜模型做意图/难度分类 → 分派模型
      或按场景静态映射（summary→mini, chat→mid, writing→flagship）

示例效果：
  全量用旗舰：   10000 次 × ¥0.30 = ¥3000/日
  分级路由：     70% 用 mini(¥0.03) + 30% 用旗舰(¥0.30)
               = 210 + 900 = ¥1110/日  → 省 63%
```

注意：分类器本身有成本与误判，简单场景用静态映射表即可。

### ③ 压缩上下文

| 手段 | 说明 | 节省 |
|---|---|---|
| 历史摘要 | 超过 N 轮的对话压缩成一段摘要 | 50-80% |
| 轮数限制 | 只带最近 K 轮 | 与 K 相关 |
| 检索精简 | top-k 从 10 降到 3-5，只保留高相关分块 | 30-60% |
| 分块调优 | 分块更精准，塞入更少 | 20-50% |
| 工具结果裁剪 | 只保留模型需要的字段 | 视情况 |
| 结构化记忆 | 用户画像/偏好存结构化字段而非全文 | 大 |

### ④ 限制输出长度

```
① prompt 中明确长度（「控制在 200 字内」）
② API 参数 max_tokens 兜底
③ 按场景设定：摘要 300、客服 500、长文 2000
★ 输出单价高，限长是立竿见影的手段
```

### ⑤ 批量 API

```
离线任务（夜间批量摘要、数据标注、evals 全量跑）
→ 走供应商批量接口，通常 5 折
代价：延迟数分钟-数小时，不能用于实时交互
```

### ⑥ 缩短系统 prompt

```
常见问题：系统 prompt 越写越长（几千 token），每次调用都重复计费
做法：
① 删掉与场景无关的通用说明
② 长规则改为按需注入（只注入本场景需要的规则）
③ 用 few-shot 示例替代冗长描述（示例 token 少、效果好）
④ 定期审计：这个规则最近触发过吗？
```

### ⑧ 结果复用（知识化）

```
高频问题 → 人工/审核确认后沉淀为标准答案
后续相同问题直接返回模板（零模型成本）
适合：客服、FAQ、固定报告格式
```

### ⑨ 蒸馏/微调小模型

```
适用：任务模式固定、有大量真实样本（>1000 条）
做法：用旗舰模型生成/积累高质量输入输出对 → 微调小模型
收益：质量接近旗舰，成本 1/10-1/50
代价：训练与维护投入、锁定任务范围
时机：场景稳定且调用量大（>10 万次/月）才值得
```

## 3. 降本组合拳示例（客服场景）

```
基线：¥0.09/次 × 10000 = ¥900/日

优化步骤：
① 语义缓存，命中率 35%      → 有效调用 6500 次
② 70% 简单问题走 mini        → 结构：4550×¥0.02 + 1950×¥0.09
③ 检索 top-k 10→4           → 输入 -40%，单次 ¥0.09→¥0.06
④ 系统 prompt 2000→800 token → 输入再 -25%

优化后：
  缓存命中 3500 次 × ¥0.001 ≈ ¥3.5
  mini 4550 次 × ¥0.015 ≈ ¥68
  旗舰 1950 次 × ¥0.055 ≈ ¥107
  合计 ≈ ¥180/日  → 省 80%
```

## 4. 降本的安全边界（不能为省钱牺牲质量）

```
① 每项降本改动必须跑 evals 回归（质量不下降才允许）
② 质量敏感场景（长文、复杂推理）不强行降级
③ 缓存答案要有失效机制（知识库更新后失效）
④ 监控降级后的质量指标（采纳率/👎率），异常即回滚
⑤ 设定「成本红线」而不是「成本目标」：红线保命，优化逐项评估
```

## 5. 供应商层面的省钱

| 手段 | 说明 |
|---|---|
| 多供应商比价 | 同能力模型价差可达数倍 |
| 预付费/包月 | 量大时谈折扣 |
| 长上下文折扣 | 部分供应商对超长上下文有阶梯价 |
| 缓存折扣 | 部分供应商对重复前缀计费打折（利用其 prompt cache） |
| 离线时段 | 批量任务走折扣通道 |
| 锁价合同 | 防涨价（B 端签约时谈） |

## 6. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 为降本牺牲质量 | 采纳率暴跌、投诉上涨 | 每项改动跑 evals + 监控回滚 |
| 缓存无失效 | 知识库更新后仍返回旧答案 | 按知识版本失效（08） |
| 路由分类器误判 | 复杂问题被打到 mini，质量差 | 静态映射起步 + 分类置信度兜底 |
| 限长过度 | 输出被截断 | max_tokens 留余量 + 截断检测 |
| 优化不计量 | 不知道省了多少、质量有没有变差 | A/B 对比成本与质量 |
| 一刀切降级 | 全场景都换小模型 | 按场景评估，敏感场景保持旗舰 |
| 蒸馏过早 | 场景没稳定就投入训练 | 等调用量与模式稳定 |

## 7. Checklist

- [ ] 有当前成本基线（按场景/输入构成归因）
- [ ] 缓存已上线且知道命中率
- [ ] 有分级路由（或至少场景静态映射）
- [ ] 输出长度与系统 prompt 已审计压缩
- [ ] 离线任务走批量 API
- [ ] 每项降本改动有 evals 回归与线上质量监控
- [ ] 高频问题有结果复用机制
- [ ] 知道下一步的降本手段与预期收益
