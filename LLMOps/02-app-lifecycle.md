# 02 · AI 应用全生命周期：每个环节的工程活动

## 1. 生命周期八阶段

```
① 探索验证 → ② 原型 → ③ 生产化 → ④ 部署发布
   → ⑤ 监控运营 → ⑥ 迭代优化 → ⑦ 模型演进 → ⑧ 退出/重构
```

与 Product 篇的区别：本文只讲**每个阶段的工程活动**（做什么、产出什么、验收什么）。

## 2. 各阶段详解

### ① 探索验证（Spike，1-3 天）

| 活动 | 产出 |
|---|---|
| 收集 20-50 个真实输入样本 | 测试样本集（evals 的雏形） |
| 定义「合格」标准 | 质量基线（可判定的） |
| Playground 手工跑模型 | 合格率数据 + 失败模式清单 |
| 估算单次成本与延迟 | 成本模型 |
| 结论：可行 / 有条件可行 / 不可行 | spike 报告 |

**验收**：有真实样本的合格率数据，不是「感觉能行」。

### ② 原型（数天-2 周）

```
工程活动：
- prompt 原型化（变量、示例、输出格式）
- 搭最小链路：输入 → 模型 → 解析 → 展示
- 建立 evals 初版（30-50 条）
- 每次改 prompt 跑一遍测试集（哪怕手工跑）

工程决策：
- 模型初选（能力、价格、延迟）
- 输出结构（JSON schema？Markdown？）
- 失败处理初版（重试？兜底文案？）
```

### ③ 生产化（1-4 周，最容易被跳过）

| 事项 | 说明 | 篇目 |
|---|---|---|
| prompt 外置 + 版本化 | 从代码字符串迁到配置/平台 | 16 |
| 模型网关 | 统一入口：路由/重试/日志 | 04 |
| 限流与成本熔断 | 防失控 | 10 |
| 降级链路 | 主模型 → 备用 → 兜底 | 11 |
| 结构化输出校验 | schema 校验 + 自动修复 | 27 |
| 请求全量落库 | trace 记录（脱敏） | 21 |
| evals 自动化 | 进 CI | 25 |

> 原型到生产的最大差距不在功能，而在**异常处理与可观测**。

### ④ 部署发布

```
标准节奏：
  CI 通过（含 evals 回归）
    → 部署（特性开关关闭）
    → 影子流量对比（新旧版本并行，不影响用户）
    → 小流量 5-10%（观察 3-7 天）
    → 全量
```

### ⑤ 监控运营（常态）

| 监控对象 | 关键指标 | 篇目 |
|---|---|---|
| 可用性 | 成功率、错误率、超时率 | 22-23 |
| 性能 | 首 token、总延迟 P95 | 09、22 |
| 成本 | 日成本、单次成本、单用户成本 | 06、22 |
| 质量 | 采纳率、👎率、拒答率、幻觉投诉 | 22 |
| 漂移 | 金丝雀集通过率趋势 | 24 |

### ⑥ 迭代优化（每周/每迭代）

```
周循环：
  bad case 收集 → 归类分级 → 修复（prompt/知识库/规则）
    → evals 回归 → 灰度 → 全量
同时：bad case 全部回写 evals 集（防复发）
```

### ⑦ 模型演进（每季度或事件驱动）

```
触发：新模型发布 / 价格变动 / 供应商下线 / 质量退化
动作：
  新模型跑全量 evals → 对比报告（质量/成本/延迟三维）
  → 影子流量 → 灰度 → 全量 或 保持原模型
详见 18 篇。
```

### ⑧ 退出与重构

```
- 功能下线：特性开关关闭 → 数据归档 → 计费确认停止
- 架构重构：新旧并行（影子流量）→ 切流 → 退役
- 供应商迁移：导出历史日志与知识库，确认数据可带走
```

## 3. 阶段间的交接物（交接不清是事故之源）

```
spike → 原型：     样本集 + 质量基线 + 成本模型
原型 → 生产化：    prompt + evals 集 + 期望行为描述
生产化 → 发布：    evals 自动化 + 监控 + 降级链路
发布 → 运营：      灰度计划 + 指标看板 + 告警阈值
运营 → 迭代：      bad case 库 + 回归流程
```

## 4. 团队角色分工（小团队一人多角）

| 角色 | 职责 | 在 LLMOps 中新增的活 |
|---|---|---|
| 开发 | 应用代码、编排、网关 | 网关实现、降级链路、trace 落库 |
| PM | 需求、质量基线 | 定义 evals 期望、审核 bad case |
| 运维 | 部署、监控 | 成本看板、模型容灾、漂移告警 |
| 领域专家 | 领域知识 | 维护知识库、标注样本 |

## 5. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 跳过生产化直接上线 | 一上量就崩 | ③ 清单逐项过 |
| evals 一次性 | 上线后再也不跑 | 进 CI，每次改动必跑 |
| bad case 不回流 | 同样问题反复出现 | 建回流机制（每周固定复盘） |
| 模型演进无流程 | 换模型凭直觉 | 走 18 篇流程 |
| 原型期的玩具代码直接上生产 | 无异常处理无日志 | 生产化清单 |
| 无退出机制 | 下线一个功能牵一发动全身 | 特性开关管理一切新功能 |

## 6. Checklist

- [ ] 当前功能处在哪个阶段，下一阶段的交接物是否明确
- [ ] spike 的结论（合格率、成本）有文档留档
- [ ] evals 集随生命周期持续扩充
- [ ] 生产化清单（③ 的 7 项）已全部完成或排期
- [ ] 每周有 bad case 复盘，且回写 evals
