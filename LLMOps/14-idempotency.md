# 14 · 幂等性与一致性：重复调用不出乱子

## 1. 为什么 AI 应用有幂等问题

```
幂等 = 同一请求执行多次，结果与执行一次相同。

AI 场景的高危组合：
① 长耗时（10-60s）→ 客户端易超时重发
② 网络波动多 → 重试频繁
③ Agent 有副作用（写库/发消息/调工具）
④ 计费按调用次数 → 重复调用 = 重复扣钱
```

## 2. 幂等键设计

```
客户端生成 idempotency_key，重发时携带相同 key：

key 组成建议：user_id + session_id + 请求内容 hash + 序号
  或：UUID（客户端在「一次用户操作」内复用同一 key）

网关行为：
  首次请求 → 执行 → 存储 (key → result, 状态)
  重复请求（key 相同）：
    ├─ 已完成 → 直接返回原结果（不调用模型、不再计费）
    ├─ 执行中 → 返回进行中状态（或长轮询挂起）
    └─ 已失败 → 按策略重试或返回失败
```

### 存储设计

```
幂等表（Redis，TTL 24h 即可）：
  key → { status: RUNNING|SUCCEEDED|FAILED,
          result_ref: "trace-xxx",
          created_at }

执行流程：
  SET NX（原子占位）成功 → 获得执行权
  SET NX 失败 → 查状态返回（进行中/已完成）
```

## 3. 各场景的幂等要点

| 场景 | 副作用 | 幂等方案 |
|---|---|---|
| 纯生成（聊天、写作） | 无（只有成本） | key 去重防重复计费即可 |
| 消息发送类（AI 生成后发送） | 重复发送 | key + 发送前查重 |
| Agent 工具调用 | 重复写库/下单 | 工具调用层幂等（业务主键去重） |
| 异步任务提交 | 重复建任务 | 任务 key 去重（见 15） |
| 计费扣减 | 重复扣费 | 以 trace_id 结算，重试合并 |
| 文件/知识库处理 | 重复入库 | 文档 hash 去重 |

## 4. 一致性问题：AI 场景的特殊形态

### ① 会话一致性

```
问题：降级/路由切换导致同一会话用了不同模型
  → 前后回答风格突变、上下文理解不一致

策略：
① 会话内锁定模型（切换时提示用户）
② 上下文跨模型兼容（摘要中文化，避免依赖特定模型格式）
```

### ② 计费与结果一致性

```
问题：模型调用成功但响应丢失（网络断在最后一步）
  → 结果没给用户，钱已扣

处理：
① 调用结果先落库（trace），响应失败时可凭 trace 补发
② 对账任务：每日对比 供应商账单 vs 内部计量记录
  差异 > 2% → 排查（漏记/重试合并错误/取消未生效）
```

### ③ 缓存与真相一致性

```
缓存答案与最新知识不一致（知识库更新后）
→ 版本进缓存键 + 知识更新时定向失效（见 08）
```

### ④ 流式的最终一致性

```
流中断后：前端已显示部分内容
  → 处理选项：
    A. 保留已生成部分 + 标注"生成中断" + 提供续写按钮
    B. 静默重试整体重生成（成本×2，体验闪烁）
  推荐 A（保留 + 续写），并对"中断率"做监控
```

## 5. 对账与补偿（一致性兜底）

```
每日对账任务：
  ① 供应商用量 API vs 内部计量总和 → 差异率
  ② 幂等表中 SUCCEEDED 但无 trace 结果的记录 → 异常清单
  ③ FAILED 但供应商计费的请求 → 统计（不可控，但要知道规模）

补偿机制：
  用户报告"扣了额度没结果" → 凭 trace_id 查证 → 手动/自动补额度
  （SLA：明确响应时限，B 端必备）
```

## 6. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 客户端超时无 key 重发 | 重复计费 + 重复副作用 | 幂等键 + SET NX 占位 |
| 幂等表无 TTL | 键堆积内存爆炸 | 24h TTL 足够 |
| Agent 工具调用不幂等 | 重复下单/发消息 | 业务主键去重（工具层） |
| 流中断直接重试全量 | 成本翻倍闪烁 | 保留部分 + 续写 |
| 计费无对账 | 月账单对不上 | 每日对账 + 差异告警 |
| 结果落库在响应之后 | 响应丢失结果丢失 | 先落库再响应（WAL 思想） |
| 会话切换模型无提示 | 用户困惑 | 锁模型或提示 |
| 补偿无流程 | 用户投诉无处安放 | trace 可查 + 补额度 SLA |

## 7. Checklist

- [ ] 所有可重发的请求携带幂等键，网关去重
- [ ] 幂等键处理覆盖「执行中/已完成/已失败」三态
- [ ] Agent 工具调用有业务层去重
- [ ] 结果先落库再响应，可凭 trace 补发
- [ ] 流中断采用「保留 + 续写」并监控中断率
- [ ] 每日对账：供应商账单 vs 内部计量，差异告警
- [ ] 用户额度补偿有流程与 SLA
- [ ] 会话内模型切换有一致性处理
