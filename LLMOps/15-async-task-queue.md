# 15 · 异步任务与队列：长耗时的正确姿势

## 1. 什么必须异步

```
判断标准：用户能等几秒？

同步（直返）        ：< 15s，交互式（聊天、摘要短文）
异步（队列 + 状态）  ：> 15s（长文生成、文档批处理、Agent 多步）
批量（夜间）        ：小时级（evals 全量跑、知识库重建）
```

不异步化的后果：网关超时 → 用户重复提交 → 成本×N + 幂等问题（见 14）。

## 2. 异步任务的标准设计

### API 形态

```
POST /tasks          → 创建任务，立即返回 task_id
GET  /tasks/{id}     → 查状态与结果（轮询）
GET  /tasks/{id}/events  → 或 SSE/WebSocket 推进度
DELETE /tasks/{id}   → 取消
```

### 状态机（必须有）

```
PENDING → RUNNING → SUCCEEDED
                  → FAILED
                  → CANCELLED
                  → TIMEOUT
每次转换落库 + 时间戳：
  created_at / started_at / finished_at / 上游请求 trace_id
```

```json
{
  "task_id": "t-9a2f",
  "type": "doc_summary",
  "status": "RUNNING",
  "progress": { "step": 2, "total": 4, "desc": "分块生成中 (12/40)" },
  "model": "flagship@2026-01",
  "prompt_version": "summary-v2.1",
  "cost_so_far": 0.34,
  "created_at": "...",
  "cancelable": true
}
```

## 3. 队列的关键配置

| 配置 | 建议 | 说明 |
|---|---|---|
| 并发消费者 | 对齐模型配额（见 13 舱壁） | 防止队列瞬间打爆限流 |
| 重试 | 失败重试 ≤ 2 次，指数退避 | 结合 12 篇失败分类 |
| 死信队列 | 重试耗尽进入 DLQ + 告警 | 人工排查 |
| 优先级队列 | 付费用户任务优先 | 分级 |
| 消息幂等 | 按 task_id 去重（见 14） | 队列 at-least-once 语义 |
| 最大滞留 | 任务在队列中 > X 分钟 → 告警或降级 | 防积压无声恶化 |

## 4. 长任务的断点与续跑

```
长任务（如 40 个文档的摘要）不要一个大调用跑完：

分步设计：
  任务 = N 个子调用（每文档一次）
  每个子调用完成即落库部分结果
  失败 → 只重跑失败的分片，不重跑全任务

收益：
  ① 重试成本最小化（只补失败片）
  ② 有真实进度可展示（12/40）
  ③ 可取消（已完成的保留）
```

## 5. Agent 任务的专属设计

```
Agent 多步任务必须有：
① 步骤日志：每步记录（工具、入参、出参、耗时、费用）
② 步数上限：max_steps（如 15），防止死循环
③ 成本上限：max_cost，超限终止并汇报
④ 人工确认点：关键动作（下单/发送）前暂停等确认
⑤ 全程可取消：用户随时停止，已完成的步骤结果保留
⑥ 失败汇报：卡在哪一步、为什么、已消耗多少
```

## 6. 削峰与降级联动

```
高峰期：
① 队列长度监控（> 阈值告警）
② 非核心任务延迟执行（夜间窗口）
③ 免费用户任务降优先级
④ 极端情况：暂停接收新任务 + 明确公告
```

## 7. 结果交付与通知

```
完成后通知方式（按场景选）：
① 站内通知 + 邮件
② Webhook 回调（B 端集成）
③ 轮询（第三方系统）
④ 离开页面后：推送/邮件「任务完成，点击查看」

注意：通知内容不含敏感数据（用链接 + 摘要）
```

## 8. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 长任务同步做 | 超时雪崩、重复提交 | 异步化 + 状态机 |
| 无进度反馈 | 用户以为卡死，反复刷新 | 分步设计 + 进度落库 |
| 失败重跑整个任务 | 成本×N | 分片重跑 |
| 队列无积压监控 | 静默恶化数小时 | 滞留告警 |
| 队列 at-least-once 重复消费 | 重复调用计费 | task_id 幂等 |
| Agent 无上限 | 死循环烧钱 | 步数/成本上限 + 人工确认点 |
| 任务状态丢失 | 服务重启后任务黑洞 | 状态落库（非内存） |
| 取消不生效 | 任务取消后仍在跑 | 检查每个子调用前读取消标记 |

## 9. Checklist

- [ ] > 15s 的任务全部异步化，有 task_id 与状态机
- [ ] 状态持久化（服务重启不丢）
- [ ] 长任务分步设计，支持分片重跑与真实进度
- [ ] 队列配置：并发对齐配额、死信队列、优先级、积压告警
- [ ] 任务消费幂等（防重复计费）
- [ ] Agent 任务有步数/成本上限、确认点、全程可取消
- [ ] 完成通知覆盖多种渠道，内容不泄漏敏感数据
- [ ] 支持取消且取消真正生效
