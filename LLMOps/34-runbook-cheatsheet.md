# 34 - 故障手册、应急预案与速查清单

> 全体系收官篇。前三部分是值班可以直接照做的 **runbook**（故障场景 → 判别 → 止血），
> 第四部分是全 34 篇的速查浓缩。打印贴在工位（或挂进值班 Wiki 首页）。

---

## 一、故障手册（Runbook）

> 通用格式：**判别信号 → 定位（2 分钟内） → 止血动作（全部为配置热更） → 验证 → 事后动作**。
> 止血永远优先于查因。

### 场景 1：供应商大面积故障（429/5xx 激增）

```
判别: 22 看板 → 按供应商拆解错误率；是否所有场景同时恶化
定位: 单供应商 vs 全部？（全部 → 检查网络出口/自家变更）
止血:
  - 网关切主流量到备用供应商 tier（04 章路由，秒级）
  - 未配置备用 → 降级阶梯下调（11 章：flagship→mini→缓存→兜底）
  - 13 章熔断已自动打开则确认降级链路正常承接
验证: 错误率回落、降级率上升（预期内）、延迟正常
事后: 更新供应商状态记录；复盘备用供应商容量是否足够（热身流量 11 章）
```

### 场景 2：成本失控（预算消耗异常加速）

```
判别: 10 章预算看板进度条超前 + 06 章单次成本 P50 上涨
定位（22 章归因顺序）: 功能 mix → prompt 新版本 → tier 路由漂移 → 计价调整 → 模型变啰嗦
止血（按优先级清单裁撤，10 章）:
  - 停非核心功能 / 降低非核心场景模型档位
  - 若是新 prompt 版本 → 秒级回滚（17 章）
  - 收紧单请求 max_tokens 与 top_k（05 章热更）
  - 80%/95% 熔断动作按预案执行
验证: 消耗曲线回归预期斜率
事后: 归因报告；若因调价更新 21 章计价表并核账
```

### 场景 3：输出质量突变（badcase/点踩激增）

```
判别: 22 看板点踩率/解析失败率环比；24 章金丝雀集分数
定位: 
  - 有本周发布？→ 灰度面板分版本对比（17 章）
  - 无发布？→ 金丝雀集掉分 + 伴随信号判别（24 章第 3 节表）
  - 检索 span 命中率下降？→ 知识漂移（19 章同步报告）
止血:
  - 发布导致 → 回滚 prompt 版本（秒级）
  - 模型漂移 → 锁旧快照 / 切备用模型
  - 知识漂移 → 修复同步任务；严重时临时关闭受影响场景
验证: 金丝雀集回跑 + 线上指标 1h 观察
事后: badcase → 25 章评估集；漂移记录归档
```

### 场景 4：延迟激增（P95 超预算）

```
判别: 22 看板 TTFT vs 总时长，哪个先涨
定位: 
  - TTFT 涨 → 供应商侧（切换验证）或 prompt 变长（渲染快照对比）
  - 生成速率降（tok/s）→ 模型 Hang（09 章），重试/切换
  - 总时长涨但 TTFT 正常 → 自家链路（检索慢/护栏排队/线程池打满）
止血:
  - 上游问题 → 切供应商/降档模型；超时分级收紧快慢路径（09 章）
  - 自家问题 → 检索降档（少 rerank）、护栏异步化、扩容 worker
验证: P95 回落至预算内
事后: 生成速率监控基线更新
```

### 场景 5：疑似注入/内容安全事件

```
判别: 27 章拦截率突增；特定会话出现违禁/越权内容
止血:
  - 单会话 → L4 隔离 + 审计
  - 攻击模式扩散 → 护栏收紧热更（词表/阈值）+ 涉事样本进黑名单
  - 越权泄漏 → 检查 acl 过滤配置，紧急关闭受影响场景
  - 系统提示词泄漏 → 输出指纹拦截确认开启，评估 prompt 资产轮换
验证: 拦截率与误拦率（27 章申诉通道）双监控
事后: 样本 → 拦截测试集；L3/L4 记录归档（32 章审计）
```

### 场景 6：密钥泄漏/盗刷

```
判别: 供应商账单异常 / 密钥扫描告警（32 章 SOP）
止血: 吊销泄漏 key（分钟级）→ 网关切备用 key → 限额确认
验证: 异常消耗停止
事后: 核账 + 溯源渠道 + 全历史扫描（32 章清单）
```

### 场景 7：异步队列积压（长任务延迟）

```
判别: 队列深度 / 任务平均等待时间（15 章）
定位: 上游限流 429 增多？worker 挂了？任务量突增（营销/刷子）
止血:
  - 刷子 → 10 章防刷收紧
  - worker 不足 → 扩容 worker 池（在配额内）
  - 配额瓶颈 → 任务降级排序：付费用户优先，长尾任务延后
验证: 积压曲线下降
事后: 削峰策略复盘（15 章）
```

## 二、应急演练（季度必做）

| 演练项目 | 方法 | 通过标准 |
|---|---|---|
| 供应商故障切换 | 预演环境拔掉主供应商 | 备用自动承接 <2 分钟，用户无感知 |
| prompt 秒级回滚 | 发布测试版本后回滚 | ≤5 分钟完成含验证 |
| 预算熔断 | 注入虚拟消耗触发 80%/95% | 裁撤动作按清单正确执行 |
| 知识库回滚 | 切回旧 collection | 检索正常，标准查询集通过 |
| 密钥泄漏 | 模拟告警 | 吊销+切换 <10 分钟 |
| 全链路断网 | 断网 30 秒恢复 | 重试/幂等/队列恢复无重复计费（12/14 章） |

演练产出：各场景实际止血时长记录，写进 runbook 作为「预期恢复时间」。

## 三、值班速查卡

### 一页应急开关清单（值班第一页）

```
□ 降级阶梯调整      11 章  (秒级)
□ prompt 回滚       17 章  (秒级)
□ 供应商切换        04 章  (秒级)
□ 预算熔断动作      10 章  (秒级)
□ 护栏严松度        27 章  (秒级)
□ 功能紧急停用      10 章  (秒级)
□ 限流配额调整      10 章  (秒级)
```

### 常用公式

```
单次成本 = (输入tok × 输入价 + 输出tok × 输出价) / 1000
缓存折扣成本 = 输入价 × 缓存折扣率 × cached_tokens
TTFT 影响 ≈ 首 token 前所有串行步骤之和（检索+护栏+排队+推理排队）
会话成本 ≈ Σ 轮次成本（注意每轮都携带历史：多轮成本近似线性增长偏上）
供应商真实瓶颈 = min(RPM 配额, TPM 配额) ÷ 单请求消耗
预算熔断线 = 日预算 × 80% / 95% / 100% 三级
```

### 参数基线（起步参考值）

| 项 | 建议值 | 出处 |
|---|---|---|
| 重试退避 | 指数退避 + 抖动，≤3 次，仅幂等可重试 | 12 |
| 熔断静默期 | 30-60s（AI 场景加大） | 13 |
| 缓存键 TTL | 按内容时效；键含 prompt 版本 | 08 |
| 语义缓存阈值 | 0.93 起步 + 灰区判定 | 08 |
| 灰度起步比例 | 1-5%，观察 ≥1 天 | 17 |
| 金丝雀掉分告警 | 周环比 -2% | 24 |
| judge 校准一致率 | ≥85% 才进门禁 | 25 |
| 账单对账差异告警 | >2% | 21 |
| trace 计量保留 | 明细 ≥180 天 | 21 |
| 计费对账 | 每日自动 | 14/21 |

### 事故响应优先级口诀

```
止血 > 查因；配置 > 发版；回滚 > 硬修；
用户可感知的（P0/P1）先处理；数据留痕（trace/badcase）随止血顺手做。
```

## 四、全体系速查（34 篇浓缩）

| 模块 | 一句话心法 | 篇 |
|---|---|---|
| 概览架构 | 模型在供应商，你运维的是胶水层与概率行为 | 01-05 |
| 成本性能 | 先计量后优化；感知性能优先；预算三道闸 | 06-10 |
| 可靠降级 | 重试→熔断→降级链闭环；幂等是一切重试的安全网 | 11-15 |
| Prompt 版本 | Prompt 也是代码：版本化、灰度、秒级回滚；输出结构=接口 | 16-19 |
| 可观测性 | 质量可代理、成本可归因、行为可对比；计量明细表是唯一事实源 | 20-24 |
| 评估保障 | 评估集是十年资产；门禁无例外通道；护栏误拦也是事故 | 25-28 |
| 部署工具 | 默认 API 调用；止血全配置化；核心数据资产自持 | 29-33 |
| 本篇 | 止血 > 查因，演练出预期恢复时间 | 34 |

### 全体系终检（自测 10 题）

1. 供应商静默更新模型，你的第一发现渠道是什么？（24 金丝雀集）
2. 灰度 5% 发现点踩率翻倍，从发现到止血要几步？（17 指针回滚，≤2 步）
3. 单次成本上涨 20%，归因排查顺序？（24：流量→prompt→tier→计价→模型）
4. 为什么 HPA 不能用 CPU 指标？（29：瓶颈在供应商配额）
5. readiness 探针能不能探供应商可达性？（30：不能，否则全服务摘流）
6. 重试导致的重复计费如何避免？（12 trace 合并 + 14 幂等键）
7. prompt 输出新增字段是几级变更？解析层怎么配合？（16：breaking，宽容未知、缺失报错）
8. judge 分数直接当门禁行不行？（25：需校准集 ≥85% 一致率）
9. 用户要求删除数据，要级联清哪些存储？（32：会话/trace/向量/备份）
10. 深夜 P1 告警，值班先做什么？（本篇 runbook：止血动作查开关清单）

## 五、持续运营

| 频率 | 动作 |
|---|---|
| 每周 | 告警误报回顾（23）、badcase 转评估集（25）、工具成本核对（33） |
| 每月 | 账单对账深查（21）、预算复盘（10）、事故复盘汇总 |
| 每季度 | 应急演练（本篇）、基线画像评审（24）、密钥轮换（32）、工具链评审（33） |
| 每半年 | 体系终检自测（本篇第四节）、成本模型与定价复盘（Product/24） |

**维护约定**：本手册为活文档，每次 P0/P1 复盘的改进项直接写入对应 runbook 场景；新增开关必须同步进速查卡与演练计划。
