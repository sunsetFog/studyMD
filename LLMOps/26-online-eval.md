# 26 - 线上评估：影子流量、A/B 与金丝雀集

> 离线 evals 测「考试能力」，线上评估测「真实表现」——真实输入分布、真实多轮交互、
> 真实的用户耐心。本篇覆盖不接触用户的观测（影子/回放）与接触用户的实验（A/B/金丝雀）。

---

## 1. 线上评估的四个手段总览

| 手段 | 是否接触真实用户 | 风险 | 用途 |
|---|---|---|---|
| **回放评估** | 否 | 无 | 用历史真实输入跑新版本，零风险预演 |
| **影子流量** | 否（用户收到旧版回答） | 成本翻倍 | 新模型/新管道的真实输入实测 |
| **A/B 实验** | 是（分流量） | 受控 | prompt/模型/管道变更的效果验证 |
| **金丝雀放行** | 是（小比例） | 最小 | 变更的常规上线方式（17 章） |

关系：**回放/影子是「发布前的实测」，A/B 是「发布中的验证」，金丝雀是「发布的方式」。** 三者共享 17 章的分流基础设施。

---

## 2. 回放评估

### 2.1 做法

从 21 章计量明细表抽取近期真实输入（脱敏），对候选版本重放：

```
样本构成：近 7 天真实输入按场景分层抽样 200-500 条
执行：新版本（prompt@v8 / 新模型）逐条生成
评估：程序断言 + judge 打分 + 与「当时的真实输出」对比
产出：真实分布下的分数报告（非考试分布）
```

### 2.2 价值与局限

- **价值**：离线评估集是精心编写的「考卷」，回放是真实「日常题」；新 prompt 在考卷上 95 分、在真实分布上崩掉是常事。
- **局限**：多轮会话只能回放单轮或截断上下文，会话连贯性测不到；真实输出本身可能有错，对比时 judge 需同时评两边。

## 3. 影子流量

### 3.1 机制

```
用户请求 → 主链路（active 版本，正常回答用户）
        └→ 影子链路（候选版本，结果只落库不展示）
```

实现要点：

- 影子调用**异步化**（15 章队列）：影子延迟不影响用户链路。
- 影子结果打 `shadow=true` 标签落库，与主链路同 trace_id 关联，便于对比。
- **成本控制**：影子使该功能成本近乎翻倍，用 1-10% 采样率控制，或只在低成本场景全量。
- 影子调用的降级/熔断**独立实例**（13 章），影子故障不影响主链路。

### 3.2 影子对比分析

```
指标             主链路(v6)   影子(v7)   差异
解析成功率        99.1%       99.0%      ✅
judge 质量分      4.12        4.21       ✅ +0.09
平均输出 tokens   380         520        ⚠️ +37%
TTFT P95         620ms       710ms      ⚠️ +15%
结论: 质量小幅提升但成本+37%，进入 A/B 前先修输出膨胀
```

影子是**发现成本/延迟副作用最便宜的实测手段**——这些副作用在离线评估里几乎不可见（离线样本少、不跑真实上下文长度）。

## 4. A/B 实验与金丝雀

### 4.1 与 17 章的分工

- 17 章讲的是「发布过程」的灰度机制（分流、看板、回滚）。
- 本节讲「实验设计」：假设、指标、样本量、结论纪律。灰度 1-5% 是金丝雀（求稳），A/B 是带假设检验的对照（求结论），可以共用同一分流设施。

### 4.2 实验设计规范

| 要素 | 要求 |
|---|---|
| 假设 | 单一明确：「加入引用来源后，客服答案采纳率 +5%」 |
| 主指标 | 预先注册（采纳率），避免事后挑指标 |
| 卫星指标 | 成本、延迟、点踩率、拒答率（守门员） |
| 样本量 | 用序贯检验或预估时长；流量小就拉长周期覆盖工作日/周末差异 |
| 分流 | 用户维度稳定哈希（17 章），对照组 = active 版本 |
| 最短周期 | ≥1 周（覆盖周期性），且只看稳定段 |
| 结束纪律 | 到点就出结论：显著提升→全量；显著恶化→回滚；不显著→记录「无证据」，不许「先放着多跑跑」 |

### 4.3 小流量产品的现实方案

日均 1k 次请求的产品做经典 A/B 检验力不足，改用：

1. **时间片切换**：交替周（本周 v6、下周 v7、再 v6...）对比周环比，牺牲速度换统计力。
2. **judge 全量评估**：不依赖用户行为指标，对线上输出按 10-20% 抽样 judge 评分，两侧同口径对比。
3. **先影子后小 A/B**：影子期过滤掉明显更差的候选，小流量期只验证 top 候选。

## 5. 结果判定：分层看数据

无论影子还是 A/B，结论都要拆层（24 章 2.2 的教训同样适用）：

```
总体: v7 质量 +0.1（不显著）→ 是不是该放弃了？
拆层:
  短输入会话   +0.35 ✅ 显著
  长输入会话   -0.28 ❌ 显著变差   ← 上下文压缩策略对长文失效
  多轮 >8 轮   样本不足，单独观察
结论: 修复长输入路径后重试，而非整体放弃候选
```

**按输入长度/会话轮数/功能场景/用户分层，是判定「值得修」还是「该放弃」的分水岭。**

## 6. 与用户反馈体系的衔接

线上评估的「金标准」永远是用户行为，但各指标信度不同：

| 指标 | 信度 | 注意 |
|---|---|---|
| 采纳率（复制/使用） | 高 | 最接近真实价值 |
| 显式点踩 + 反馈文本 | 高（量少） | 定位问题类型，转 badcase |
| 重新生成率 | 中高 | 与输出随机性耦合（温度高会虚高） |
| 会话放弃率 | 低 | 混杂「问题已解决就走了」 |
| 会话时长 | 低 | 不等于满意度 |

组合使用：**采纳率/点踩率做主信号，judge 抽评补量，其余做卫星校验。**

---

## 7. 常见坑

| 坑 | 后果 | 对策 |
|---|---|---|
| 只信离线分数直接全量 | 真实分布上的副作用（成本/延迟/风格）翻车 | 发布前必跑回放或影子 |
| 影子同步执行 | 影子拖慢主链路 P95 | 异步队列 + 独立熔断实例 |
| 影子/实验不打标签混进生产计量 | 成本报表污染、A/B 数据失真 | shadow/experiment 标签贯穿落库 |
| A/B 主指标事后挑选 | 假阳性率失控，什么都能「赢」 | 预先注册主指标与卫星指标 |
| 不显著也全量上线 | 「没证据」被当成「没问题」 | 结束纪律：不显著=记录并维持现状 |
| 小流量硬做经典 A/B | 检验力不足，结论随机 | 时间片切换 / judge 全量 / 先影子 |
| 结论只看总体不拆层 | 值得修的候选被误杀 | 强制分层判定 |
| 实验期与灰度叠加（三层流量切分） | 分流互不独立，数据全废 | 实验体系分层设计，同一时间一个分层维度 |

---

## 8. Checklist

- [ ] 发布前实测通道：回放（分层抽样 200-500 条）或影子（异步、打标、独立熔断）
- [ ] 影子对比报告含质量 + 成本 + 延迟三维度，成本副作用必查
- [ ] A/B 实验规范：假设/主指标/卫星指标/最短周期/结束纪律成文
- [ ] 小流量场景备好替代方案（时间片/judge 全量）
- [ ] 分层判定强制（长度/轮数/场景），总体不显著时先拆层再决策
- [ ] shadow/experiment 标签贯穿计量落库，与生产口径隔离
- [ ] 用户反馈指标组合使用，主信号=采纳率+点踩率
- [ ] 实验结论（含失败结论）归档，失败候选记录原因防重复尝试
