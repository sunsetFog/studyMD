# 11 · 降级与容灾：模型挂了怎么办

## 1. 降级的本质

```
AI 应用的降级 = 回答「当最好的路径不可用时，用户体验退到哪一级」

 unlike 传统服务（降级=功能关闭），AI 降级可以是「换个差一点的模型继续答」
 —— 这是 AI 应用独有的容灾红利：质量可分级，不必全有或全无。
```

## 2. 降级阶梯（按场景设计）

```
L0 旗舰模型（最佳质量）
 ↓ 主模型熔断/限流
L1 备用旗舰（另一供应商）
 ↓ 备用也熔断
L2 便宜模型（mini）—— 质量降级但仍有产出
 ↓ mini 也不可用
L3 缓存答案（语义检索最相近的已缓存回答）
 ↓ 无可用缓存
L4 静态兜底（预置模板话术 / 人工服务入口）
```

### 配置示例（配置中心，可热更新）

```yaml
degradation:
  chat:
    chain:
      - model: flagship-a@2026-01
        condition: normal
      - model: flagship-b          # 另一家供应商
        condition: primary_unavailable
      - model: mini-latest
        condition: all_premium_down
        note: 提示用户"当前为快速模式"
      - type: semantic_cache
      - type: static_template
        note: "服务暂时繁忙，已转人工通道"
```

## 3. 降级触发条件

| 触发源 | 信号 | 响应 |
|---|---|---|
| 模型 API 错误率 | 5xx / 429 比例 > 阈值（如 5%/1min） | 自动切下一级 |
| 延迟劣化 | TTFT P95 > 预算 2 倍 | 切快模型 |
| 供应商限流 | 429 持续 | 削减并发/排队/切备用 |
| 质量异常 | 金丝雀集通过率骤降 | 切回稳定版本（见 24） |
| 成本熔断 | 日预算 100%（见 10） | 全局降到 L2/L3 |
| 人工开关 | 值班判断 | 秒级热更新（见 05） |

## 4. 降级时的用户体验（必须设计）

```
原则：降级可以，但要让用户知道状态变化，且保留求助出口。

① 状态标识：「当前为快速模式，回答质量可能略降」
② 转人工入口：L3/L4 级别必须提供人工通道
③ 保留输入：任何降级路径都不得丢失用户输入
④ 兜底文案分级：
   L2 → "回答由轻量模型生成，供参考"
   L3 → "以下为相似问题的回答，可能不完全匹配"
   L4 → "暂时无法回答，可稍后重试或联系人工"
```

## 5. 多供应商容灾设计

```
① 双活/主备：
   主备各承担比例（如 90/10 保持备用链路热身）或纯主备

② 切换速度目标：
   自动切换 < 1 分钟（熔断器驱动）
   人工切换 < 5 分钟（配置热更新）

③ 切换验证：
   备用模型必须平时就跑金丝雀集（防止"备用是坏的"才发现）

④ API 差异适配：
   参数差异（温度语义、max_tokens 行为）
   输出格式差异（tool call 结构不同）
   → 网关统一抽象层解决（见 04）
```

## 6. 不可降级场景的处理

有些场景降级 = 不可用（如代码生成要求特定模型的独家能力）：

```
策略：
① 明确标注该场景的依赖与风险（风险登记表）
② 该场景走独立配额池（避免被其他场景的量挤占）
③ 不可用时给出明确预期恢复时间与通知订阅
④ 提前与供应商沟通高优支持渠道（B 端 SLA）
```

## 7. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 只有降级没有体验设计 | 用户看到的是报错或空白 | 分级兜底文案 + 状态标识 |
| 备用模型平时不用 | 切过去才发现备用也是坏的 | 备用链路保持 10% 热身流量 |
| 降级后不观察 | 质量暴跌没人知道 | 降级时质量指标独立看板 + 告警 |
| 兜底文案太技术 | "Error 503" | 分级人话文案（见 Product/18） |
| 静态兜底年久失修 | 模板过时误导用户 | 兜底内容纳入维护清单 |
| 降级不自动恢复 | 主模型恢复后仍跑在降级档 | 自动探测恢复 + 灰度切回 |
| 切换造成会话断裂 | 同会话前后答案风格突变 | 会话内尽量保持模型一致，切换点提示 |

## 8. Checklist

- [ ] 每个场景画出了 L0-L4 降级阶梯并配置化
- [ ] 降级链路经过实测演练（不是纸面设计）
- [ ] 备用供应商有热身流量与金丝雀验证
- [ ] 每级降级有对应的用户文案与人工出口
- [ ] 降级状态对用户可见
- [ ] 有自动恢复机制，恢复时灰度切回
- [ ] 不可降级场景有风险登记与独立配额
- [ ] 降级期间质量指标独立监控
