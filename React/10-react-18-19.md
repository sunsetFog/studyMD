# 10 - React 18/19 新特性

## 1. React 18 核心（并发时代开启）

| 特性 | 说明 |
|---|---|
| **并发渲染（Concurrent Rendering）** | 渲染可中断、可恢复、可丢弃，由优先级调度（见 31） |
| **自动批处理** | Promise/setTimeout/原生事件中的多次 setState 合并为一次渲染 |
| **Transitions** | `useTransition` / `startTransition`：更新标记为可中断低优先级 |
| **Suspense 全面支持** | 数据获取协调（配合框架） |
| **新 Hooks** | useId、useDeferredValue、useSyncExternalStore、useTransition、useDeferredValue |
| **createRoot** | 并发模式入口（ReactDOM.render 已废弃） |
| **严格模式增强** | 开发期 effect 双执行检测 |

### 1.1 自动批处理

```tsx
setTimeout(() => {
  setA(1)
  setB(2)     // React 17：两次渲染；React 18：合并为一次
}, 100)
```

退出批处理（同步 flush）：`flushSync(() => setA(1))`——仅在需要「读更新后 DOM」的罕见场景。

### 1.2 useTransition：可中断的昂贵更新

```tsx
const [isPending, startTransition] = useTransition()

function onChange(e) {
  setInput(e.target.value)              // 高优先级：输入框立即响应
  startTransition(() => {
    setFiltered(hugeFilter(e.target.value))  // 低优先级：可中断的大列表更新
  })
}
return { isPending && <Spinner /> }
```

### 1.3 useDeferredValue：值的延迟版本

```tsx
const deferredQuery = useDeferredValue(query)   // query 抢先渲染，deferred 落后一拍
const list = useMemo(() => bigFilter(deferredQuery), [deferredQuery])
```

与 useTransition 的区别：**useTransition 包「更新动作」（你有权改代码的地方），useDeferredValue 包「值」（值来自他人如 props）**。

### 1.4 useSyncExternalStore

订阅外部 store 的官方方案（ tearing 安全）：

```tsx
const state = useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot)
```

Zustand/Jotai 等库的底层基石（见 `17-zustand-jotai.md`）。

### 1.5 useId

```tsx
const id = useId()   // SSR 安全的唯一 id，用于 label htmlFor、aria
<label htmlFor={id}><input id={id} /></label>
```

禁止用 `Math.random()` 生成 SSR 不一致的 id。

## 2. React 19 核心（Actions 时代）

| 特性 | 说明 |
|---|---|
| **ref 作为 prop** | 函数组件不再需要 forwardRef |
| **use() API** | 在渲染中读取 Promise/Context，条件可用 |
| **Actions（useActionState / useOptimistic / form actions）** | 表单异步提交的一等公民抽象 |
| **useFormStatus** | 表单提交状态（react-dom） |
| **document metadata** | `<title>` `<meta>` 可直接写在组件里，自动提升到 head |
| **资源预加载 API** | preload / preinit |
| **性能改进** | ref callback 清理函数、更小注水开销 |

### 2.1 ref 作为 prop

```tsx
// React 18
const Input = forwardRef<HTMLInputElement, Props>((props, ref) => <input ref={ref} {...props} />)

// React 19
function Input({ ref, ...props }: Props & { ref?: React.Ref<HTMLInputElement> }) {
  return <input ref={ref} {...props} />
}
```

### 2.2 use()：读取 Promise 与 Context

```tsx
import { use, Suspense } from 'react'

function Profile({ userPromise }: { userPromise: Promise<User> }) {
  const user = use(userPromise)    // 未 resolve 时向上找 Suspense
  return <h1>{user.name}</h1}
}
<Suspense fallback={<Spinner />}><Profile userPromise={p} /></Suspense>
```

- `use(promise)` 触发 Suspense 边界（Promise 缓存很重要——每次渲染新 Promise 会无限 pending，配合 Query/框架缓存）
- `use(Context)` 可在**条件语句**中使用（useContext 不行）

### 2.3 form actions 与 useActionState

```tsx
import { useActionState } from 'react'

function Signup() {
  const [state, formAction, isPending] = useActionState(async (prev, formData) => {
    const err = await api.signup(formData)
    return err ? { error: err } : { ok: true }
  }, { ok: false })

  return (
    <form action={formAction}>        {/* 原生 form action 属性 */}
      <input name="email" />
      <button disabled={isPending}>注册</button>
      {state.error && <p>{state.error}</p>}
    </form>
  )
}
```

价值：**渐进增强**（JS 未加载也能提交）、pending 状态内建、配合 useOptimistic 做乐观更新。

### 2.4 useOptimistic：乐观更新

```tsx
const [optimisticLikes, addOptimistic] = useOptimistic(likes, (cur, delta: number) => cur + delta)

function onLike() {
  addOptimistic(1)                        // 立即显示 +1
  startTransition(async () => {           // transition 完成时自动回滚到真实值
    await api.like()
    setLikes(l => l + 1)                  // 服务端确认后更新真实值
  })
}
```

### 2.5 useFormStatus

```tsx
// 子组件（不需要父传 pending prop）
import { useFormStatus } from 'react-dom'
function SubmitButton() {
  const { pending } = useFormStatus()
  return <button disabled={pending}>{pending ? '提交中…' : '提交'}</button>
}
// 必须放在 <form> 内部
```

## 3. 升级迁移要点（17 → 18 → 19）

```
17→18: createRoot 替换 render；Aware of StrictMode 双 effect；依赖库版本兼容（18 是 PEER 要求 ^18）
18→19: 移除 forwardRef（可选）；JSX 类型变化（ref 进 props）；移除propTypes；UMD 构建移除
```

## 4. React Compiler（实验性，方向性重要）

编译时自动 memoization：组件/hook 纯函数前提下，编译器自动插入 useMemo/useCallback/memo 等价物。

- 纯函数纪律变得更重要：不改 props、渲染无副作用
- 现在手写的 memo/useMemo 未来多数可删，但**语义习惯不变**（数据不可变、引用稳定思维依然是根本）

## 常见坑

1. **18 下库未兼容并发**（旧版 setState 泄漏 / 手动批处理假设）：升级依赖。
2. **use(promise) 每次渲染新 Promise**：无限 pending；Promise 必须缓存在组件外/Query。
3. **useDeferredValue 滥用**：仅昂贵渲染用，普通输入加 debounce 即可。
4. **useFormStatus 放在 form 外**：拿不到状态。
5. **useOptimistic 忘了在 transition 内调用**：乐观值不生效。
6. **18 StrictMode 双 effect 导致重复请求**：正确 cleanup / Query 才是解法。
